# Методы ML и измерение качества

Состояние кода: 2026-09-29. Обрабатываются синтетические учебные карточки и размеченные примеры в `backend/data/labeled/`. Никакие результаты не предназначены для оценки работы реального диспетчера.

## Обработка данных

| Задача | Метод и вход | Выход и фолбэк |
|---|---|---|
| Группа ЕКП | `ml/classify/ekp_group_classifier.py`: текст фабулы → локальные эмбеддинги rubert-tiny2 → классификатор scikit-learn; обучающие пары строит `ml.scripts.train_classifier` | Группа, top-3, уверенность и версия; при отсутствии артефакта — предусмотренный локальный режим. |
| Оценка попытки | `ml/assess/engine.py`: события, эталон сценария, карточка и справочники → компоненты правил (`timing`, `decision`, `statuses`, `comments`, `fields`, `grammar`, `multitask`, `report`, `address`); для режима 112 свой набор компонентов | Балл 0–100, четыре оси контракта, ошибки с `ruleId`, текстовое объяснение. Учительский override хранится отдельно и имеет приоритет в отчёте. |
| Текст и адрес | `ml/nlp/grammar.py`: SymSpell и доменные слова; `ml/nlp/address.py`: нормализация и fuzzy match; `ml/nlp/semantic.py`: смысловое сравнение через эмбеддер | Ошибки и степень совпадения; при отсутствии модели семантика переходит к лексическому сравнению с признаком недоступности. |
| Генерация и валидация | `ml/generate/scenario_generator.py`: вариации по шаблону, опционально локальная Ollama; `validator.py`: категория, адрес, обязательные поля, дубль, грамматика, согласованность | Черновик билета и отчёт проверок. Для дубля E5 сравнивает происшествия с похожим адресом: пожары на разных улицах не считаются одной карточкой. При недоступности Ollama используется шаблон; сомнительный результат требует проверки преподавателя. |
| Рекомендации | `ml/insights/recommender.py`: ошибки и оценки в истории по категориям | Слабые категории с причиной; подбор не изменяет оценку попытки. |
| Аудио | Локальные Silero TTS и Vosk STT из `models/`; Vosk сначала распознаёт свободную речь, доменная грамматика применяется при пустом результате | Озвученная реплика заявителя и расшифровка доклада с сохранённым WAV. Жёсткая грамматика как основной проход искажала свободный доклад в последовательность чисел. |

ИИ-шлюз `app/ai_gateway.py` делает реализацию заменяемой, но основной оценщик основан на проверяемых правилах, а не на LLM-судье. Результат оценки содержит версию, веса, компоненты и ссылки на правила; ошибки пригодны для разбора преподавателем.

### Добавленный контур AI-релизов

После обновления репозитория появились `ml/dataset/` (санитизация, факты, разметка train/validation/holdout и упаковка), `ml/pipeline/` (LangGraph-конвейер с детерминированными проверками и ручным решением), версионируемые промпты и `ml/release.py`. API `app/api/v1/ai_*` хранит ревизии оценки, журнал ошибок и решения преподавателя. Активировать разрешено только релиз со статусом `accepted`; правила гейта проверяют происхождение данных, валидность схемы, критические ошибки, сравнение с baseline, независимость судьи и CPU/RAM-бюджет.

Это отдельный экспериментальный контур от измерений `assessor`/`classifier` ниже. `ml.scripts.eval_ai_release.run_baseline_smoke()` сейчас возвращает заданные в коде числа, поэтому его результат нельзя представлять как фактически измеренную производительность или качество модели. Датасет из нового коммита требует ручной проверки выборки до заявления о независимой оценке.

## Метрики и ограничения выборки

Команды ниже обновляют `var/metrics.json`; файл доступен администратору через `GET /api/v1/metrics/ml`. Числа в таблице взяты из локального `var/metrics.json` на 2026-09-29, а не из отдельного независимого эксперимента.

| Раздел | Команда | Что измеряется | Локальный результат |
|---|---|---|---|
| `assessor` | `uv run python -m ml.scripts.eval_assessor` | Совпадение типов ошибок, κ, корреляции и MAE с экспертными баллами | `dds-1.1.0`, 110 примеров; agreement 0,9986; Pearson 0,9336; Spearman 0,7576; MAE 10,52. |
| `assessorOperator112` | `uv run python -m ml.scripts.eval_assessor --mode operator112` | Те же метрики для режима 112 | 58 примеров; agreement 1,0; Pearson 0,974; Spearman 0,8337; MAE 10,98. |
| `classifier` | `uv run python -m ml.scripts.eval_classifier` | Accuracy на банке, top-3, доля уверенных, 5-блочная CV | 96 карточек; accuracy 1,0; CV accuracy 0,5729. Accuracy на банке оптимистична, поскольку карточки участвуют в обучении. |
| `validator` | `uv run python -m ml.scripts.eval_validator` | Доля пропущенных корректных и отклонённых дефектных билетов | 20 + 20; обе доли 1,0. Это регрессия на примерах из банка, не независимый тест генерализации. |
| `recommender` | `uv run python -m ml.scripts.eval_recommender` | Худшая категория попадает в top-3 на воспроизводимых историях | 10 синтетических историй; top-3 hit rate 1,0. |

Порог `passed` каждого скрипта проверяется самим скриптом. Высокое совпадение на синтетических и обучающих примерах не доказывает качество на новых случаях: для внешней оценки нужны отдельные карточки, независимые эксперты и слепое сравнение.

## Калибровка

`uv run python -m ml.scripts.calibrate [--db] [--alpha 1.0]` собирает матрицу баллов компонентов по размеченным попыткам; с `--db` добавляет примеры из `calibration_samples`, созданные при правках преподавателя. Ridge-регрессия без свободного члена получает веса, отсекает отрицательные значения и нормирует сумму к единице. Файл `var/weights.json` не меняет оценки сам по себе: веса применяются явно через план занятия или `eval_assessor --weights`.

Скрипт записывает в `metrics.json["calibration"]` размер набора, `alpha`, веса и Pearson/Spearman/MAE до и после. Перед принятием новых весов нужно повторить оценку на отложенном наборе и проверить ошибки по категориям: подгонка на тех же 110 примерах может улучшить MAE без улучшения обобщения. Исходные правила и версии артефактов сохраняются для воспроизводимости.

## Воспроизведение

```bash
cd backend
uv sync --extra nlp --group dev
uv run python -m ml.scripts.prepare_models --verify-only
uv run python -m ml.scripts.eval_assessor
uv run python -m ml.scripts.eval_assessor --mode operator112
uv run python -m ml.scripts.eval_classifier
uv run python -m ml.scripts.eval_validator
uv run python -m ml.scripts.eval_recommender
```

Для первого запуска модели готовятся отдельной командой `prepare_models` в сети; проверки и штатный рантайм используют только локальные файлы. Версии скриптов, модельные артефакты и разметку надо фиксировать вместе с отчётом о замере.
