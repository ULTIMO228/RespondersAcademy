# Research: Рейтинг обучающихся (006)

## R1. Источник показателей
- **Decision**: `analytics.rows()` — одна выборка «попытка + оценка» с учётом правки преподавателя (`TeacherOverride`), режимом, форматом, `reactionMs`, `processingMs`, ошибками. Функция расширяется необязательным `student_ids`, чтобы группа читалась одним запросом (без N+1). Только завершённые попытки — у них есть `Evaluation`; незавершённые в выборку не попадают.
- **Rationale**: те же значения, что в отчётах и аналитике обучающегося (FR-011, SC-002).

## R2. Рейтинг режимов
- **Decision**: существующий `rating_service.ratings()` (Эло по попыткам, `StudentRating`) — тот же, что в профиле (FR-004). Рейтинг режима не зависит от периода (это накопленная величина) — в таблице подписывается «рейтинг (за всё время)».
- **Риск**: `sync()` на первом обращении вставляет строку `student_ratings`; параллельные запросы дают гонку (дефект 5.4). В рейтинге группы `sync` вызывается последовательно в одном запросе; гонка между разными запросами устраняется защитой в `sync` (повтор при `IntegrityError`) — отдельный пункт 7 плана исправлений, в эту фичу включается минимальная защита, т. к. рейтинг группы впервые синхронизирует десятки учеников разом.

## R3. Нормативы и «в нормативе»
- **Decision**: реакция ≤ 30 000 мс и отработка ≤ 180 000 мс (Q&A; AGENTS §2). «Доля в нормативе» — доля попыток, где выполнены оба. Средние — по попыткам с ненулевым временем.

## R4. Права
- **Decision**: `error_map_access.accessible_groups / require_group_access / require_student_access` (спека 003, FR-028): преподаватель — только `assigned_groups`, админ — всё, обучающийся — 403. Тем же `require_student_access` закрывается существующий `GET /teacher/students/{id}/profile` (сейчас пускает любого преподавателя).
- **Последствие**: список `/teacher/students` берёт `/users?role=student` (все ученики), а профили чужих станут 403. Решение: на `/teacher/students` преподавателю показываются только ученики его групп (фильтр по `groups` из ответа `/teacher/rating`); у администратора — все.

## R5. Место и «мало данных»
- **Decision**: место — «соревновательное» (1, 2, 2, 4) по текущему столбцу сортировки, только среди учеников с ≥ 3 попытками за период и режим; остальным — «мало данных». Сортировка — на клиенте (≤ 30 строк), сервер отдаёт строки без мест; место вычисляется на клиенте под выбранный столбец.

## R6. Полный профиль
- **Decision**: новый `GET /api/v1/teacher/students/{id}/stats?period=&mode=` → скорость, доля в нормативе, динамика (балл и время по попыткам), список попыток. Слабые этапы — существующий `GET /error-map/students/{id}` по каждому режиму, во фронте отбираются до 3 этапов с уровнем `red`/`yellow` по убыванию доли. Рейтинги, типичные ошибки и рекомендации — существующий `profile`.
- **Alternatives**: всё одним новым эндпоинтом — дублирование логики карты ошибок.

## R7. Возврат к рейтингу и мастер
- **Decision**: состояние таблицы (группа, период, режим, сортировка) — в query-параметрах `/teacher/rating`; ссылка на профиль несёт `?from=<закодированный путь рейтинга>`, «Назад к рейтингу» ведёт туда. «Назначить тренировку» — существующий `ROUTES.teacherAssignmentNewPrefilled({ studentIds: [id] })`.

## R8. Ученикам — нет
- **Decision**: роуты `/teacher/*` уже закрыты гвардом роли; API — `_actor()` даёт 403 обучающемуся.
