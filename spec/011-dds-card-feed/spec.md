# Спецификация фичи 011: преподаватель подаёт оператору ДДС карточки обучающихся-112

**Ветка**: `claude/kind-goldberg-ij6veq` (от `develop`, коммит `db44740`)
**Создана**: 2026-10-20
**Статус**: согласована с владельцем 2026-10-20, в реализации (задачи — `tasks.md`)
**Номер**: 011 — номера 006–010 уже заняты фичами в ветках `SASHA` и `codex/feature-007-learner-role-split`, ещё не влитых в `develop`.

## 1. Обзор

Обучающийся-ДДС получает карточку не напрямую от обучающегося-112, а **от преподавателя**. Карточки, которые
обучающиеся-112 сохранили на своих заданиях, копятся в банке. Преподаватель отбирает их в задание режима ДДС
вместе с билетами или без них, подтверждает эталон каждой карточки и назначает задание.

Так закрывается требование ТЗ «Действия с карточками»: категории «сформированные обучающимися» и «смешанный выбор»
(`extracted.txt`, стр. 15–16). Роль службы 112 при этом берёт на себя преподаватель (Q&A, вопрос 4: «её роль берёт
на себя симулятор (преподаватель или ИИ)»).

## 2. Контекст: что было до фичи (develop `db44740`)

| Механизм | Где | Что делает |
|---|---|---|
| Сохранение карточки 112 | `backend/app/services/operator112_service.py:submit` | создаёт `IncidentCard` с `created_by_student_id`, `mode_origin="operator112"`, `extra.sourceCardId` |
| Автоэталон для ДДС | `backend/app/services/chain_service.py:etalon_from_source` | службы, выбранные обучающимся-112, совпали с билетом → «Принята»; не совпали → «Не принята, передано в …» |
| Автоподача | `chain_service.issue_submitted_card` | сразу выдаёт сохранённую карточку всем подходящим по службе обучающимся-ДДС в идущих занятиях с источником `studentCreated`/`mixed` |
| Пул живого занятия | `session_engine.build_session_pool` | источник `studentCreated` берёт **все** карточки обучающихся, без отбора |
| Пул в мастере занятия | `src/features/session-wizard/ui/StepCardSource.tsx` | преподаватель только видит пул, отобрать не может |
| Задания ДДС | `assignment_service.create` | `cardIds` — только утверждённые билеты (`_approved_ids`), карточки обучающихся не допускаются |

## 3. Решения владельца (2026-10-20)

- **D1. Источник для ДДС задаёт преподаватель.** Живой передачи «обучающийся-112 → обучающийся-ДДС» нет.
- **D2. Где подаёт:** в мастере заданий `/teacher/assignments/new`, режим ДДС, шаг «Билеты».
- **D3. Эталон подтверждается при отборе:** система предлагает эталон по правилу `etalon_from_source`,
  преподаватель видит его у каждой отобранной карточки и может сменить решение и «кому передано».
- **D4. Автоподачу в идущие занятия убрать.**
- **D5. Режим заданий «цепочка A → B» (`chain`) в этой фиче не трогать:** его вывод придёт при слиянии ветки SASHA
  (спека 007 там). Ветка `chain` в `issue_submitted_card` остаётся как есть.

## 4. Роли и права

| Действие | Обучающийся | Преподаватель | Администратор |
|---|---|---|---|
| Видеть банк карточек обучающихся-112 (`GET /api/v1/student-cards`) | — (403) | карточки обучающихся **своих групп** (`User.assigned_groups`) | все |
| Включить карточку обучающегося в задание ДДС | — | только карточку из своего банка; иначе 403 | любую |
| Подтвердить / изменить эталон карточки | — | при создании задания | при создании задания |
| Отработать карточку | обучающийся-ДДС, назначенный на задание | — | — |

Без сессии — 401. Автор карточки (обучающийся-112) свою карточку в банке не видит: банк — инструмент преподавателя.

## 5. API и контракты

### 5.1 `GET /api/v1/student-cards` (новый)

Ответ — массив `StudentCard`, новые сверху:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | id карточки (`c-NNN`) |
| `group` | string | группа происшествия, которую выбрал обучающийся-112 |
| `summary` | string | описание со слов заявителя |
| `address` | string | адрес из карточки |
| `authorId`, `authorName` | string | обучающийся-112 |
| `authorGroup` | string? | учебная группа автора |
| `registeredAt` | string? | время сохранения карточки |
| `sourceCardId` | string? | исходный билет |
| `selectedServices` | string[] | службы из списка оповещения карточки (выбор обучающегося-112) |
| `ticketServices` | string[] | службы по билету (эталон 112) |
| `proposed` | `StudentCardEtalon` | эталон, предложенный системой (D3) |

`StudentCardEtalon = { cardId, expectedDecision: "accepted" | "notAccepted", expectedTransferTo?: string }`.

### 5.2 `POST /api/v1/assignments` (расширение)

Новое необязательное поле запроса `studentCards: StudentCardEtalon[]` — эталоны, подтверждённые преподавателем.

Правила (нарушение → 400, если не указано иное):

1. Карточка обучающегося (`mode_origin = operator112`) в `cardIds` допустима только при `trainingMode = "dds"`.
2. Каждой карточке обучающегося из `cardIds` соответствует ровно одна запись `studentCards`, и наоборот.
3. `expectedDecision = "notAccepted"` требует непустой `expectedTransferTo`.
4. Карточка не из банка преподавателя (автор вне его групп) → 403.
5. Профиль службы обучающегося-ДДС проверяется как для билетов (`filter_cards_for_student`).

Подтверждённые эталоны хранятся в `Assignment.params.studentCards` (без миграции схемы). Ответ задания не меняется.

### 5.3 Оценка

Попытка ДДС по заданию с карточкой обучающегося оценивается по эталону преподавателя из `params.studentCards`.
Автоэталон `extra.chainEtalon` используется, только если подтверждённого нет (живое занятие, старые данные).

## 6. Модель данных

Новых таблиц и колонок нет. Используются `IncidentCard` (`created_by_student_id`, `mode_origin`, `extra`),
`Assignment.params.studentCards`, `User.assigned_groups`.

## 7. Потоки

**П1. Подготовка.** Обучающийся-112 проходит задание режима 112 и сохраняет карточку → карточка в банке.

**П2. Назначение.** Преподаватель → «Новое задание» → обучающиеся-ДДС → режим ДДС → шаг «Билеты»: под списком
билетов блок «Карточки обучающихся-112». Отмечает карточки, у каждой видит «по билету / выбрал обучающийся-112» и
предложенный эталон, при необходимости меняет решение («Принята» / «Не принята» + кому передать) → «Проверка» показывает
число карточек обучающихся и решения → «Создать задание».

**П3. Отработка.** Обучающийся-ДДС запускает задание и получает карточку обучающегося-112 так же, как билет.
Оценка — по эталону преподавателя.

## 8. Функциональные требования

- **FR-001** Банк `GET /student-cards`: права по §4, поля по §5.1, предложенный эталон по правилу `etalon_from_source`.
- **FR-002** Задание ДДС принимает карточки обучающихся вместе с билетами (смешанный выбор) или без них; правила §5.2.
- **FR-003** Оценка попытки по подтверждённому эталону (§5.3).
- **FR-004** Сохранение карточки 112 больше не выдаёт её автоматически в идущие занятия ДДС; режим `chain` — как раньше (D5).
- **FR-005** Мастер заданий: блок «Карточки обучающихся-112» только в режиме ДДС; состояния загрузка / пусто /
  ошибка / требуется сервер; правка эталона; проверка «Не принята» без «кому передать» до отправки.
- **FR-006** Шаг «Проверка» показывает число отобранных карточек обучающихся и решение по каждой.

## 9. Критерии приёмки

- **SC-001** Преподаватель группы ДДС-01 видит в банке карточку обучающегося ДДС-01; преподаватель ДДС-02 — не видит;
  обучающийся получает 403, аноним — 401.
- **SC-002** Задание ДДС с билетом и карточкой обучающегося создаётся (201); без записи `studentCards`,
  с «Не принята» без адресата, с карточкой в режиме 112 — 400; чужая карточка — 403.
- **SC-003** Обучающийся-ДДС проходит такую карточку; эталон, изменённый преподавателем («Не принята» вместо
  предложенной «Принята»), попадает в оценку: «Принята» обучающегося даёт ошибку решения.
- **SC-004** После сохранения карточки обучающимся-112 идущее живое занятие ДДС не получает её в ленту.
- **SC-005** В мастере (мок-слой без бэкенда) блок банка показывает «требуется сервер», остальной мастер работает.

## 11. Вне объёма

- Отдельная учётка и профиль ДДС (спека 008 ветки SASHA, `codex/feature-007-learner-role-split`).
- Карточка ДДС «как в АРМ» без поля «Действие диспетчера» (спека 007 ветки SASHA).
- Отбор карточек в мастере живого занятия `/teacher/session` (пул там остаётся «все карточки обучающихся»).
- Эталон с учётом службы конкретного обучающегося-ДДС: эталон один на карточку (допущение A1).

## 12. Допущения (требуют подтверждения)

- **A1.** Эталон один на карточку и не зависит от службы обучающегося-ДДС. Преподаватель отбирает карточки под
  своих обучающихся.
- **A2.** Банк ограничен обучающимися групп преподавателя, по аналогии с картой ошибок (`error_map_access`).
