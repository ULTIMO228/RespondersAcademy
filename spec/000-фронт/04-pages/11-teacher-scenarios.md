# 04-pages/11. Преподаватель: сценарии и эталоны (`/teacher/scenarios`, `/teacher/scenarios/[id]`)

**Роль:** Преподаватель. **Основание:** ТЗ §8 (создание/редактирование/валидация сценариев, классификация по сложности, критерии успешности), §10 (сценарий «Настройка учебной среды»), Q&A в3 (шаблоны+генерация, преподаватель-арбитр), в13 (96 учебных ситуаций из 32 билетов как эталоны и датасет).

## `/teacher/scenarios` — Список

### Состав

- Фильтры: категория событий (множественный выбор из групп ЕКП), сложность (1–5), источник (`template`/`generated`), статус валидации (`draft`/`pending`/`approved`/`rejected`).
- Таблица: название, категории, итоговые типы ЕКП, сложность, источник (бейдж «ИИ» для generated), статус валидации, кнопки: предпросмотр, редактировать, назначить в занятие, удалить (только неактуальные; с подтверждением).
- Кнопки действий: «Создать сценарий» (вручную, на базе карточки-шаблона), «Сгенерировать (ИИ)» — мок-генерация: выбор категории → получение 2–3 мок-сценариев со статусом `pending`.
- Блок «Загрузка материалов»: файлы DOCX/PDF/MP3-заглушки (ТЗ §12; сценарий А, шаг 8) + кнопка «Проверить грамматику» после ручных правок (мок-результат с подсветкой ошибок).

### Профильные категории обучающихся (ролевая модель, ТЗ §10 сценарий А шаг 5)

Привязка службы/организации курсанта (`User.service` или учебной группы целиком) к группам происшествий ЕКП, чтобы в ленту курсанта на занятии попадали **только профильные события** (Мосводоканал, Москоллектор, управы, службы газа…).

- Таблица привязки: строка — служба/группа курсантов, колонка — профильные группы происшествий из `classifier.json` (множественный выбор тегами). Пример по мок-данным (`mocks/users.json`):

| `User.service` / группа | Профильные группы происшествий ЕКП | Службы-получатели (`ServiceRef`) |
|---|---|---|
| ДДС района Чертаново Южное (гр. ДДС-01) | Дерево; Провал грунта яма; Снег грязь мусор тротуарная плитка; пожар в жилом доме | Упр. Чертаново Южное, ДДС Чертаново Южное, Деп. ЖКХ |
| ДДС района Зюзино (гр. ДДС-01) | Дерево; Провал грунта яма; пожар на улице | Упр. Зюзино |
| Мосводоканал (учебный профиль) | Аварии в городском хозяйстве - прорыв воды; Качество воды, нет воды, канализация; Скопление воды Подтопление Паводок | Мосводоканал, МОЭК |
| Мосгаз (учебный профиль) | Запах газа в помещении (в доме, в квартире); Запах газа на улице (вне помещения); Повреждение газопровода; Нарушения в работе газового оборудования | Служба 104 |
| Москоллектор (пример для ролевой модели) | Колодец люк повреждение; Провал грунта яма | Москоллектор |

- Поведение: фильтрация применяется при формировании `Session.cardFlow` — карточки непрофильных групп курсанту не выдаются; если выбранные в мастере занятия категории не пересекаются с профилем части группы, преподаватель видит предупреждение (см. `12-teacher-session.md`).
- Сохранение: кнопка «Сохранить привязку» — запись в мок-слой (таблица service/группа → группы ЕКП), действие фиксируется в аудите; привязка переживает перезагрузку страницы.

## `/teacher/scenarios/[id]` — Редактор и валидация

### Состав

1. **Параметры сценария** (ТЗ §8): название, категории, тип происшествия (привязка `classifierCodes` — выбор из дерева ЕКП по `classifier.json`), локация (округ/район), сложность 1–5, тайминги (реакция — дефолт 30 сек; отработка — дефолт 180 сек), режим (`demo`/`follow`/`practice`).
2. **Карточка-основа**: предпросмотр заполненной карточки (`cardTemplateId`) — тот же рендер, что у курсанта (аутентичность).
3. **Эталон** (`Etalon`): эталонные значения полей, ожидаемая последовательность действий (статусы + звонок точке C), эталонная формулировка текста + ключевые фразы (`keyPhrases`). Подсветка «правильных по мнению системы» вариантов (сценарий А, шаг 6).
4. **Предпросмотр вопросов и ответов**: как их увидит система при оценке.
5. **Коррекция**: контекстное поле комментария к вопросу/ответу (`validation.comment`) — «отрабатывается системой» (в моке: сценарий уходит в `pending` с записью комментария; повторная «генерация» выдаёт исправленный мок-вариант).
6. **Валидация**: кнопки «Утвердить полностью», «Утвердить частично» (чекбоксы по полям эталона), «Отклонить». Только `approved`-сценарии доступны для занятий.
7. **Критерии успешности**: порог допустимых грамматических ошибок, обязательные поля, требования к синтаксису ответов (ТЗ §8).

### Ограничения

- Удаление — с подтверждением и записью в аудит; системные данные преподаватель удалять не может (ТЗ §8).

## Критерии приёмки

- Полный цикл «генерация → предпросмотр → коррекция → утверждение» работает на моках; неутверждённый сценарий нельзя назначить в занятие.
- Привязка профильных категорий сохраняется в моке и ограничивает выдачу: курсант с профилем «Мосгаз (учебный профиль)» получает только карточки газовых групп происшествий.
- Частичное утверждение сохраняет выбор полей; комментарий коррекции виден в карточке сценария.
