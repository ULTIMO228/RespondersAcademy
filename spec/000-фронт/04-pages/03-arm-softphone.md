# 04-pages/03. АРМ-112: софтфон (`/arm/phone`)

**Роль:** Обучающийся. **Основание:** ТЗ §3 (имитация вызовов через виртуальную IP-телефонию), Q&A в2 (софтфон/WebRTC, эмуляция достаточна), Q&A в8 (контур B→C).

**Референсы:** телефонная панель АРМ ЕДДС (`research/arm-112/screenshots/arm-edds/page-28–31, 50.png`): вкладки Контакты/Звонки/SMS/Набор; верх карточки ПОВ-112 (АОН/предоставленный/на место).

## Назначение

Эмуляция внутренней IP-телефонии учебного контура. Главный сценарий: после обработки карточки диспетчер **связывается с руководством профильной службы (точка C)** по внутреннему 3–4-значному номеру; ИИ-абонент снимает трубку и подтверждает приём информации (реплики из мока).

## Состав

- **Статус линии оператора** (индикатор в шапке софтфона; дублирует блок состояния линии карточки — см. `02-arm-card.md`): `доступен` — готов к вызовам; `недоступен` — занят; `не подключен` — софтфон не зарегистрирован в учебном контуре; `ошибка` — сбой регистрации/линии (в моке состояния `не подключен`/`ошибка` переключаются флагом для демонстрации).
- **Панель набора**: поле номера (3–4 знака), кнопка «Позвонить», цифровая клавиатура (опционально).
- **Внутренние номера** (справочник из `reference.json → internalNumbers`): напр. 301 — «Руководитель дежурной смены ДДС», 302 — «Начальник выездной бригады», по службам. Вариант `callTarget` наряду с 301/302 — **учебные внутренние номера служб**: 101 — дежурный МЧС, 102 — дежурный СОДЧ МВД, 103 — дежурный СМП, 104 — дежурный МОСГАЗ; ожидаемый номер определяется главной службой карточки (`ClassifierEntry.mainService`). Контекстная подсказка: в рамках карточки подсвечивается номер, который ожидается по эталону (`Etalon.expectedActions`).
- **Экран активного вызова**: состояние («Вызов…», «Разговор», «Завершён»), таймер разговора, «голос абонента» — лог реплик ИИ в виде чата транскрипции («Слушаю вас» → после реплики диспетчера → «Я вас понял, информация принята»), кнопка «Завершить». Вариативность голоса (м/ж, служба) — текстовая пометка в логе (аудио опционально, Q&A в8).
- **Журнал вызовов**: дата/время, номер, длительность, ссылка на карточку (`PhoneCall`).
- Дополнительно (для аутентичности): вкладки «Контакты», «SMS» — минимальные эмуляции (SMS-чат-заглушка).

## Поведение

- Вызов открывается из карточки (кнопка в блоке «Действие диспетчера») или напрямую по номеру.
- Открытие карточки автоматически переводит линию в `недоступен` (оператор занят — новые вызовы ему не маршрутизируются); статус удерживается ещё 10 сек после закрытия карточки, затем линия возвращается в `доступен`.
- Если номер не из справочника — «Абонент не найден».
- Реплика диспетчера вводится текстом (или «удержать» кнопку-микрофон-заглушку); ИИ отвечает мок-репликой. Транскрипт пишется в `Attempt.calls`.
- Пропуск ожидаемого по эталону звонка — ошибка в оценке (`Evaluation.mistakes`).

## Критерии приёмки

- Полный цикл «набор → ответ ИИ → реплика → подтверждение → завершение» работает на моках без сети.
- Статус линии переключается по регламенту: открытие карточки → `недоступен`; после закрытия `недоступен` удерживается 10 сек → `доступен`.
- Транскрипт виден преподавателю в мониторинге и попадает в отчёт.
