# 04-pages/02. АРМ-112: карточка происшествия (`/arm/card/[cardId]`)

**Роль:** Обучающийся (диспетчер ДДС). **Основание:** ТЗ §8, §10; Q&A в4, в5, в6. Ключевой экран тренажёра.

**Референсы:** `hack/Фронт/images/p23_Image108.png` (вид карточки на АРМ-112 ДДС Чертаново Южное), `images/p15_Image74.png`, `images/p16_Image77.png`, `скриншоты_из_docx/ДДС_image6–20.png` (весь жизненный цикл). **Тема: светлая** (карточка) + тёмная нижняя панель служб.

## Состав (сверху вниз, по реальному экрану)

### 1. Верхняя полоса телефонии

- Блок состояния линии: статус телефонии оператора — **доступен / недоступен / не подключен / ошибка** (источник п. 1.6, 3.1). «Недоступен» проставляется автоматически при открытой карточке и держится 10 секунд после закрытия; ручное переключение — кликом по статусу. Кнопка «Отключение», иконка трубки; кнопки «записи звонков», «список SMS».
- Поля: **АОН** (автоопределённый, read-only), **предоставленный** (номер заявителя), **телефон на место** — маски `+7 (___) ___-__-__`, иконка копирования/АОН.
- Справа — шапка: «**Происшествие 881412**», «Сохр. 20.08.2021 в 11:57:19», «Опер. 14, АРМ 7, Рожкова О.И.»; кнопки «просмотр» (синяя) и «дополнение» (тёмная).
- В тренажёре дополнительно: **таймер отработки 3:00** (моноширинный) и компактный индикатор выполненного норматива 30 сек («Реакция: 0:18 ✓»). При превышении норматива красным окрашиваются таймер **и вся шапка карточки** — обязательное состояние интерфейса (источник п. 1.2).

### 2. Строка заявителя и флаги

- «Иванов» + статус заявителя («очевидец»).
- Справа текстовые флаги: «Пострадавшие: нет · Отказ от скорой: нет · Заблокированные: нет» + кнопки «ЧС» (молния), «ЧП» (треугольник), карандаш (редактирование — в тренажёре: только если сценарий разрешает).

### 3. Левая колонка

- **Адрес** (справочно, источник п. 3.6): единая адресная строка с выпадающим списком вариантов и автозаполнением полей (Страна, Субъект, Нас. пункт, Округ, Район, Улица, Дом, Корпус, Подъезд, Этаж, Описательный адрес). В реальном АРМ источники вариантов — Яндекс.Карты / Яндекс.Организации / ФИАС; в тренажёре эмулируются локальным мок-справочником адресов, без внешних сервисов. Отображение: «Россия, Москва, (ЮАО, Чертаново Южное), Чертановская улица, 58, к. 2, под. 2».
- Кнопка «Указать на карте» — клик по локальной карте-заглушке ставит отметку и заполняет адрес; иконка карты открывает окно локальной карты с точкой/полигоном (статичный тайл, без внешних сервисов).
- **Журнал событий / описание**: строки вида «17.09.2026 11:13:19 · УМЦ О.п. · Пожар в квартире» — история карточки.
- **Описание** — неформализованная информация, отметки о контроле.

### 4. Правая колонка — «Что случилось»

- Тёмный заголовок блока типа («Аварии и происшествия в городском хозяйстве»).
- Строка атрибутов анкеты (свёрнутая опросная карта): «Дерево. Двор (упало).» / у пожара: «Дом. Открытое пламя / Дым (дом)… Дом многоквартирный. квартира. Есть угроза людям…».
- «Класс.: Дерево упало во дворе;»
- «[ВИС] Класс.:» — для карточек из ВИС.
- Развёрнутый вид опросной карты (по клику): чип-группы вопросов анкеты типа (референс КАРТОЧКА_image2), выбранные — синие; в режиме диспетчера — read-only.

### 5. Поля ручного ввода диспетчера (тренажёр!)

В реальном АРМ диспетчер вводит комментарии к статусам; в тренажёре по сценарию ТЗ («введение текста», напр. «Сообщение принято, дежурная бригада направлена на место») добавляется блок **«Действие диспетчера»**:
- текстовое поле ответа (проверяется: грамматика + смысловая точность против `Etalon.expectedText`, Q&A в5);
- поля-заглушки «Номер наряда»;
- ввод сохраняется в `Attempt.enteredText`, автосохранение (буферизация при сбое, ТЗ §7).

### 6. Нижняя панель «Службы:» (тёмная, фиксированная)

- Плитки служб списка оповещения: название (допускается усечение «Поселение Во…»), время последнего статуса, статус («11:14 Добавлена»). «Только телефонные» службы — светло-серые. **Основные службы типа происшествия подчёркнуты двойной линией** (источник п. 1.5, 3.9).
- Моя служба — с иконками «конверт» (история) и «карандаш» (смена статуса). Активная плитка — синяя подсветка.
- Шеврон разворачивания панели (доп. службы), справа: иконка чата (бейдж счётчика), кнопка закрытия карточки.

### 7. Смена статуса реагирования (форма поверх затемнения)

- Поля: «Статус» (дропдаун — **только доступные по последовательности**, см. модель), «Номер наряда», «Комментарий» (обязателен для «Не принята»/«Отказ от выполнения работ» — валидация блокирует сохранение), кнопки ✓ / ✕.
- Последовательность: старт — «Принята»/«Не принята» → после «Принята»: «Начало реагирования», «Прибытие», «Проведение работ», «Работы завершены», «Отказ от выполнения работ» → после «Не принята» — только «Принята» (памятка стр. 25).
- «Работы завершены»/«Отказ…» закрывают карточку для редактирования (предупреждение перед сохранением, памятка стр. 22).

### 8. Попап истории службы (синий)

- Строки: «оп. 0 › 17.09.2026 11:23:21 Принята › Отправлен сантехник…» — вся хронология с авторами и комментариями; скролл при переполнении.

### 9. Подсказки новичку (hint-режим, Q&A в4)

- Если преподаватель включил: плашка-подсказка текущего шага («Откройте карточку → Проставьте "Принята" → …») из `Scenario.hints`.

### 10. Блок «Связи»

- Цепочка связанных карточек с ролями: **главная** / **подчинённая** карточка (источник п. 3.11); из блока — переход в связанную карточку (в реальном АРМ — средней кнопкой мыши, в тренажёре — обычным кликом).
- В тренажёре связи read-only (заданы мок-данными): операторская механика привязки (кнопка «Совпадение» по номеру заявителя/адресу, смена роли, отвязка, объединение цепочек) — справочно в подсказках, не воспроизводится.

### 11. Режим дополнения (Shift+F2)

- Кнопка «Дополнить» (Shift+F2) → доступны незаполненные ранее поля + «Описание со слов заявителя» → «Сохранить» (источник п. 3.13).
- Мок-блокировка при параллельном редактировании: если карточку дополняет другой пользователь, ввод блокируется — уведомление «Вы не можете вносить изменения» (и обратное уведомление, когда карточка снова доступна).

### 12. Строки отработки

- Read-only рендер `workLines`: оператор, дата/время, служба, куда звонили, кто принял, суть сообщения.
- Опциональная форма «Добавить отработку» (если сценарий разрешает): поля «Служба» (поиск по списку), «Куда звонили», «Телефон» (авто/вручную), «Кто принял», «Суть сообщения»; кнопка вызова на номер — связка с софтфоном тренажёра; подтверждающая галочка — без неё отработка не сохраняется (источник п. 3.13).

### 13. Модалка «Записи разговоров»

- Из кнопки «записи звонков»: список мок-записей с длительностью в формате мм:сс; прослушивание и скачивание мок-аудио (источник п. 3.13).
- Если записей нет — «Записей не найдено». Окно перетаскивается.

### 14. SMS в карточке

- Кнопки «Список СМС» / «История сообщений» — переписка по АОН карточки (все СМС с одного АОН попадают в первую карточку, источник п. 3.15).
- Форма «Отправить СМС» — рядом с полем АОН.
- Для входящей СМС-карточки — автозаполнение: текст СМС в «Описание со слов заявителя», полигон местоположения на локальной карте (источник п. 3.15).

### 15. Горячие клавиши (источник п. 3.17)

**Общие (активны в тренажёре):**

| Комбинация | Действие |
|------------|----------|
| Alt (зажатие) | Отображение подсказок по комбинациям клавиш |
| Insert | Создать новую карточку (в тренажёре: режим преподавателя) |
| Esc | Закрыть карточку / всплывающее окно |
| Tab / Shift+Tab | Переход вперёд/назад между полями и кнопками |

**Переход к блокам карточки (режим создания; в ДДС-режиме тренажёра неактивны — справочно в подсказках по зажатому Alt):**

| Комбинация | Действие |
|------------|----------|
| Alt+F1 / Alt+F2 / Alt+F3 | К блокам телефонных номеров |
| Alt+K | К блоку «Канал связи» |
| Alt+Q | К блоку заявителя |
| Alt+A | К блоку «Адрес» |
| Alt+P | К блоку пострадавших |
| Alt+N | К блоку «Нет контакта / Срыв звонка» |
| Alt+T | К блоку «Что случилось» |
| Alt+R | К блоку значимого типа происшествия |
| Alt+O | К блоку описания / отработок |
| Alt+Z | К блоку управления службами |
| Alt+1..n | К блокам добавленных опросных карт |

**Мгновенные действия (режим создания; в ДДС-режиме тренажёра неактивны — справочно):**

| Комбинация | Действие |
|------------|----------|
| Alt+S | Сохранение карточки |
| Alt+W | Создание связи |
| Alt+B | Создание напоминания |
| Alt+V | Указание происшествия как важного |
| Alt+M | Создание сообщения об ошибке |

**Режим просмотра (активны в тренажёре — ДДС-режим):**

| Комбинация | Действие |
|------------|----------|
| Shift+F1 | Пункт меню «Просмотр» |
| Shift+F2 | Пункт меню «Дополнить» |
| Alt+S | «Отработана» / «Завершить» (по статусу КП) |
| Alt+Y | «Проверена» (в статусе Проверена) |
| Alt+N | «Вернуть на доработку» (в статусе Проверена) |

В ДДС-режиме тренажёра активны общие комбинации и комбинации режима просмотра. Комбинации режима создания (переходы к блокам, мгновенные действия) не действуют: карточка открывается уже заведённой, поля — read-only.

## Данные

- `GET /api/mock/cards/[id]` → `IncidentCard`; действия → `POST /api/mock/cards/[id]/status` (пишет `ResponseStatusEvent` в `Attempt`); текст → в `Attempt.enteredText`.

## Состояния

- Открытие карточки автоматически проставляет «Получена службой» (памятка стр. 21) и останавливает таймер 30 сек.
- Карточка из ВИС (`createdByVis`): меньше данных — нет номера АРМ оператора, не всегда опросная карта и формализованные признаки (памятка стр. 14) — показывать пустые блоки с пометкой.
- Завершение отработки («Работы завершены»/«Отказ…»): экран итога попытки → мок-оценка ИИ (баллы по критериям + разбор ошибок, бейдж «ИИ») → «Следующая карточка» (сценарий В) или возврат в список.
- Потеря соединения (ТЗ §7): баннер «Соединение потеряно — восстанавливаем…», автопереподключение; таймеры продолжают идти; ввод буферизуется локально и досылается после восстановления (кратковременные сбои до 30 сек — без потери данных).

## Критерии приёмки

- Компоновка и подписи блоков соответствуют реальной карточке ДДС (проверка по скриншоту p23_Image108).
- Полный жизненный цикл статусов проходим без нарушения последовательности; «Не принята»/«Отказ…» без комментария не сохраняются.
- Ручной ввод уходит в оценку; опечатка в тексте видна в мок-разборе (грамматика).
- Таймеры 30 сек/3 мин фиксируются в `Attempt` для отчёта.
- При превышении норматива таймер и вся шапка карточки окрашиваются в красный (обязательное состояние, источник п. 1.2).
- Статусы телефонии — 4 состояния; «недоступен» выставляется автоматически при открытой карточке и держится 10 секунд после закрытия.
- Горячие клавиши: общие и режим просмотра активны; комбинации режима создания неактивны и показываются только в подсказках по зажатому Alt.
