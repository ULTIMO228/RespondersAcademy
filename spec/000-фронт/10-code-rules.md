# 10. Правила кода фронтенда

**Норматив:** `hack/Фронт/ПРАВИЛА-КОДА-ФРОНТ.md` — обязательные правила кода команды
(Feature-Sliced Design + SOLID, лимиты файлов, именование, чистота кода, чек-лист PR).
Принят без оговорок: нарушение = код не принимается в ревью.

Этот файл фиксирует **только адаптации норматива под наш стек** (Next.js App Router +
TypeScript) и карту слайсов проекта. Всё, что ниже не переопределено, действует по нормативу.

## 1. Структура: FSD внутри Next.js

Два «app» не смешиваются:

- `src/app/` — **FSD-слой app** (норматив п. 1.1): провайдеры, глобальные стили,
  стор приложения, entrypoint-логика;
- `app/` (корень репозитория) — **роутинг Next.js (App Router)**: только роуты-обёртки.

Роут-обёртка тонкая: реэкспорт слайса FSD-слоя `pages/` (+ гвард роли на layout-группе,
см. `03-architecture.md` → «Карта роутов»). Логики, данных и вёрстки в `app/` нет:

```tsx
// app/arm/card/[cardId]/page.tsx
export { IncidentPage as default } from '@/pages/incident';
```

Слои, слайсы, сегменты, правило импортов «только вниз», public API через `index.ts`
без `export *`, cross-imports через `@x` — по нормативу ч. 1. Слой `processes` не использовать.

## 2. Переменные окружения

- Только `NEXT_PUBLIC_*` (аналог правила `VITE_*` из норматива п. 3.3).
- Доступ — исключительно через `shared/config`; прямое обращение к `process.env`
  в коде слайсов запрещено.

## 4. Линтеры и формат

- **Steiger** (`@feature-sliced/steiger`) — обязателен в CI; ошибки Steiger = ошибка сборки
  (норматив п. 1.3, ч. 7).
- **ESLint**: `@typescript-eslint/recommended` + `react-hooks`
  (`rules-of-hooks`, `exhaustive-deps`).
- **Prettier** — единый конфиг в репо, автоформат на сохранении; споры о стиле закрыты конфигом.

## 5. Стили

- **CSS-модули** (`Component.module.css`) — единый подход на весь проект; хардкод hex
  в компонентах запрещён (норматив ч. 9).
- Дизайн-токены — в `shared/ui/styles/vars.css`; источник семантики —
  `07-design-guidelines.md` («Цветовая семантика»):
  - `--color-timer-exceeded` — красный таймер при превышении норматива;
  - цвета статусов карточки (Новая/Создана/Назначена/Принята/Завершена/Закрыта) —
    `--color-status-*` по канонической палитре;
  - цветокод служб (01/02/03/04/ЖКХ/АТ/ЕДДС/112) — `--color-service-*`.
- Смена дизайна правится в одном месте — в `vars.css`, не в компонентах.

## 6. Тесты

- По testing-политике проекта; файл теста — рядом с тестируемым
  (`Component.test.tsx`, норматив п. 2.2).
- Моки подключаются **только через `shared/api`**: route handlers `/api/mock/*`
  (при необходимости — MSW с теми же контрактами). Компоненты и хуки не знают
  про `fetch`, URL и файлы моков.
- Зависимости (localStorage, audio, телефония) — за интерфейсами в `shared/lib`,
  в тестах подменяются (норматив ч. 4).
