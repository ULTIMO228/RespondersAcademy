# План реализации: визуальный конструктор учебных сценариев

**Папка**: `spec/005-visual-scenario-builder` | **Дата**: 2026-10-19 | **Спека**: [spec.md](spec.md)
**Ветка**: работа ведётся в отдельной ветке от `main` (имя назначает владелец; спеки подготовлены в `claude/gracious-darwin-x0znyd`)
**Статус**: проект для обсуждения, код не менялся

## Кратко

Конструктор добавляет второй вид сценария — схему из блоков. Её собирает преподаватель в редакторе в стиле графового редактора Unreal, оформленном как корпоративная система. Схему исполняет детерминированный движок без ИИ, выдача идёт через существующие «Назначения». Каждая карточка оценивается в существующие `evaluations`, поэтому отчёты, правка оценок и карта ошибок работают без переделки. Архитектура меняется минимально:

- 5 новых таблиц одной миграцией;
- новый модуль API `/api/v1/flows*`;
- одна новая фича-слайс холста и две страницы на фронте;
- точечные расширения в `assignment_service`, `error_map_service` и TS-типах.

Авторизация, роли, симулятор `/arm/*`, групповые занятия и старые сценарии не меняются.

## Технический контекст

**Язык и версии**: TypeScript 5.9.3 (strict), React 19.3.0, Next.js 16.3.5 App Router (по `package-lock.json`; `node_modules` в контейнере аудита не установлены — перед кодом `npm ci` и чтение `node_modules/next/dist/docs/`); Python ≥ 3.11.
**Основные зависимости**: FastAPI, SQLAlchemy 2 async, Pydantic v2, Alembic (бэкенд); без новых npm-зависимостей (research R6).
**Хранение**: SQLite (dev/demo) / PostgreSQL (цель); миграция `0006_scenario_flows`; триггеры неизменности версий по образцу `0004_ai_immutability_guards`.
**Тесты**: pytest (unit — валидатор, движок, оценка; contract — формы ответов и права; integration — задание → прохождение → оценка); Vitest + RTL (холст, инспектор, библиотека, словарь интерфейса); Playwright (снимки симулятора не изменились; путь конструктора).
**Целевая платформа**: офисный ПК без GPU, Chrome / Firefox / Яндекс.Браузер, экран 1920 px и шире, локальная сеть без интернета.
**Тип проекта**: веб-приложение (фронт Next.js + бэкенд FastAPI в одном репозитории).
**Цели производительности**: проверка схемы до 150 блоков / 500 путей — не больше 1 с; пересчёт состояния прохождения — не больше 50 мс на запрос; холст на 60 блоках — плавное перетаскивание.
**Ограничения**: локальный контур (без внешних сетей и CDN); аутентичность `/arm/*` 1:1; платформа — токены `--pf-*`; FSD + Steiger; русский интерфейс; ИИ не обязателен.
**Масштаб**: десятки преподавателей, сотни студентов, схемы до 150 блоков.

## Проверка по конституции

| Принцип | Как выполняется | Итог |
|---|---|---|
| I. Локальный контур, CPU-only | Без моделей и внешних API; холст без внешних библиотек и CDN | ✅ |
| II. Методическая достоверность | Варианты блоков — только из справочников: статусы и переходы ДДС, службы, классификатор ЕКП, банк из 96 ситуаций, нормативы 30/180 с. Каждая ошибка — одна строка со ссылкой на шаг и этап. Преподаватель правит оценку существующим механизмом с аудитом | ✅ |
| III. Измеримый ML | Оценка полностью детерминирована и раскладывается по блокам; ML не добавляется. Воспроизводимость проверяется пересчётом (SC-003) | ✅ (ML вне объёма) |
| IV. Простота | Без циклов, без параллельных веток, без проводов данных, без фоновых задач; выдача через существующие задания; без мок-дубля | ✅ |
| V. Единый контракт | Схема `flow/1` версионирована и лежит в `contracts/`; режим `dds \| operator112` в сценарии и оценке; оценка в общем формате `Evaluation` | ✅ |
| Ограничение «три роли, RBAC» | Роли не меняются: эксперт и руководитель группы — преподаватели | ✅ |

Нарушений нет, таблица «Обоснование сложности» не нужна. Повторная проверка после дизайна (фаза 1): изменений нет.

## Риски

| Риск | Мера |
|---|---|
| Холст — самая трудоёмкая часть (перетаскивание, масштаб, доступность) | ограничения v1 (без вложенных групп, мини-карты и автораскладки); запасной вариант — React Flow по решению владельца (R6) |
| Показ реплик и вводных в симуляторе может задеть аутентичность | только существующие каналы (транскрипт, лента работ); снимки `simulator-visual` — гейт |
| Расхождение TS ↔ Pydantic | `extract_ts_fields.py` + контрактные тесты |
| Пересчёт «на лету» при большом журнале | журнал одного прохождения — десятки событий; `trace` фиксируется при завершении |
| Дрейф «эксперт = любой преподаватель» | вопрос В1; если понадобится флаг, это одно поле пользователя, без новых ролей |
| Существующие БД (`dev.db`, `demo.db`) без новых таблиц | `alembic upgrade head` или `app.seed.load --reset` — только с разрешения владельца (урок L009) |

- **В3. Групповые занятия**: нужно ли в этой фиче запускать схемы в групповом занятии (`/teacher/session`), или хватит «Назначений»? В проекте: только «Назначения».
