## Подготовка

```bash
npm ci
cd backend && uv sync --group dev && uv run python -m app.seed.load --reset   # нужна миграция 0006; согласовать сброс с владельцем
uv run uvicorn app.main:app --port 8000

```

Учётные записи — демо-пользователи из `spec/000-фронт/mocks/users.json`: два преподавателя (автор и эксперт), преподаватель с закреплённой группой, студент этой группы, администратор.

## Сценарий 1. Сборка по билету 4.1 (истории 1–2, SC-001)

1. Автор: «Конструктор» → «Создать», режим «Специалист 112».
2. Собрать схему из `data-model.md` §11, при этом специально не подключить выход «Нет» у условия.
3. «Проверить» → ошибка E05 у условия, блок подсвечен; «Запустить тест» и «Опубликовать» недоступны.
4. Подключить выход, «Проверить» → «Ошибок нет», путей: 2, максимум баллов: 10.
5. Перезагрузить страницу — схема та же.

## Сценарий 2. Контрольный набор некорректных схем (SC-002)

Фикстуры `backend/tests/fixtures/flows/invalid/*.json` — по одной на каждое правило E01–E14 (кроме E06, который проверяется на уровне формата), всего 12. Ожидаемо: `POST /flows/{id}/validate` возвращает ровно ожидаемый код ошибки, а `publish` — 422.

```bash
cd backend && uv run pytest tests/unit/test_flow_validator.py -q
```

## Сценарий 3. Пробный прогон (история 3)

1. «Запустить тест» → в «Моих действиях» указать адрес «ул. Грина, 11», этажность 14, газификация «нет», оповестить 101 и 102.
2. Ожидаемо:
   - путь идёт через «Нет» и подсказку;
   - 104 не оповещена → ошибка `flow.action.missed`;
   - балл = (3 + 1 + 0 + 3 + 1) − 1 (подсказка) = 7 из 10 → 70.
3. Тестовое прохождение не видно в статистике.

## Сценарий 4. Версии и согласование (история 4)

1. Администратор: «Система» → включить «Обязательное согласование».
2. Автор: «Отправить на согласование» → версия 1 «На согласовании»; кнопки «Согласовать» у автора нет (`review` от автора → 403; от эксперта → 200).
3. Эксперт: комментарий к блоку, «Вернуть на доработку» → автор видит комментарий, сценарий снова «Черновик».
4. Автор исправляет и отправляет снова, эксперт согласует → «Опубликован v1».
5. Автор: «Редактировать» → черновик; две вкладки сохраняют с одной ревизией — вторая получает 409.

## Сценарий 5. Прохождение студентом (истории 5–6)

1. Автор назначает v1 группе (тренировка, порог 70).
2. Студент проходит в `/arm/operator112`:
   - звонок приходит, реплики появляются в транскрипте;
   - на условии отмечает газификацию «да» → идёт ветка «Да».
3. Автор публикует v2. Задание студента по-прежнему на v1 (`GET /assignments/{id}` → `flowVersions[0].version = 1`).
4. Студент «Завершить» → результат: балл, «сдано / не сдано», ошибки с шагами. До завершения `GET /flow-runs/{id}/result` → 409; `GET /flow-runs/{id}` не содержит ожидаемых значений.
5. Пересчёт: `uv run pytest tests/unit/test_flow_engine.py -k replay` — 20 зафиксированных журналов дают тот же путь и балл (SC-003).

## Сценарий 6. Руководитель группы (история 7)

1. Преподаватель с группой: `/teacher/constructor/{id}/stats?groupId=<своя>` → 200, проценты ошибок на блоках.
2. Чужая группа → 403.
3. Ошибки прохождения видны в `/teacher/error-map/<группа>` на этапах «Место» и «Оповещение служб» (SC-006).
