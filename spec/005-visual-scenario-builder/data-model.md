# Модель данных и правила: визуальный конструктор сценариев (фича 005)

Документ задаёт блоки, их входы и выходы, правила соединения, проверки, исполнения, оценки, версий и доступа. Всё реализуется обычным кодом и правилами, ИИ не нужен. Внутренние названия (`type`, `port`) в интерфейсе не показываются, пользователь видит только русские подписи из колонки «Подпись».

## 1. Структура сценария

```text
Сценарий-схема (ScenarioFlow, sf-NNN)
├── метаданные: название, описание для студента, режим (dds | operator112), сложность 1–5, категории ЕКП, автор
├── черновик: схема (FlowGraph) + номер ревизии + результат последней проверки
└── версии 1…N (ScenarioFlowVersion) — неизменные снимки схемы, каждая со статусом и согласованием
      └── используется в заданиях (AssignmentFlowVersion) → прохождения (FlowRun) → оценки попыток (Evaluation)
```

Схема (`FlowGraph`, формат `flow/1`) хранится одним JSON-документом:

```json
{
  "schemaVersion": "flow/1",
  "nodes": [
    { "id": "n1", "type": "start", "title": "Начало", "position": { "x": 80, "y": 200 }, "props": { } }
  ],
  "edges": [
    { "id": "e1", "from": { "node": "n1", "port": "next" }, "to": { "node": "n2" } }
  ],
  "settings": { "lateCreditPercent": 50, "hintPenalty": 1 }
}
```

- `id` блока и стрелки — короткая строка, уникальная внутри схемы; при копировании сохраняется.
- `position` — только для отображения, на исполнение не влияет.
- `settings` — значения по умолчанию на всю схему, их можно поменять в свойствах блока «Начало».

## 2. Блоки первой версии (11 типов)

Группы библиотеки: **Начало и конец**, **Вызов и заявитель**, **Действия диспетчера**, **Логика**, **Обучение**.

| `type` | Подпись | Группа | Вход | Выходы (подписи) | Что делает | Главные настройки | Проверка (баллы) | Этап по умолчанию |
|---|---|---|---|---|---|---|---|---|
| `start` | Начало | Начало и конец | нет | `next` «Следующий шаг» | Точка старта, общие нормативы | режим (ДДС / Специалист 112), норматив реакции (30 с), норматив отработки (180 с), описание для студента, доля зачёта при опоздании (50%), штраф за подсказку (1) | — | — |
| `end` | Завершение | Начало и конец | «Вход» | нет | Конец прохождения | исход: «Успешно» / «Неуспешно» / «Нейтрально»; сообщение для разбора | — | — |
| `incomingCall` | Входящий вызов | Вызов и заявитель | «Вход» | `next` «Следующий шаг» | Создаёт карточку: в ДДС — в журнале, в 112 — звонок в софтфоне | источник: «Из банка билетов» (поиск по 96 ситуациям) или «Своя ситуация» (суть, адрес, заявитель: ФИО, телефон, статус из справочника; группа ЕКП) | — | `intake` |
| `callerReply` | Реплика заявителя | Вызов и заявитель | «Вход» | `next` «Следующий шаг» | Добавляет фразу заявителя в транскрипт / ленту | текст реплики; голос (муж./жен.) | — | — |
| `requiredQuestion` | Обязательный вопрос | Вызов и заявитель | «Вход» | `correct` «Верно» (обязателен), `wrong` «Неверно» (необязателен) | Ждёт, пока студент зафиксирует в карточке нужные сведения | что выяснить (поле карточки из списка: адрес, уточнение адреса, телефон, ФИО, статус заявителя, число пострадавших, этаж, этажность, газификация, признак ЕКП); правильный ответ; способ сравнения («Точно», «Содержит слова», «Одно из», «Похоже — допускает опечатки», «Число от… до…», «Любое заполненное»); срок, сек (необязательно); реплика заявителя, если студент ответил неверно (необязательно) | да | по полю: адрес → `address`/`place`, заявитель → `applicant`, признаки → `signs` |
| `action` | Действие | Действия диспетчера | «Вход» | `done` «Выполнено» (обязателен), `missed` «Не выполнено» (необязателен) | Ждёт действие студента в АРМ | что сделать (список: «Поставить статус…», «Вызвать службу по телефону…», «Оповестить службу…», «Перевести в ЦУС другого региона», «Выбрать признак…», «Выбрать тип по классификатору…», «Написать комментарий, содержащий…»); значение из справочника; срок, сек; «Важен порядок» (выкл.) | да | статус → `statuses`, служба → `services`, перевод → `route`, тип → `decision`/`type`, признак → `signs`, комментарий → `card` |
| `forbiddenAction` | Запрещённое действие | Действия диспетчера | «Вход» | `next` «Следующий шаг» | С этого места и до конца следит, чтобы студент НЕ сделал указанное | то же, что «Действие», плюс пояснение, почему нельзя | штраф | как у «Действия» |
| `condition` | Условие | Логика | «Вход» | `yes` «Да», `no` «Нет» (оба обязательны) | Разветвляет путь по тому, что сделал или указал студент | что проверить (список ниже); сколько ждать, сек (по умолчанию 60; 0 — проверить сразу) | — | — |
| `randomVariant` | Случайный вариант | Логика | «Вход» | `a` «Вариант А», `b` «Вариант Б», `c` «Вариант В» (число вариантов 2–3, все обязательны) | Делает попытки разными: выбирает ветку один раз на прохождение | число вариантов; вес каждого (по умолчанию равные); подпись варианта | — | — |
| `briefing` | Вводная | Логика | «Вход» | `next` «Следующий шаг» | Событие по ходу работы | вид: «Сообщение о ходе работ» (выехали / прибыли / начали / завершили), «Повторный звонок заявителя», «Служба отказалась»; текст; задержка, сек | — | — |
| `hint` | Подсказка | Обучение | «Вход» | `next` «Следующий шаг» | Показывает подсказку (только в тренировке, в экзамене пропускается) | текст; штраф, баллы (по умолчанию из «Начала») | штраф | — |

Перечень «что проверить» у **Условия** (каждый пункт — готовая фраза с полями из справочников):

| Вариант | Как считается «Да» |
|---|---|
| «Студент выбрал признак …» | в журнале событий есть выбор признака |
| «Студент поставил статус …» | есть смена статуса на указанный |
| «Студент вызвал или оповестил службу …» | есть вызов или оповещение службы |
| «Студент указал в поле … значение …» (с тем же способом сравнения, что у вопроса) | значение поля карточки совпадает |
| «Ответ на вопрос „…“ верный» (ссылка на блок «Обязательный вопрос» выше по пути) | вопрос завершился выходом «Верно» |
| «Студент уложился в норматив реакции» | первичная реакция ≤ норматива |
| «Студент брал подсказку» | на пути была показана подсказка |

Баллы и критичность у блоков-проверок (`requiredQuestion`, `action`) и штрафных блоков (`forbiddenAction`, `hint`): `points` — целое 1–10 (по умолчанию 1), `critical` — «Критическая ошибка» (по умолчанию выкл.), `stage` — этап «схемы приёма вызова» (по умолчанию по таблице, автор может сменить; список этапов — `backend/app/services/error_map_stages.py`).

Набор блоков зависит от режима в «Начале»:

| Настройка | ДДС | Специалист 112 |
|---|---|---|
| «Поставить статус…» | статусы `reference.ddsStatuses` | — |
| «Вызвать службу по телефону…» | `reference.internalNumbers` | — |
| «Оповестить службу…» | — | службы `reference.services` |
| «Выбрать признак / тип…» | — | классификатор ЕКП (`classifier.json`) |
| «Обязательный вопрос» | поля карточки ДДС (ограниченно: комментарий, наряд) | все поля опросной карты |

## 3. Формат входов и выходов

- **Типов данных нет.** У любого блока не больше одного входа «Вход» и 0–3 именованных выхода. По стрелке передаётся только «ход» — какой шаг следующий. Это сознательное упрощение по сравнению с Unreal Blueprints: значения по проводам не текут, пользователю не нужно понимать переменные.
- **Сведения о прохождении** (что ввёл и сделал студент) движок держит сам, в «журнале прохождения». Блоки «Условие» и «Обязательный вопрос» читают их по ссылке из справочника, а не по проводу.
- Выход — это возможный исход блока. Каждый выход ведёт ровно к одному следующему блоку. В один вход может приходить сколько угодно стрелок (ветки сходятся).
- Необязательные выходы («Неверно», «Не выполнено»): если не подключены, движок идёт по основному выходу («Верно» / «Выполнено»), а ошибка всё равно фиксируется.

Нормализованные события студента, которые читает движок (собираются адаптером из уже существующих данных попыток — `attempts.statuses`, `services_called`, `calls`, `entered_text`, `events`):

```json
{ "kind": "status",  "value": "accepted",  "cardRef": "n2", "at": "2026-10-19T10:00:25+03:00" }
{ "kind": "call",    "value": "104",       "cardRef": "n2", "at": "…" }
{ "kind": "service", "value": "svc-104",   "cardRef": "n2", "at": "…" }
{ "kind": "transfer","value": "region",    "cardRef": "n2", "at": "…" }
{ "kind": "sign",    "value": "газифицирован", "cardRef": "n2", "at": "…" }
{ "kind": "type",    "value": "1020101",   "cardRef": "n2", "at": "…" }
{ "kind": "field",   "field": "addressRefined", "value": "ул. Грина, 11", "cardRef": "n2", "at": "…" }
{ "kind": "text",    "field": "dispatcherAction", "value": "…", "cardRef": "n2", "at": "…" }
{ "kind": "finish",  "at": "…" }
```

`cardRef` — блок «Входящий вызов», к карточке которого относится событие.

## 4. Правила соединения (проверяются при рисовании и при проверке)

| № | Правило | Что видит пользователь при нарушении |
|---|---|---|
| С1 | Стрелка идёт от выхода к входу; от входа к выходу не тянется | линия не прилипает |
| С2 | У «Начала» нет входа, у «Завершения» нет выходов | нет точки подключения |
| С3 | Из одного выхода — не больше одной стрелки; новая заменяет старую | старая стрелка исчезает (отменяется Ctrl+Z) |
| С4 | Стрелка на сам себя запрещена | линия не прилипает |
| С5 | Стрелка, замыкающая круг, запрещена | всплывающее «Так получится круг: сценарий не сможет закончиться» |
| С6 | В один вход можно привести сколько угодно стрелок | — |
| С7 | Блоки ожидания и показа (вопрос, действие, реплика, вводная, запрещённое действие, условие с проверкой карточки) должны стоять после хотя бы одного «Входящего вызова» на любом пути | проверка, ошибка E09 |

## 5. Правила проверки корректности (сервер; одинаковы для «Проверить», теста и публикации)

## 6. Модель выполнения (движок)

Движок — **чистая функция**: `replay(схема версии, зерно, события, время сейчас) → состояние`. Состояние в фоне не хранится и не «тикает»: при каждом запросе студента или преподавателя оно пересчитывается из журнала событий. Отсюда воспроизводимость (SC-003), восстановление после перезагрузки страницы и отсутствие фоновых задач.

1. **Старт.** При начале задания создаётся прохождение (`FlowRun`) со случайным зерном (`seed`) и активным блоком «Начало».
2. **Один активный шаг.** Параллельных веток нет.
3. **Блоки показа** (`start`, `incomingCall`, `callerReply`, `briefing`, `hint`, `randomVariant`, `forbiddenAction`) проходятся мгновенно (у «Вводной» — после своей задержки):
   - «Входящий вызов» создаёт попытку по карточке (существующие механизмы ДДС / 112), с этого момента идёт отсчёт нормативов карточки;
   - «Реплика» и «Вводная» добавляют запись в ленту студента;
   - «Подсказка» в экзамене пропускается без штрафа;
   - «Случайный вариант» выбирает выход по зерну (`hash(seed, nodeId)` → по весам);
   - «Запрещённое действие» включает наблюдателя до конца прохождения.
4. **Блоки ожидания:**
   - «Действие» / «Обязательный вопрос» завершаются выходом «Выполнено» / «Верно», как только в журнале появилось подходящее событие. Если выключено «Важен порядок», подходит и событие, случившееся раньше входа в блок. Если срок истёк, а подходящего события нет, — выход «Не выполнено» / «Неверно». Если событие пришло после срока, но до завершения прохождения, оно засчитывается как «выполнено с опозданием» (частичный балл) и идёт по выходу «Выполнено».
   - Без срока блок ждёт до завершения прохождения.
   - «Условие» ждёт до своего «сколько ждать». Если событие, дающее «Да», появилось раньше — выход «Да» сразу; иначе по истечении ожидания — «Нет».
5. **Завершение:**
   - путь дошёл до «Завершения»;
   - студент нажал «Завершить»: активный блок и все блоки-проверки дальше по пути (по выходам «Не выполнено» / «Неверно» / «Нет», а при их отсутствии — по основному) засчитываются как невыполненные;
   - истёк лимит времени задания: то же, что «Завершить».
6. **Что видит студент:** ленту реплик и вводных, свои карточки, оставшееся время. Ожидаемые значения, баллы и следующую ветку — нет.
7. **Пробный прогон автора** — тот же движок, события вводятся из панели «Мои действия». Прохождение имеет `isTest=true` и в статистику не попадает.

Журнал прохождения (`trace`, хранится в `FlowRun` после завершения и пересчитывается при чтении во время прохождения):

```json
[
  { "nodeId": "n1", "enteredAt": "…T10:00:00", "leftAt": "…T10:00:00", "port": "next" },
  { "nodeId": "n4", "enteredAt": "…T10:00:05", "leftAt": "…T10:00:31", "port": "done",
    "result": { "status": "late", "points": 0.5, "maxPoints": 1, "eventAt": "…T10:00:31" } }
]
```

## 7. Оценка и фиксация ошибок (без ИИ)

- **Максимум** — сумма `points` блоков-проверок на фактически пройденном пути (с учётом достройки пути при досрочном завершении).
- **Набрано:**
  - выполнено в срок — `points`;
  - выполнено с опозданием — `points × lateCreditPercent / 100`;
  - не выполнено / неверно — 0;
  - каждое срабатывание «Запрещённого действия» — `−points` блока;
  - каждая показанная подсказка — `−hintPenalty`.
  Итог не ниже 0.
- **Балл** = `round(100 × набрано / максимум)`, от 0 до 100.
- **Сдано** = балл ≥ проходного порога задания (`params.passThreshold`, по умолчанию 70) и нет критических ошибок.
- **Раскладка по карточкам:** каждый блок относится к карточке ближайшего предшествующего «Входящего вызова». По каждой карточке пишется обычная оценка (`evaluations`, `assessor_version = "flow/1"`) со своим баллом. Отчёты, журнал группы, правка оценки преподавателем и карта ошибок работают без изменений.

Запись ошибки (расширение существующего `EvaluationError` — `type`, `severity`, `message` — необязательными полями):

```json
{
  "type": "flow.action.late",
  "severity": "major",
  "message": "Шаг «Поставить статус „Принята“»: выполнено через 41 с при сроке 30 с",
  "ruleId": "t1",
  "stage": "statuses",
  "nodeId": "n4",
  "expected": "Принята за 30 с",
  "actual": "Принята на 41-й секунде",
  "at": "2026-10-19T10:00:41+03:00",
  "pointsLost": 0.5
}
```

| Код `type` | Когда | `severity` |
|---|---|---|
| `flow.action.missed` | действие не выполнено | `critical`, если у блока стоит «Критическая ошибка», иначе `major` |
| `flow.action.late` | выполнено после срока | `minor` |
| `flow.action.order` | выполнено раньше предыдущего шага при включённом «Важен порядок» (засчитано как не выполнено) | `major` |
| `flow.question.missed` | сведения не зафиксированы | как у `missed` |
| `flow.question.wrong` | зафиксировано, но не совпало | `major` |
| `flow.forbidden` | сделано запрещённое | `critical` / `major` |
| `flow.hint` | взята подсказка | `minor` |
| `flow.run.aborted` | прохождение прервано «Завершить» или по времени | `minor` (для справки, без баллов) |

- `ruleId` берётся из существующей раскладки правил, если блок однозначно ей соответствует. Например, первичный статус в срок → `t1`, служба → `d1`, статус «Не принята» без комментария → `v4`. Иначе ставится `flow-<type>`, а этап задаёт явное поле `stage`. Карта ошибок учитывает `stage`, если он есть (небольшая правка `error_map_service`).
- Грамматику и «смысловые» оценки текста движок схемы не считает. Если для «Действия: комментарий» включить «Проверять грамматику», это существующий детерминированный спеллчек (не ИИ); по умолчанию выключено.

## 9. Состояния и версии

```text
            Сохранить (сколько угодно)
          ┌──────────┐
          ▼          │
      [Черновик] ────┘
          │ Опубликовать (проверка без ошибок, актуальная ревизия)
          ├─────────────── согласование выключено ──────────────┐
          ▼                                                      ▼
  [На согласовании] ── Согласовать (не автор) ──────────► [Опубликован vN]
          │                                                      │ Редактировать
          └── Вернуть на доработку (с комментарием) ──► [Черновик] ◄┘ (из vN, публикация → vN+1)
  [Опубликован] ── Архивировать ──► [В архиве]  (нельзя назначить; выданные задания доигрываются)
```

- Статус сценария — это статус последней версии плюс признак «есть черновик» (в списке: «Опубликован v3 · есть черновик»).
- Версия на согласовании тоже неизменна. При возврате она получает статус «Возвращена» и остаётся в истории.
- Одновременно у сценария не больше одного черновика и одной версии на согласовании.
- Публикация фиксирует снимки карточек «Из банка билетов» и создаёт карточки для «Своих ситуаций» (`incident_cards.mode_origin = "flow"`), чтобы последующие изменения банка не меняли опубликованную версию.

Нормализованные события прохождения отдельно не хранятся: они строятся из существующих `attempts` (статусы, вызовы, тексты, события 112). Только события тестового прогона, у которого попыток нет, лежат в `flow_runs.test_events` JSON.

Изменения существующих таблиц: нет. `assignments` связываются через новую `assignment_flow_versions`, как уже сделано для ИИ-версий (`assignment_scenario_versions`). Настройка «обязательное согласование» — ключ в существующих настройках «Системы» (`scenarioFlows.requireReview`, по умолчанию `false`).

## 11. Пример: билет 4, ситуация 1 (c-010)

«Горит балкон и два окна на 13-м этаже… ул. Грина, № дома неизвестен, в доме библиотека № 193 (ул. Грина, 11). Дом 14 эт., газифицирован». Режим — специалист 112.

```text
[Начало] → [Входящий вызов: билет 4.1]
         → [Реплика: «Горит балкон на тринадцатом этаже, номер дома не знаю, там библиотека»]
         → [Запрещённое действие: «Оповестить СМП (103)» — пострадавших нет, 1 балл]   (действует с этого места до конца)
         → [Обязательный вопрос: уточнение адреса = «ул. Грина, 11» (Похоже), 3 балла, критическая]
               Верно ─────────────┐
               Неверно → [Реплика: «Это дом, где библиотека сто девяносто три»] ─┘
         → [Обязательный вопрос: этажность = 14 (Число 14–14), 1 балл]
         → [Условие: «Студент указал в поле „Газификация“ значение „да“», ждать 60 с]
               Да  → [Действие: оповестить службу 104, 2 балла] → ┐
               Нет → [Подсказка: «Уточните, газифицирован ли дом»] → [Действие: оповестить службу 104, 2 балла] → ┐
         → [Действие: оповестить службу 101, 3 балла, критическая]
         → [Действие: оповестить службу 102, 1 балл]
         → [Завершение: Успешно]
```

Пути: 2. Максимум на любом пути: 3 + 1 + 2 + 3 + 1 = 10 баллов. Ожидаемые службы взяты из разметки карточки (`expectedServices`: 101 главная, 104 — дом газифицирован, 102). Запрещённое действие стоит в начале: наблюдение действует от блока до конца прохождения, поэтому блок перед самым «Завершением» ничего бы не поймал. Пример иллюстративный: окончательную раскладку баллов задаёт преподаватель.
