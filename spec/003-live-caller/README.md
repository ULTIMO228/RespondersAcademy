# Актуализация 19.10.2026

Потоковая реализация заменяет прежний WAV-режим в тренировочном софтфоне. Актуальные требования и контракт — [realtime.md](realtime.md); конкретный стенд и состояние проверки — [инструкция](../../backend/deploy/realtime-qwen/README.md). Ниже сохранено описание предыдущего прототипа. Оно не является критерием готовности realtime.

## История предыдущего прототипа

## Объём и роли

Итоговое уточнение пользователя 19.10.2026: нужен потоковый диалог в реальном времени, а не запись, отправка после паузы и воспроизведение WAV. Предыдущий конвейер не принят пользователем. Он отключён в интеграции софтфона: при включённой фиче тренировка показывает честное состояние отсутствия realtime-подключения, не загружает запись и не захватывает микрофон. Экзамен и выключенная фича используют прежний режим записей. Для нового контура нужны потоковый голосовой backend, доступ к нему и проверка лицензий/возможности локального развёртывания всех моделей. Текстовый Chat Completions API не является заменой такого соединения. Работающий realtime-звонок пока не заявляется.

Поправка после ручной пробы 19.10.2026: кнопочный обмен репликами не удовлетворяет запросу на разговор. Микрофон захватывается один раз при ответе; AudioWorklet передаёт PCM, детектор речевой активности выделяет фразы по паузе (около секунды), автоматически отправляет WAV. Начало речи прекращает текущую озвучку; вопросы, сказанные во время обработки ответа, сериализуются. Есть уровень микрофона, отключение/включение, завершение освобождает все дорожки и AudioContext. Тишина не отправляется. Восстановление после перезагрузки требует одного явного включения микрофона. Это непрерывный захват с автоматическими границами реплик; STT/LLM/TTS остаются запросами по законченным фразам, не потоковым серверным аудио. Приёмка: первая фраза не обрезана, пауза отправляет один запрос, озвучку можно прервать, поздний ответ не возобновляет прерванный звук, mute/уход/ошибки освобождают ресурсы. Порог детектора требует ручной проверки на реальной гарнитуре.

Поправка 19.10.2026 по уточнению пользователя: для финала разрешён облачный API сильной модели с доступными весами; локальное развёртывание выполняется позднее. Серверный транспорт `LIVE_CALL_LLM_TRANSPORT=api` получает настраиваемые base URL, модель и секретный ключ. Облачный режим по умолчанию формирует естественные реплики по исходным фактам билета; локальная малая модель сохраняет выбор готовых фактов. Режим ответа выбирается отдельно (`auto/facts/dialogue`). Переезд той же модели на локальный совместимый сервер меняет настройки соединения, без изменений UI. Промпт ограничивает факты, но не гарантирует отсутствие галлюцинаций при генерации текста. Качество проверяется после подключения ключа; до этого внешние запросы не выполняются. Vosk и Silero пока остаются локальными.

- Обучающийся принимает собственный вызов активного тренировочного задания, записывает вопрос кнопкой «Говорить», отправляет его, слушает ответ, завершает разговор и заполняет прежнюю карточку.
- Преподаватель и администратор могут прочитать сохранённый диалог через авторизованный API попытки. Автоматическую оценку карточки нужно проверить преподавателю: модель может не раскрыть все факты.
- Только `training`; экзамен сохраняет прежний режим. По умолчанию функция выключена. Нет SIP и звонков на реальные номера. Локальный транспорт работает без внешних API; транспорт `api` использует выбранный облачный или собственный сервер.
- Это диалог по очереди, не непрерывный full-duplex. VAD, потоковый STT, перебивания и автоматическое определение конца фразы — следующий этап.

## Архитектура, модели данных и поток

`Operator112Softphone` выбирает контрол по `NEXT_PUBLIC_LIVE_CALLS_ENABLED`. UI использует `useLiveCaller`, сеть находится в `shared/api/endpoints/live-call`, микрофон — за интерфейсами `shared/lib/audio-recorder` и `shared/lib/live-call`. Серверный `CallerProvider` отделяет жизненный цикл вызова от реализации моделей.

1. «Ответить» проверяет разрешение микрофона и выполняет существующий answer.
2. Сервер проверяет владельца, состояние попытки и задания, доступность моделей, синтезирует первую реплику по summary билета. Повторный start возвращает тот же разговор.
3. Браузер отправляет моно PCM WAV 16 кГц с UUID реплики. Сервер распознаёт речь и читает исходные факты билета (без `addressRefined` и эталонных служб). Адрес и контакты возвращаются непосредственно. В режиме `facts` на остальных вопросах LLM выбирает ключи фактов; сервер озвучивает их значения. В режиме `dialogue` LLM генерирует короткую реплику по фактам с сохранением ролей истории, сервер проверяет формат и длину ответа. Факты и системный промпт не принимаются от клиента.
4. Диалог сохраняется в `Attempt.calls`, запись `kind=liveCaller`: id, status, startedAt, endedAt, maxDurationSec, transcript. Реплика: speaker (`dispatcher`/`caller`), text, at, turnId. В записи нет скрытого эталона, токенов или ключей. WAV ответов — `VAR_DIR/live-calls/{attemptId}/{turnId}.wav`.
5. Повторная отправка UUID возвращает уже готовую реплику. Ошибка распознавания/LLM/TTS видна; неполная реплика не сохраняется. Завершение и уход освобождают микрофон; finish идемпотентен. После перезагрузки start возвращает сохранённое состояние.

База API: `/api/v1/operator112/attempts/{attemptId}/live-call`.

| Метод | Назначение |
| --- | --- |
| GET | Состояние и транскрипт; до старта `idle` |
| POST | Начать, вернуть `active` и первую реплику |
| POST /turn | Multipart `file`, `turnId`; вернуть обновлённый диалог |
| GET /audio/{turnId} | WAV сохранённой реплики; проверка доступа к попытке |
| POST /finish | Завершить, вернуть `ended` |

Ошибки: 401/403 — доступ, 400 — входные данные/пустое распознавание, 409 — состояние или лимиты, 503 — модели/настройки. Не более 20 вопросов и трёх минут по умолчанию; лимит времени проверяется клиентом и сервером перед следующей репликой. Запрос, начатый до лимита, может закончиться позже.

## Запуск

Нужен работающий Python backend с обычной авторизацией и БД, фронт с `BACKEND_URL`. Мок-сервер живые вызовы не реализует. Инструкция и команды: [LIVE-CALLER.md](../../docs/LIVE-CALLER.md).

## Трассировка и приёмка

| Требование пользователя | Реализация | Проверка |
| --- | --- | --- |
| Браузер + гарнитура | существующий WAV recorder, освобождение микрофона | hook: отказ, уход во время старта, завершение |
| Вместо записи — разговор с ИИ | авторизованный API, STT/LLM/TTS, аудиоответ | API: полный цикл и повтор UUID; локальная модель: smoke |
| Существующая карточка | флаг и прежний RecordedOperator112Softphone | существующие тесты виджета, typecheck |
| Можно разворачивать локально | Vosk, Silero, llama.cpp/Ollama, настраиваемый URL/model | smoke локальных компонентов |
| Без доступа к чужим звонкам | require_attempt + проверка student owner | API: 401/403, экзамен, закрытая попытка |
| Надёжный повтор и сохранение | серверный UUID, атомарное сохранение пары реплик | API: сбой TTS, повтор; hook: сетевой сбой |

Ограничения: один backend worker (блокировка в процессе), факты читаются из текущего билета — не редактировать билет во время звонка. Нет отдельного отчёта с диалогом в UI преподавателя, политики очистки аудио и автоматической проверки достоверности каждого ответа LLM. Компактная модель выбрана для проверки на CPU; качество и задержка на гарнитуре требуют ручного испытания. Финальный статус проверок фиксируется в отчёте о реализации, ручное испытание нельзя заменять тестом с синтетическим WAV.
