# Модель данных — фича 019

## Специализация (новое значение)

| Поле | Тип | Правило |
|---|---|---|
| `Specialization` | `"operator112" \| "dds"` | словарь режимов проекта (конституция V) |
| `User.specializations` | `Specialization[] \| null` | у `student` — непустой список без дублей (одна или обе); у `teacher`/`admin` — `null`; изменяет только `admin` (и `teacher` для своих групп — допущение 2) |

Хранение: `users.specializations` (JSON), миграция `0007_user_specializations` (существующим `student` → `["dds"]`). Публичный вид (`to_public`) отдаёт ключ только когда он есть (как `assignedGroups`).

## Viewer (бэкенд)

`Viewer` получает `specializations: tuple[str, ...]` (из строки `User`, читаемой в `get_viewer`); `has_specialization(mode)`: `teacher`/`admin` → истина (режим просмотра), `student` → вхождение в список.

## Допустимые сочетания «режим → требуемая специализация»

| Режим задания / попытки | Требуется у студента |
|---|---|
| `operator112` | `operator112` |
| `dds` | `dds` |
| `chain` | обе |

Правило проверяется: при создании задания (назначаемые студенты), при старте и создании попытки, при событиях и отправке попытки, при открытии ДДС-карточки.

## Состояния карточки (уточнение ответственности, без новых таблиц кроме данных 112)

`Создана → Зарегистрирована` (112, «Сохранить» + подтверждение оповещения) `→ Отработана` (112) `→ Закрыта` (112; из «Создана/Завершена/Отменена»); статусы службы `Получена → Принята/Не принята → … → Работы завершены/Отказ` ведёт ДДС. Состояния «Нет контакта», «Срыв звонка» — признаки карточки/вызова, ставит 112. Точные имена полей и значения сверяются с `backend/app/models/card.py` и `types/cards` в задачах.
