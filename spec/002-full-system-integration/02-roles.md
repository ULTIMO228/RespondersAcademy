# Роли и права: Сквозная интеграция (Фича 002)

Роли — как в `spec/000-фронт/02-roles.md`: обучающийся (`student`), преподаватель (`teacher`), администратор (`admin`). Фича добавляет разделы только для обучающегося; экраны преподавателя и администратора не создаются, но их права на новые эндпоинты фиксируются здесь, потому что бэкенд уже их различает.

Источник прав — код бэкенда (`app/api/deps.py`: `require_viewer`, `require_role`, `assert_own_attempt`) и таблицы `specs/002-two-mode-simulator/contracts/v1-endpoints.md`. Гварды маршрутов фронта — `proxy.ts` (чужая роль → `/forbidden`, без сессии → `/login`).

## 3. Инварианты изоляции

1. Фронт не полагается на скрытие кнопок: отказ сервера (401/403) всегда обрабатывается и показывается пользователю (экран «Доступ запрещён» или сообщение), см. FR-040.
2. Идентификатор обучающегося берётся сервером из сессии; фронт не передаёт `studentId`, кроме сценариев преподавателя/администратора (вне объёма).
3. Обучающийся не видит эталон билета и разбор чужих попыток; эталонные различия (`fieldDiff`) показываются только после передачи собственной карточки.
4. В экзамене подсказки и повторное прослушивание запрещены независимо от клиента.
5. Все действия обучающегося логируются сервером (аудит, конституция «Рабочий процесс и качество»); фронт не ведёт собственного аудита.

Авторизация (`POST /auth/password`, `POST /auth/logout-all`, `GET /auth/session`): доступны любой аутентифицированной роли и действуют только на **свою** учётную запись/сессии. Смена чужого пароля — только администратором через существующий `reset-password`.

Гварды `proxy.ts`: matcher `/arm`, `/student`, `/teacher`, `/admin`, `/reference`, `/account`; для `/reference` и `/account` достаточно любой валидной сессии; серверные лэйауты проверяют роль через `verifySession()` (`03-architecture.md` §3.2).
