## Резюме

**Что изменилось 2026-09-29 (часть B).** Владелец указал, что текущий фронт — «сырая копия АРМ», а нужна обучающая система: платформа-«обложка» с родственным, но более красивым оформлением и всеми нужными страницами (главная, задания, результаты, аналитика, «мой кабинет», справочник; у преподавателя — назначения и обучающиеся; у администратора — аудит и безопасность) и **правильной авторизацией**. План теперь состоит из двух частей: **A** — интеграция (разрывы G1–G6) и **B** — платформа и авторизация (G7–G9, `07-platform-shell.md`). Симулятор АРМ (`/arm/*`) остаётся точной копией боевой системы; всё вне его получает новый визуальный язык. Правки бэкенда ограничены авторизацией (B1–B5).

**Часть A.**

Бэкенд волны B готов, фронт и сеть до него не доходят. План: сначала починить основу (роутеры, полная схема БД с триггерами, проксирование `/api/v1`, автономные ответы ИИ-панелей), затем вывести во фронт режим специалиста-112, задания/экзамен, прогресс, рекомендации и базу знаний, затем цепочку A → B с сообщениями служб и голосовым докладом, в конце — сквозная приёмка. Новых эндпоинтов бэкенда не создаётся; контракт — код бэкенда (`contracts/v1-integration.md`). Все решения Фазы 0 и их источники — в [research.md](research.md).

## Технический контекст

**Язык/версии**: фронт — TypeScript 5.9.3 strict, React 19.3.0, Next.js 16.3.5 (App Router; гайды — `node_modules/next/dist/docs/`); бэкенд — Python 3.11+.
**Основные зависимости**: без новых. Фронт — только существующие (`docs/LIBRARIES.md`); бэкенд — FastAPI, SQLAlchemy 2 async, Pydantic v2, Alembic. Запись звука — браузерные API без библиотек (R6).
**Хранилище**: SQLite `backend/var/dev.db` (разработка), PostgreSQL (целевая, extra `pg`); фронт-мок — in-memory стор процесса Next.
**Тестирование**: фронт — Vitest 5.0.1 + RTL 16.3.3 (тесты рядом с кодом), Playwright 1.63.0; бэкенд — `pytest` (`tests/{unit,contract,integration}`), `ruff`; сквозные HTTP-скрипты `scripts/e2e-*.sh`.
**Целевая платформа**: Chrome/Firefox/Яндекс.Браузер, desktop-first ≥ 1920 px, локальный изолированный контур (Windows 10/11, Ubuntu 20.04+, macOS для разработки), без GPU.
**Тип проекта**: web-приложение — фронтенд (Next.js) + бэкенд (FastAPI) в одном репозитории.
**Цели по производительности**: полная отработка вызова в режиме 112 — норматив 3 мин (`norms.submitSec: 180`), первичная реакция — 30 с (`answerSec`); опрос ленты сообщений — тик 2–5 с (`FEED_TICK_MS`); запись доклада ≤ 180 с (≈ 5,5 МБ WAV, лимит бэкенда 20 МБ).
**Ограничения**: нет внешних сетей в рантайме; ML-модели (Silero TTS, Vosk small-ru) локальные и опциональные — без них аварийные режимы; правила фронта (FSD, CSS-модули на токенах, состояния экрана, ошибки не скрываются); аутентичность АРМ-112 1:1.
**Объём**: часть A — экран режима 112, задания, лента сообщений, запись доклада, ~10 клиентских модулей API, правки бэкенда (роутер, миграция) и фикстура демо (31 задача). Часть B — новые токены и набор компонентов платформы, оболочка и навигация, ~12 новых страниц (главная, задания, результаты, аналитика, справочник, профиль обучающегося; назначения, обучающиеся, группы преподавателя; главная, аудит, безопасность администратора), переоформление существующих страниц преподавателя и администратора, безопасная авторизация с малыми правками бэкенда (27 задач). Итого 61 ID (58 активных) в 4 волнах.

## Платформа-обложка и авторизация (часть B)

Подробно — [`07-platform-shell.md`](07-platform-shell.md); исследование — `research.md` R14–R21; задачи — `tasks.md` T032–T058.

### Что делаем на фронте (кратко)

1. **Авторизация переделывается на серверную сессию.** `arm112_session` выдаёт бэкенд (`HttpOnly`); `proxy` проверяет оптимистично, страницы — `verifySession()` (`GET /auth/session`); клиентский `session-store`, JSON-cookie и чтение `document.cookie` удаляются; вход без «Номера АРМ» и без шага 2FA; смена пароля и «выйти на всех устройствах»; нейтральные сообщения, блокировка, безопасный `returnUrl`; мок-режим повторяет то же.
2. **Появляется платформенный слой** с оболочкой (боковая и верхняя панели, хлебные крошки, плашка «Учебная система…») и новым визуальным языком `--pf-*`; **симулятор `/arm/*` не меняется**, к нему добавляется тонкая панель «В кабинет».
3. **Кабинет обучающегося**: главная, задания, результаты с разбором, аналитика, справочник (105 статей + номера + памятки + горячие клавиши + статусы), профиль.
4. **Кабинет преподавателя**: назначения (создание — сейчас недоступно из UI), обучающиеся, группы, главная с задачами подтверждения, справочник с правкой, экспорт отчётов; существующие страницы переоформляются без потери функций.
5. **Кабинет администратора**: главная, аудит, безопасность; существующие страницы переоформляются.

### Как фронт получает сессию на сервере (закрывает U1 из `/speckit-analyze`)

`verifySession()` делает серверный `fetch` на **собственный origin** `${origin}/api/mock/auth/session` с пробросом заголовка `cookie` (origin — из `headers()`: `x-forwarded-proto` и `host`). Запрос попадает под rewrite (бэкенд при заданном `BACKEND_URL`) либо в мок-обработчик — один код для обоих режимов; `BACKEND_URL` при этом читается только в `next.config.ts`, как требует AGENTS §6. Решение принято в задаче T036; риск — корректный origin за прокси, в тестах fetch подменяется.
