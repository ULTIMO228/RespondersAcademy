# Пользовательские потоки: Сквозная интеграция (Фича 002)

Сценарии для реализации и приёмки. Пути и поведение сверены с кодом бэкенда (`contracts/v1-integration.md`). Демо-учётки — сиды `spec/000-фронт/mocks/users.json`: обучающиеся `ivanov` (`u-005`), `petrova` (`u-006`); преподаватель `morozova` (`u-002`). Пример билета — `c-010` («пожар в жилом доме»). Конкретные тексты реплик заявителя в примерах — иллюстрации; реальные берутся из билета.

Соответствие историям спецификации: Поток 1 → US1; Поток 2 → US5; Поток 3 → US4; Поток 4 → US4; Поток 5 → US2/US3 (проверка стенда).

## Поток 1. Первичный приём вызова в режиме «Специалист-112» (US1)

**Участник**: обучающийся `ivanov`. **Предусловие**: преподаватель создал тренировочное задание `operator112` с билетом `c-010`; фронт запущен с `BACKEND_URL`.

1. **Задание.** Обучающийся входит на `/login`, открывает «Задания», видит карточку тренировки с режимом, числом билетов, порогом и состоянием. Нажимает «Начать».
2. **Входящий вызов.** Открывается рабочее место 112: индикатор входящего вызова на софтфоне, идёт отсчёт ожидания ответа относительно норматива задания (`norms.answerSec`, в сиде 30 с). Подсказки (`hints`) для тренировки включены и показываются после `idleSec` бездействия.
3. **Ответ.** «Ответить на вызов» (клавиатурное сокращение — по референсу АРМ-112). Фиксируется время ответа; если норматив превышен — событие `answerTimeout`. Включается таймер разговора; плеер запрашивает запись заявителя.
   - *Аварийный режим.* Если записи нет (не готова, сбой синтеза, `emergency`), вместо плеера показан транскрипт с пометкой «Аварийный режим: аудио недоступно, показан текстовый транскрипт»; ввод не блокируется.
4. **Адрес.** Вводит улицу: после 3 символов подсказка из справочника улиц; выбор из подсказки фиксируется как «из справочника», ручной ввод — как «вручную».
5. **Опросная карта.** Отмечает признаки; при каждом выборе клиент отправляет событие `signSelected` и пересчитывает список оповещения: обязательные службы включены автоматически (с причиной), условные — предложены («добавить вручную» → `serviceAdded`).
6. **Передача.** Заполнены адрес и описание (или опросная карта). Нажимает «Передать карточку». При пустом адресном блоке сервер отвечает 400 — сообщение на поле, введённое сохранено.
7. **Разбор.** Показывается оценка: итоговый балл, время, корректность, грамматика, смысл, ошибки одной строкой, таблица различий с эталоном по полям, версия оценщика; бейдж «ИИ» у ИИ-составляющей. Для тренировки «сдал/не сдал» не показывается; для экзамена — показывается.
8. **Перезагрузка.** Если обучающийся обновил страницу до передачи, он возвращается в ту же попытку (запрос задания `start` возвращает открытую попытку; так же в экзамене).

**Проверка**: SC-001, SC-003, SC-005.

## Поток 2. Цепочка A → B: от вызова до диспетчера ДДС (US5)

**Участники**: обучающийся `ivanov`, преподаватель `morozova`. **Предусловие**: задание `chain` для `ivanov` (утверждённая версия `operator112` для билета назначена) с `workMessagesEnabled: true`; в сиде такого задания нет — его создаёт фикстура (`quickstart.md` §E, задача T031).

1. **Этап A.** Обучающийся проходит Поток 1 (шаги 1–7). После передачи вместо «Дальше» видит сообщение: «Карточка сохранена. Этап ДДС ожидает проверки и подтверждения преподавателем». Кнопка «Начать этап ДДС» доступна, но при нажатии до подтверждения объясняет причину (ответ 409 «Вход ДДС ожидает проверки и подтверждения преподавателем»).
2. **Подтверждение.** Преподаватель открывает `/teacher/scenarios/{scenarioId}` (`scenarioId` из `chainReview`), в панели ИИ видит новую версию со статусом «на проверке» (источник — карточка обучающегося) и утверждает её (`POST /ai/scenarios/{scenarioId}/approve`, `{ version, requestId }`).
3. **Этап B.** Обучающийся нажимает «Начать этап ДДС»: `start` возвращает попытку ДДС по сохранённой карточке; клиент открывает `/arm/card/{cardId}`. Карточка — та, что обучающийся оформил на этапе A.
4. **Обработка.** Диспетчер принимает карточку в работу. Бэкенд планирует четыре сообщения от служб относительно момента принятия (по умолчанию через 20, 50, 90 и 150 с).
5. **Лента.** Клиент периодически запрашивает `work-messages` с курсором `since`; в ленте появляются сообщения: «Расчёт выехал к месту вызова» (`departed`), «Расчёт прибыл на место» (`arrived`), «Начаты работы» (`started`), «Работы завершены» (`done`), каждое со временем. Дубликаты не показываются. Если занятие не включало сообщения, блока нет.
6. **Голосовой доклад.** Диспетчер нажимает «Голосовой доклад» на софтфоне карточки, записывает речь (адрес, тип, пострадавшие, решение), нажимает «Отправить». Клиент шлёт WAV моно 16 бит 16 кГц с адресатом (по умолчанию `112`).
   - Успех: показаны распознанный текст и чек-лист из пяти пунктов (номер карточки, адрес, тип, пострадавшие, решение) с отметками и долей выполненных, например «4 из 5».
   - Ошибки: «Распознавание речи недоступно» (503, модель не установлена), «Речь не распознана», «Ожидается моно PCM WAV 16 бит, 8 или 16 кГц» — карточка не теряется.
   - Нет микрофона/доступа: сообщение и продолжение без доклада.
7. **Завершение.** Диспетчер завершает работу по карточке; оценка режима ДДС и отчёт — по существующим механизмам (вне объёма фичи).

**Проверка**: SC-006, SC-005 (отказы речи), FR-030–FR-035.

## Поток 3. Экзамен (US4)

**Участник**: обучающийся. **Предусловие**: сидовый экзамен `asg-002` (`operator112`): билеты `c-071`, `c-090`, порог 70, `timeLimitSec: 600` **на каждый билет**, подсказки отключены сервером.

1. «Задания» → карточка экзамена показывает условия: лимит времени на билет, число билетов, порог, «повторное прослушивание запрещено».
2. «Начать» → открывается первый билет, включается индикатор лимита (`openedAt + timeLimitSec`); клиентские часы — только индикатор, истина у сервера.
3. Первый билет: обучающийся принимает вызов, слушает запись. Повторное прослушивание блокируется («Повторное прослушивание в экзамене запрещено», ответ 409).
4. Передаёт карточку; сразу видит разбор; в оценке экзаменационной попытки есть признак «сдал/не сдал» по порогу задания (`passed`).
5. Повторно открыть тот же билет нельзя (409 «В экзамене билет выдаётся один раз»).
6. Отрабатывает второй билет (завершение задания — по лимиту на сервере или действием преподавателя; у обучающегося кнопки «Завершить» нет), либо лимит на билет истекает: по нулю индикатора клиент запрашивает состояние — просроченная попытка закрыта сервером («не выполнено», оценка 0, «Истёк лимит времени»), итог «не сдал».
7. Итог задания: «сдан/не сдан» и баллы относительно порога (`Assignment.state`, `passed` по билетам в `progress`).

**Проверка**: SC-004, FR-013, FR-021.

## Поток 4. Аналитика, рекомендации, справочник (US4, US7)

**Участник**: обучающийся с историей попыток.

1. **Аналитика.** `/student/analytics`: сводка (число попыток, средний балл, реакция, топ ошибок, динамика, разрезы по режимам/форматам) и список попыток с фильтрами «режим» и «формат», постранично. Без истории — пустые состояния.
2. **Рекомендации.** Блок «Рекомендации ИИ» (бейдж «ИИ»): для каждой — название, причина (тип ошибки, число повторов, правило). Кнопка «Принять/Изучить»: принимает рекомендацию (`accept`) и открывает связанный материал — статью базы знаний группы. Принятая помечается и уходит вниз выдачи. (Прямой запуск билета возможен только при наличии задания — A5.)
3. **Справочник.** `/reference`: поиск по названию и группе, фильтр по группе; статья показывает пять разделов: признаки, оповещение, уточнения, решение ДДС, типичные ошибки. Всего 105 статей.

**Проверка**: SC-007, FR-022–FR-025.

## Поток 5. Проверка стенда (US2, US3)

**Участник**: инженер/CI.

1. `cd backend && uv run pytest -q && uv run ruff check .` — ожидание: 0 failed, 2 skipped (на T003 — 362 passed = 359 + 3 теста Alembic; число растёт с тестами фичи); ruff чист.
2. Пустая БД: `alembic upgrade head` создаёт 44 таблицы; `alembic check` — без расхождений; затем сид (`python -m app.seed.load`).
3. `BACKEND_URL=http://localhost:8000` → `npm run build && npx next start`; открыть экраны ИИ преподавателя и раздел «Задания» — в консоли нет 404 на `/api/v1/*`.
4. Без `BACKEND_URL` (пересборка): экраны ИИ преподавателя отвечают 200 синтетикой с бейджем «ИИ»; новые разделы обучающегося показывают «Раздел требует подключения к серверу тренажёра».

**Проверка**: SC-002, SC-003, FR-001–FR-006.
