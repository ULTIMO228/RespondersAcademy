# 04-pages/13. Преподаватель: отчёты и аналитика (`/teacher/reports`, `/teacher/reports/[sessionId]`)

**Роль:** Преподаватель. **Основание:** ТЗ §8 (отчёты по успеваемости, инсайты ИИ), §10 (состав отчёта о занятии), Q&A в16 (детальный состав отчёта, графики), ТЗ §6 (экспорт Excel/PDF — опционально).

## `/teacher/reports` — Журнал отчётов

- Таблица прошедших занятий: дата, группа, категории, курсантов, средний балл, статус («отчёт сформирован»/«черновик»).
- Фильтры: период, группа, курсант, категория.

## `/teacher/reports/[sessionId]` — Отчёт о практическом занятии

### Состав (строго по ТЗ §10 + Q&A в16)

1. **Шапка**: дата занятия, преподаватель, категории, режим; мок-индикация «Отчёт сформирован за N сек» (демонстрация норматива ТЗ §7 — формирование отчёта ≤ 30 сек); кнопки экспорта: «Скачать CSV», «Скачать PDF» (опционально XLSX — ТЗ §6; в тестовом фронте — генерация файла на клиенте из мока).
2. **Сводная таблица по курсантам** (`ReportRow`): ФИО, № АРМ, карточек отработано, средняя реакция (с) и отклонение от 30 сек, средняя отработка (с) и отклонение от 180 сек, грамматических ошибок, интегральный балл.
3. **Детализация по каждой попытке**: карточка (№, тип), тайминги по этапам (реакция, статусы, завершение) с отклонениями от нормативов, допущенные ошибки (`mistakes`), грамматические ошибки (`grammarErrors`) — построчно: **поле** карточки, **фрагмент** «как написано» → «как правильно», **тип** (`spelling` — орфография / `syntax` — синтаксис); одного счётчика без детализации недостаточно. Балл с расшифровкой по критериям (время/корректность/грамматика/смысл) — веса видны и настраиваются.
   Каждая ошибка (`mistakes` и `grammarErrors`) маркируется **критичностью** (`severity`): `critical` — нарушение регламента/искажение смысла (пропущен звонок точке C, оповещена не та служба, истёк норматив реакции); `major` — влияет на балл (превышение норматива отработки, незаполненное обязательное поле); `minor` — незначительное (опечатка без искажения смысла). В детализации — фильтр по severity.
4. **Оценка: ИИ vs преподаватель**: мок-оценка ИИ с бейджем «ИИ» + форма экспертной оценки преподавателя (балл + комментарий) — **приоритет за преподавателем** (Q&A в3); изменение оценки фиксируется в журнале аудита (ТЗ §8 — обязательное ограничение; показать запись «оценка изменена преподавателем X, было/стало»).
5. **Обратная связь курсанту**: комментарий к результату и рекомендации по улучшению (ТЗ §8) — отправляется в `/arm/progress` курсанта.
6. **Инсайты ИИ по группе** (`groupInsights`, мок): типичные ошибки группы («4 из 6 превысили норматив реакции», «частые опечатки в названиях улиц»), рекомендации по следующим занятиям.
7. **Графики и диаграммы** (`charts`) — три структурных блока:
   - `byStage` — по этапам отработки: время реакции и полной отработки по попыткам против нормативов 30/180 сек (line с линией норматива);
   - `byErrorType` — по типам ошибок: «тепловая карта ошибок» по полям карточки и типам (тайминг / заполнение / грамматика / последовательность статусов / пропущенный звонок; heatmap — опциональный модуль аналитики ТЗ §6);
   - `dynamics` — динамика: баллы по курсантам (bar), средний балл по занятиям (line).
   Требование финальной экспертизы ТЗ §17: диаграммы наглядны и достоверно отражают данные.

## Критерии приёмки

- В отчёте присутствуют все обязательные элементы ТЗ §10: действия, замечания (ошибки), время заполнения карточки, отличие времени от нормативного, грамматика.
- В шапке видна индикация «Отчёт сформирован за N сек», N ≤ 30 (ТЗ §7); грамматические ошибки детализированы (поле, фрагмент, тип spelling/syntax); ошибки классифицированы по severity (critical/major/minor); графики сгруппированы в блоки byStage/byErrorType/dynamics.
- Изменение оценки преподавателем пересчитывает итог и оставляет след в аудите (видимый в `/admin/system` → журналы).
- Экспорт CSV выгружает сводную таблицу; PDF — отчёт целиком (можно print-to-pdf верстку).
