# 04-pages/01. АРМ-112: главный экран «Поиск происшествий» (`/arm`)

**Роль:** Обучающийся (диспетчер ДДС). **Основание:** ТЗ §8, §10; Q&A в4, в6.

**Референсы:** `hack/Фронт/images/p12_Image66.png` (главный экран ПОВ-112, роль «Контролер»), `скриншоты_из_docx/ДДС_image2–5.png` (главный экран ДДС, тёмная тема). **Тема: тёмная** (`07-design-guidelines.md`).

## Состав

### Верхняя панель

- Слева: заголовок «Поиск происшествий» + кнопка-лупа; ссылка «расширенный по параметрам» (разворачивает форму расширенного поиска), кнопка «сбросить».
- Центр/справа: текущие дата и время («Четверг, 17 Сентябрь 2026», часы ЧЧ:ММ:СС — живые), пользователь (ФИО + «АРМ <номер>»), иконка уведомлений.
- Селектор вида «выберите что показать» — фильтр ленты; значения: «Все карточки», «Пустые карточки» (завершённые без обработки — «Нет контакта»/«Срыв звонка», источник п. 3.4), «Новые СМС» (источник п. 1.3, 3.15); тумблер «Автообновление» (по умолчанию включён — памятка стр. 11: следить, чтобы бегунок в правом положении); селектор «Записей на странице: 10».
- В тренажёре ДОПОЛНИТЕЛЬНО: бейдж активного занятия (название, оставшееся время) и счётчик новых неоткрытых карточек.

### Таблица «Список происшествий»

Колонки (по реальному экрану ДДС): Связи · ЧС · Опер. · АРМ · Номер · Дата · Время · Тип происшествия · Постр. · Адрес · Статус службы. Справа в строке: иконки действий (развернуть, закладка, молния — «важное происшествие», будильник — «напоминание»), иконка журнала, предпросмотр; красный индикатор новых СМС по карточке (источник п. 3.15).

- Строка разворачивается вниз: «Описание: <дата время оператор — текст>» (референс ДДС_image3).
- «Статус службы» — последний статус реагирования моей службы с цветным маркером (красная стрелка «Добавлена» и т.п.).
- Колонка «Связи» — счётчик связанных карточек; клик раскрывает цепочку связей с ролями «главная»/«подчинённая», из цепочки — переход в связанную карточку (источник п. 1.3, 3.11). В тренажёре связи read-only; операторская механика привязки (кнопка «Совпадение» по АОН/адресу, смена роли, объединение цепочек) — справочно в подсказках, не воспроизводится.
- Молния — «важное происшествие»: пометка карточки как важной + мок-уведомление главным специалистам с номером АРМ и ФИО оператора (источник п. 3.13); в строке — индикация важного (подсветка/иконка).
- Будильник — «напоминание» (источник п. 3.13): текст + время срабатывания. Окно напоминания появляется только при закрытой карточке; при закрытии окна без действий повторяется каждые 20 секунд. Действия из окна: перейти в карточку, удалить, переназначить.
- ЧС — красный бейдж. Постр. — отметка о пострадавших («Нет»/кол-во).
- Тултип при наведении на тип происшествия — код типа («101»).
- Пагинация: «Страница: 1 · Записей на странице: 10 · 1–10 из N».

### Расширенный поиск (разворачиваемая форма)

Поля (памятка стр. 35–40, источник п. 3.14): Тип происшествия · Признаки происшествия (дерево, как в опросной карте; поиск по 3-му уровню не работает — честно сохранить ограничение) · АРМ (множественный выбор) · Адрес · По округу (через запятую) · По району (один) · По описательному адресу · По региону · По службе (множественный выбор) · По описанию · Заявитель (ФИО/АОН) · По каналу связи (множественный выбор) · По источнику происшествия (ВИС, множественный выбор) · По оператору, работавшему с КП из ВИС · Номер карточки · Статус карточки (множественный выбор) · Период (дата/время заведения). Множественные селекты — чипы с выбором нескольких значений.

### Поступление новой карточки (режим занятия)

- Новая строка появляется вверху с визуальным (мигание/подсветка, с учётом reduced-motion) и звуковым сигналом (опционально).
- В строке — **таймер первичной реакции 30 сек** (моноширинный, краснеет при истечении); открытие карточки останавливает таймер и фиксирует `Attempt.openedAt`.
- Несколько неоткрытых карточек одновременно — норма (многозадачность, Q&A в6): каждая со своим таймером; сортировка — новые сверху.
- Лента фильтруется по профильным категориям: обучающийся видит только карточки своих профильных групп ЕКП (привязка `User.service` → группы ЕКП; настройка — преподавателем при подготовке занятия, ТЗ §10 сценарий А шаг 5).

### Мои назначенные модули (тренажёрное дополнение)

- Список назначенных преподавателем сценариев со статусом `approved` (ТЗ §8: обучающийся «выбирает доступные (назначенные преподавателем) учебные модули»): название, категории, сложность, дедлайн занятия.
- Клик по модулю → переход в занятие: старт сессии по сценарию, лента карточек + бейдж активного занятия.

## Данные

- `GET /api/mock/cards` (фильтры = поля расширенного поиска) → `IncidentCard[]` (списочная проекция).
- Новые карточки занятия: `GET /api/mock/sessions/[id]/feed` → `CardFlowItem[]`.

## Состояния

- Пусто: «Карточек нет» (референс ДДС_image2 — «0 из 0»).
- Автообновление выкл. → плашка «Автообновление отключено — список может быть неактуален».
- Истёкший таймер 30 сек → строка помечается нарушением (красная рамка/маркер), нарушение пишется в `Attempt` для отчёта.

## Действия

- Открыть карточку → `/arm/card/[cardId]`.
- Предпросмотр (иконка) → модалка с краткой информацией, оповещёнными службами и последними статусами (памятка стр. 14).
- Поиск/сброс; переключение страниц пагинации.
- Горячие клавиши списка: Insert — создать новую карточку (в тренажёре: режим преподавателя — ручное заведение учебной карточки; у обучающегося неактивно), Esc — закрыть карточку/попап (возврат в список).

## Критерии приёмки

- Колонки, порядок и подписи соответствуют реальному экрану ДДС; тёмная тема.
- Таймер 30 сек работает по каждой новой карточке независимо; истечение фиксируется.
- Расширенный поиск фильтрует мок-карточки хотя бы по: тип, адрес, округ, статус, период, описание, заявитель (ФИО/АОН), номер карточки.
