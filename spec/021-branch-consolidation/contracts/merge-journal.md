# Контракт: журнал слияния (`spec/021-branch-consolidation/merge-journal.md`)

Журнал — единственный источник правды о ходе слияния. Записи только дописываются. Исправление
оформляется новой записью со ссылкой на прежнюю.

## Запись шага

```markdown
## F<N> — K<id> <ветка> @ <tip>

- Дата: YYYY-MM-DD HH:MM
- База: <хеш интеграционной ветки до шага>
- Вершина источника сверена: <tip> = origin/<ветка> ✅ | расхождение → новый кусок
- Merge-коммит: <хеш>
- Конфликты: <N> (список — ниже)
- Генерируемые файлы пересобраны: expected_fields.json | uv.lock | mocks:sync — команда
- Миграции: головы до/после (`uv run alembic heads`), merge-ревизия <id> | —
- Быстрый гейт: lint ✅|❌ · steiger · typecheck · test <passed>/<failed> · pytest <p>/<f>/<s> · ruff
- Красные: <тест> → наш | унаследован (доказано: прогон на <ветка>@<tip>, дата)
- Итог: влит | откатан (`git revert -m 1 <merge>` → <revert-хеш>, причина; гейт после отката = гейт предыдущего шага)
```

## Запись конфликта

```markdown
| Файл | Тип (content/modify-delete/rename/add-add) | Взято из HEAD | Взято из K<id> | Почему |
```

Правила:
- Решение «целиком одна сторона» допустимо только с указанием, почему вторая сторона не нужна
  (например, «K4 содержит ту же правку в развитом виде, сверено diff»).
- Файлы `.ai/SESSIONS.md`: объединение записей обеих сторон по дате.
- `.ai/SESSION_STATE.md` и `.ai/LESSONS.md` на шагах F1–F7 берутся из HEAD с добавлением
  уникального содержания второй стороны. Уроки с совпавшими номерами получают следующие свободные номера.
  Полная переработка — в F8.
- Генерируемые файлы в таблицу не вносятся, а пересобираются (строка «Генерируемые файлы»).

## Запись сверки без слияния (F4)

```markdown
## F4 — K<id> сверка с K<target>
- Команда: git diff <commit> <target-commit> -- <пути>
- Отличия: <список> → объяснение
- Потерянные строки: нет | есть → вернуть (задача)
- Вердикт: уже содержится | взять частично
```
