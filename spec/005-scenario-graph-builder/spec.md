# 005 — Визуальный конструктор сценариев 112

Статус: **согласовано владельцем 2026-10-20**: ветвление по выбору из объявленных вариантов (`input`), формула результата §4. Остальное (§5–§6) — рабочее предложение, уточняется по ходу этапов.
Опирается на реализованное: версии сценариев и процесс submit → review → publish (`spec/001-ai/contracts/ai-workflow-v1.md`), движок `backend/app/scenario_runtime`, прогоны обучающегося (`/api/v1/ai/scenario-runs/*`).

## 1. Цель и границы

Преподаватель собирает сценарий приёма вызова как граф из блоков (шаги, условия с именованными ветками, завершения), сохраняет версию, отправляет на проверку; уполномоченный эксперт проверяет и публикует; обучающийся проходит назначенную опубликованную версию и получает результат. Опубликованную версию нельзя менять — правка создаёт новую версию, результаты прошлых попыток остаются привязаны к своей версии.

Вне границ: ИИ не управляет переходами (инвариант); граф не заменяет АРМ-112-симулятор (`/arm/*`) и его снимки; редактор живёт в кабинете преподавателя (платформа-обложка, токены `--pf-*`), не в симуляторе. Без внешних библиотек и сети: холст — собственный SVG/HTML.

## 3. Формат `scenario-graph/1` (совместимое расширение — предложение к согласованию)

Версия схемы остаётся `scenario-graph/1`: все новые поля необязательны, существующие графы остаются валидными. Парсер по-прежнему отклоняет неизвестные ключи; список допустимых ключей расширяется только перечисленным ниже.

```jsonc
{
  "schemaVersion": "scenario-graph/1",
  "start": "n1",
  "nodes": [
    { "id": "n1", "type": "action", "title": "Приём вызова",
      "prompt": "Заявитель сообщает о дереве на дороге. Что делаете?",   // текст для обучающегося
      "action": "captureCaller", "label": "Записать данные заявителя",   // код и подпись кнопки
      "sets": { "callerKnown": true },                                   // факты, которые шаг задаёт сам (автор, не студент)
      "next": "n2", "maxVisits": 10 },
    { "id": "n2", "type": "action", "action": "classify", "label": "Определить тип происшествия",
      "input": { "fact": "category", "options": [                        // выбор обучающегося из объявленных вариантов
        { "value": "tree", "label": "Падение дерева" },
        { "value": "fire", "label": "Пожар", "penalty": 20 } ] },
      "next": "n3" },
    { "id": "n3", "type": "condition", "title": "Тип происшествия",
      "branches": [ { "name": "Дерево", "when": { "fact": "category", "op": "eq", "value": "tree" }, "next": "n4" } ],
      "else": { "name": "Иначе", "next": "n5" } },
    { "id": "n4", "type": "end", "outcome": "completed", "score": 100, "passed": true },
    { "id": "n5", "type": "end", "outcome": "wrongCategory", "score": 40, "passed": false }
  ],
  "decoys": [ { "action": "callPolice", "label": "Вызвать полицию" } ],   // лишние кнопки для выбора
  "scoring": { "wrongActionPenalty": 5, "passScore": 60 },
  "layout": { "n1": { "x": 80, "y": 60 } }                                // только для редактора, движок игнорирует
}
```

Ограничения (все проверяются сервером и повторяются в редакторе): `title` ≤ 160, `prompt` ≤ 1000, `label` ≤ 160, `sets` ≤ 16 скалярных фактов, `input.options` 2–12 вариантов с уникальным `value`, `penalty` 0–100, `score` 0–100, `wrongActionPenalty` 0–50, `passScore` 0–100, `decoys` ≤ 20, `layout` — координаты конечные числа в пределах ±10000, только для существующих узлов. Правила графа (`start`, достижимость, `else`, уникальные имена веток, запрет цикла из одних условий, `maxVisits`/`maxSteps`) не меняются.

**Факты прогона.** Начальные: скалярные поля карточки сценария (вложенные — `caller.status`), они заблокированы. Далее факты задают только автор (`sets`) и выбор обучающегося в `input`. Произвольные `facts` в запросе действия отклоняются (сейчас принимаются — меняется, см. §7 риски).

**Выбор действий обучающимся.** Видит `prompt` текущего шага и список кнопок: подписи всех `action`-узлов графа плюс `decoys`, отсортированные по подписи (список не раскрывает порядок). Неверный выбор не меняет прогон, но фиксируется событием `rejected` и штрафует.

## 4. Результат и попытка

Результат считается детерминированно при завершении прогона и сохраняется вместе с попыткой (`ai_scenario_runs.result`):

- `score = clamp(end.score − wrongAttempts × wrongActionPenalty − Σ penalty выбранных вариантов, 0, 100)`;
- `passed = end.passed ∧ score ≥ passScore` (по умолчанию 60);
- прерванный студентом прогон: `score = 0`, `passed = false`, `outcome = abandoned`; остановленный защитой от циклов: `faulted`, 0;
- в результате также: `outcome`, `wrongAttempts`, `steps`, `path` (список id узлов), `branches` (имена выбранных веток), `durationMs`.
Результат неизменяем после записи; ИИ в расчёте не участвует.

## 5. Версии: новая версия из опубликованной

`POST /api/v1/ai/scenarios/{id}/versions/{n}/derive` (автор/администратор; `requestId`): `n` должна быть `approved`; создаётся версия `latest+1` как `draft` (граф, карточка и эталон копируются, `parentVersion = n`). Если последняя версия не `approved` (уже есть черновик/проверка) — `409`. Старая версия, её назначения и результаты не меняются; обучающиеся продолжают проходить назначенную версию `n`, пока преподаватель не назначит новую после публикации.

## 6. Архитектура и интерфейсы

- Редактор — вкладка «Граф» страницы `/teacher/scenarios/[id]` (слайс `src/pages/teacher-scenario-editor`, виджет холста в `widgets/scenario-graph-editor`); данные — через `shared/api` (`ai-client`), без `fetch` в компонентах.
- Холст: блоки (SVG), соединения с подписями веток, палитра блоков, панель свойств, список ошибок (клиентская проверка зеркалит серверную; ошибки сервера показываются как есть). Клавиатурная доступность и состояния loading/empty/error/success обязательны.
- Сохранение: создание (`POST /ai/scenarios` с `graph`) и новая версия (`revise` с `graph`), повторное открытие — `GET .../versions/{n}`; отправка/проверка/публикация/«новая версия» — кнопки по правам.
- Студент: роут `/student/scenarios/[scenarioId]/[version]` (запуск/продолжение прогона из карточки назначенного задания), экран с текстом шага, кнопками, итогом; результаты в `/student/results`.
- Преподаватель: выбор опубликованных версий в мастере заданий; список результатов прогонов по сценарию.
- Автономный режим без бэкенда: пути графового API переводят клиент в «требуется сервер» (как остальные v1 вне `ai/*`), текст понятный, без падений.

## 7. Риски и допущения

- Допущение: подписи и значения `input.options` задаёт автор; корректность методики — на эксперте при `review`.
- Меняется контракт `POST .../actions`: `facts` заменяется на `choice` (`{fact, value}` из объявленных `input.options`); тесты и спека 001 обновляются в этапе 5. API не выпускался, миграции данных нет.
- Редактор не покрывает ветвление по ошибкам оценки ИИ — по инварианту.
- Новые правила в `graph.py` меняют допустимые ключи; старые графы валидны.
