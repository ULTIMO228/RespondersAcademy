# Research — фича 006

## R1. Как закрепить маршрут Cerebras/fp16 в запросе к Polza.ai
- **Decision (T003, 2026-10-20)**: Polza.ai принимает маршрутизацию в `provider: {only: ["cerebras/fp16"], allow_fallbacks: false}`; фактический маршрут в ответе не возвращается. Модель остаётся `qwen/qwen3.8-27b`. Код закрепляет маршрут в каждом запросе, проверка ответа по фактическому маршруту не применяется.
- **Evidence**: официальный пример Polza.ai для OpenAI-совместимого SDK передаёт `extra_body.provider.only` вместе с `allow_fallbacks: False` ([документация/API-пример](https://polza.ai/use-cases/testy-po-urokam), обновлено 2026-10-14); тот же формат показан в [другом официальном API-примере Polza.ai](https://polza.ai/use-cases/obyavleniya-avito). Живой вызов 2026-10-20 с `qwen/qwen3.8-27b` и `cerebras/fp16` успешен; неподдерживаемое имя маршрута вернуло 503 `noProvidersFiltered`, подтверждая применение ограничения. Ответ не содержит поля фактического маршрута.
- **Implementation**: `backend/ml/generate/llm.py` задаёт `CLOUD_ROUTE_PARAMS`, `build_cloud_payload()` и `check_cloud_route()`; `CLOUD_ROUTE_VERIFIED=True` в `backend/app/services/ai_settings_service.py`. Ответный маршрут недоступен для независимого сравнения; гарантия — белый список из одного маршрута без fallback.
- **Alternatives**: имя модели не кодирует маршрут; отказ провайдера при неизвестном имени безопаснее автоматического fallback. T003 снял стопор; повторная сквозная проверка живого выбора и UI остаётся T041.

## R2. Шифрование ключа
- **Decision**: Fernet (`cryptography`, уже транзитивная зависимость), мастер-ключ из `AI_SETTINGS_KEY`, иначе HKDF от `JWT_SECRET` (≥ 32 байт).
- **Rationale**: без новых зависимостей; ключ в дампе БД бесполезен без секрета окружения.
- **Alternatives**: открытое хранение (отвергнуто: FR-004); системный keyring (нет в контейнере/Linux-стенде).
- **Проверено (T001, 2026-10-20)**: `backend/uv.lock` содержит `cryptography` 50.0.1 (транзитивно через `python-jose[cryptography]` из `pyproject.toml`); `uv run python -c "from cryptography.fernet import Fernet; from cryptography.hazmat.primitives.kdf.hkdf import HKDF"` — импорт успешен. Новых зависимостей не добавлено. Реализация — `backend/app/services/ai_secrets.py` (HKDF-SHA256, фиксированная соль, отдельные метки `info` для `AI_SETTINGS_KEY` и `JWT_SECRET`; `AI_SETTINGS_KEY` ≥ 32 байт проверяется в `app/config.py`).

## R3. Откуда состояние здоровья
- **Decision**: каждый исход `complete_json` обновляет таблицу `ai_health`; плюс «Проверить подключение» — явная проба. Опрос без исходящих запросов к модели.
- **Rationale**: баннер не должен сам тратить лимит облака; фактические исходы точнее пинга.
- **Alternatives**: периодический ping провайдера (тратит запросы, ложные срабатывания); только in-memory (теряется при перезапуске и с несколькими воркерами).

## R4. Что делать с локальной моделью 0,8B для текстов отчётов
- **Decision**: использовать для текстов при локальном источнике и как запасной путь, но с валидацией выхода; не прошёл → шаблон с пометкой «шаблон».
- **Rationale**: владелец требует реальную модель; качество 0,8B не гарантировано — честная пометка важнее.
- **Alternatives**: всегда шаблон при локальном (противоречит требованию).

## R5. Дефекты текущего контура, которые надо убрать попутно
Глобальный список событий без привязки к запросу и залипающий `purpose` (`ml/generate/llm.py`, `ai_gateway.py:102`); пояснение карты ошибок не использует локальную модель; сбои без следа в UI. Решаются единым `complete_json` (Design п.4).
