# Implementation Plan: Выбор языковой модели и контроль её использования

**Branch**: работа в `main` (ветка не создавалась) | **Date**: 2026-10-20 | **Spec**: [spec.md](spec.md)

## Summary

Администратор в профиле (`/account/ai`) выбирает источник ИИ — локальная Qwen3.5-0.8B или облачная `qwen/qwen3.8-27b` через Polza.ai с маршрутом `cerebras/fp16` — и вводит ключ. Настройка и зашифрованный ключ хранятся в БД и применяются без перезапуска. Все ИИ-вызовы идут через один слой `complete_json`: облако → при сбое автоматически локальная модель → шаблон, и каждый результат несёт источник (`cloud | local | template`). Состояние здоровья пишется на каждый вызов; баннер показывается администратору (с причиной) и преподавателю (кратко). Тексты отчётов (комментарий попытки, инсайты группы), рекомендации и пояснения карты ошибок генерируются моделью и помечаются источником в UI и выгрузках; вводящие в заблуждение бейджи «ИИ» на детерминированных текстах убираются. Диалог звонящего не затрагивается.

## Technical Context

**Language/Version**: Python 3.11+ (бэкенд), TypeScript strict / Next.js (версию смотреть в `node_modules/next/package.json`; перед фронтом читать `node_modules/next/dist/docs/`)
**Primary Dependencies**: FastAPI, SQLAlchemy 2 async, Pydantic v2, httpx (уже есть); шифрование — `cryptography` (Fernet), приходит транзитивно через `python-jose[cryptography]` (`backend/pyproject.toml:15`; наличие в `uv.lock` проверить в T001); новых зависимостей не добавлять
**Storage**: SQLite (dev) / PostgreSQL; новая миграция `0006_ai_settings` (две таблицы, раздел «Data»)
**Testing**: pytest (unit/contract/integration; сеть только через `httpx.MockTransport`), Vitest + RTL, `scripts/e2e-*.sh`; тесты не обращаются к Polza
**Target Platform**: локальный стенд (macOS/Linux), опционально исходящий HTTPS к `polza.ai` только при выбранном облаке
**Project Type**: web (Next.js фронт + FastAPI бэкенд, FSD)
**Performance Goals**: баннер ≤ 1 мин после первого сбоя/успеха (SC-005); «Проверить» ≤ 15 с (SC-008); опрос здоровья 30–60 с, один лёгкий запрос
**Constraints**: ключ только зашифрованным, никогда в ответах/логах/аудите/выгрузках; модель и маршрут облака — константы кода, не настройки; диалог звонящего (`call_reply`, `call_script`) не менять; синтетические данные; русский интерфейс
**Scale/Scope**: один администраторский контур, ≈ 1 строка настроек, десятки ИИ-вызовов в минуту

## Design

1. **Эффективный источник.** `ai_settings_service.effective()`: строка `ai_settings` (id=1), если есть; иначе значения окружения фичи 004 (`AI_PROVIDER`, `POLZA_API_KEY`) как начальные (FR-016). Кэш процесса с инвалидацией при сохранении и TTL 5 с (на случай нескольких воркеров).
2. **Секрет.** Fernet; мастер-ключ — `AI_SETTINGS_KEY` из окружения, а если не задан — производный от `JWT_SECRET` (HKDF). В БД: `cloud_key_cipher`, `cloud_key_last4`. Расшифровка только внутри `complete_json`; `repr`/логи/аудит ключ не содержат; заменить ключ — старый шифртекст затирается.
3. **Облако фиксировано.** Константы `CLOUD_MODEL="qwen/qwen3.8-27b"`, `CLOUD_ROUTE="cerebras/fp16"`; запрос несёт параметры маршрутизации провайдера **в форме, подтверждённой документацией/реальным вызовом (research R1 — не выдумывать)**, без резервных маршрутов; ответ проверяется на фактический маршрут/модель, расхождение → ошибка `wrong_route`.
3a. **Стопор облака.** `CLOUD_ROUTE_VERIFIED` закрывал выбор `source=cloud` до решения владельца (T002) и подтверждения маршрута (T003). T002 решён, T003 подтверждён; флаг сейчас открыт. После изменения маршрутизации повторно проверить реальное закрепление в T041.
3b. **Надёжность проверки подключения (T044, SC-008).** В `test_ai_connection`:
   - Сессия запроса `db` коммитится/освобождается до вызова `reserve_cloud_call`, чтобы избежать взаимоблокировки транзакций в SQLite (lock contention).
   - В `build_cloud_payload` для пробного пинга разрешается малый `max_tokens` (16–32 токена), устраняя задержку на токены рассуждения (`reasoning_tokens`).
   - Таймаут HTTP-клиента динамически ограничивается остатком `probe_deadline - monotonic()`.
4. **Единый вызов.** `llm.complete_json(purpose, system, user, schema, …) → LlmOutcome(data, source, provider, reason)`: пытается выбранный источник; при облачной ошибке сразу локальная (`llama.cpp`/Ollama из окружения), затем `template`. Исход пишется в `ai_health` и в аудит *тут же, в контексте вызова* (убирает глобальный список событий и залипающий `purpose`).
5. **Здоровье.** `ai_health` (одна строка): `last_ok_at`, `last_error_at`, `last_error_reason`, `errors_today`, `day`, `calls_today`, `probe_calls_today`, `served_by_last`. Состояние: `ok` — последний исход успешный на выбранном источнике; `degraded` — работает запасной путь; `down` — шаблон. Дубликаты сбоев не плодят уведомлений: один баннер со счётчиком.
6. **Тексты отчётов.** Генерация синхронная при построении отчёта, с таймаутом 20 с на текст (FR-019); при превышении — запасной путь и пометка; результат сохраняется. `report_ai_text` готовит запросы только из агрегатов и формулировок правил (без ФИО, как в `explain_stage`), валидирует ответ (язык, длина, отсутствие служебных фрагментов); результат хранится с отчётом вместе с `source`, повторно не генерируется при просмотре. Локальный 0,8B допускается, при непрохождении валидации — `template` с пометкой.
7. **Маркировка.** `AiSourceBadge` (облако / локально / шаблон); детерминированные тексты без модели (оценка, эталон, звонящий, метка «Подтверждено LLM», название «Вариация N (ИИ)») теряют вводящий бейдж либо получают «по правилам». Выгрузки PDF/XLSX несут подпись источника.
8. **Лимиты.** Суточная квота атомарно резервируется в `ai_health.calls_today + probe_calls_today` до HTTP (переживает перезапуск и общая для процессов); расход проб подключений хранится отдельно от обычного usage. Поминутный лимит — в памяти процесса; значения `POLZA_RPM`/`POLZA_DAILY_LIMIT` — из окружения (FR-015).
9. **Баннер.** `AiHealthBanner` в лэйаутах платформы: опрос `GET /api/v1/ai/health` раз в 30 с; admin видит причину и ссылку на `/account/ai`, teacher — «ИИ временно работает в запасном режиме», student — ничего. Без бэкенда (автономный режим) — скрыт.
10. **Аудит.** Новые действия: `ai.settings.change`, `ai.connection_test`; `ai.external_call` расширяется результатами облака/запаса, по-прежнему без текстов и ключа.

## Complexity Tracking

| Нарушение | Зачем | Почему проще нельзя |
|---|---|---|
| Принцип I конституции (внешний API) | Требование владельца: рабочая облачная `qwen/qwen3.8-27b` | Локальная 0,8B не заменяет её качеством; ограничено: по умолчанию выключено, только синтетика, одна модель и маршрут, автоматический возврат на локальную |
| Ключ в БД (решение 004 «не хранить») | Требование: ключ из интерфейса «реально сохраняется» | Окружение не меняется без доступа к серверу и перезапуска |
