# Quickstart — проверка фичи 006

Предусловия: стенд (`./scripts/demo-up.sh`), администратор из сидов; для шагов с облаком — **тестовый** ключ Polza, который вводит владелец (в репозиторий/чат не записывать).

1. **Локальный режим по умолчанию.** Войти админом → `/account/ai`: источник «Локальная Qwen3.5-0.8B», ключа нет, баннера нет.
2. **Неверный ключ.** Выбрать облако, ввести заведомо неверный ключ → «Проверить» → «неверный ключ», «Сохранить» всё равно доступно (стенд может быть без сети), но интерфейс предупреждает; проба введённого (несохранённого) ключа ничего не меняет ни в настройках, ни в состоянии. Проба уже **сохранённого** ключа (поле пустое) при выбранном облаке обновляет карточку «Состояние»: успех → «Работает», сбой → причина и «Только шаблоны».
3. **Рабочий ключ.** Ввести рабочий, «Проверить» → «работает», маршрут `cerebras/fp16`, сохранить; перезапустить бэкенд → настройка и «ключ задан …abcd» на месте.
4. **Реальный вызов.** Сгенерировать сценарий и открыть карту ошибок/отчёт → блоки несут пометку «облако»; в аудите `ai.external_call` без текстов и ключа.
5. **Сбой.** Подменить ключ на неверный (или отключить сеть) → следующий ИИ-запрос идёт на локальную модель, у админа баннер с причиной, у преподавателя краткий баннер; блоки помечены «локально». Остановить и локальную → «шаблон».
6. **Восстановление.** Вернуть ключ → после первого успешного ответа баннер пропадает ≤ 1 мин.
7. **Права и утечки.** teacher/student на `/admin/ai/*` → 403; `grep` ключа по ответам API, аудиту, логам, PDF/XLSX → 0 совпадений.
8. **Не затронуто.** Диалог звонящего работает как до фичи.

Автоматически: `cd backend && uv run pytest -q tests -k "ai_settings or ai_health or complete_json" && uv run ruff check .`; `npm run test -- ai`; `npm run check`; e2e — `backend/scripts/run_frontend_e2e.sh --only ai`.
