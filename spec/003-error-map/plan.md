# План реализации: Карта ошибок — «схема приёма вызова»

**Ветка**: не создана (работа в `main`; коммиты — только по просьбе владельца, AGENTS §12) | **Дата**: 2026-10-19 | **Спека**: [spec.md](spec.md)

**Вход**: спецификация фичи `spec/003-error-map/spec.md`. Каталог — `spec/003-…` (не `specs/`), как требует реестр `spec/README.md` и AGENTS §8.

## Краткое описание

Преподаватель получает «схему приёма вызова»: этапы работы диспетчера со светофором, разбор этапа, карту обучающегося, журнал группы, режим показа, печать в PDF и ИИ-пояснение с вердиктом преподавателя; обучающийся получает блок «Над чем поработать».

Технический подход (обоснование — [research.md](research.md)):

- **Данные**. Агрегация строится по уже сохранённым оценкам попыток (`Evaluation.errors`, из них же состоят аналитика и инсайты группы). У каждой ошибки есть `ruleId`, `type`, `severity`. Соответствие «правило → этап» — статическая таблица в коде бэкенда, покрытая тестом полноты: каждое правило из `ml/assess/rules.py` обязано быть отнесено к этапу или к «Прочее».
- **Бэкенд**. Один новый роутер `/api/v1/error-map/*` и сервис агрегации. Новых таблиц одна — вердикты преподавателя по ИИ-пояснениям; пороги светофора лежат в существующих `SystemSettings` (раздел `errorMap`). Данные об ошибках не дублируются.
- **ИИ-пояснение**. Новый метод шлюза `explain_stage` с необязательной реализацией; по умолчанию и при недоступной модели — шаблонный текст по правилам (`available=false`, пометка «справочное пояснение»). Внешних обращений нет.
- **Фронт**. Новые слайсы по FSD: виджет `error-map` (схема, плитка, разбор, журнал), страницы `teacher/error-map`, виджет `my-focus` для кабинета обучающегося. Графовые библиотеки не нужны: плитки на CSS, пунктир цепочки на SVG. Режим показа и печать: крупная вёрстка и PDF с бэкенда (`reportlab`, шрифт уже локальный).
- **Назначение тренировки**. Кнопка ведёт в существующий мастер `assignment-create` и передаёт подготовленные поля через параметры маршрута (обучающиеся, режим, название); создание задания остаётся за мастером, контракт заданий не меняется.

## Технический контекст

**Язык/версии**: фронт — TypeScript strict, Next.js (`latest`, фактическую версию смотреть в `node_modules/next/package.json`; перед кодом прочитать гайд в `node_modules/next/dist/docs/`) + React; бэкенд — Python 3.11+, FastAPI, SQLAlchemy 2 async, Pydantic v2.

**Зависимости**: новых пакетов нет (фронт — `next`/`react`; бэкенд — уже есть `reportlab`). Перечень в `docs/LIBRARIES.md` не меняется.

**Хранилище**: SQLite для разработки, PostgreSQL 12+ целевая. Одна новая таблица `error_map_verdicts` (миграция Alembic `0005`), пороги — в `SystemSettings.settings["errorMap"]` без миграции схемы.

**Тестирование**: бэкенд — `uv run pytest -q` (+ `ruff`); фронт — Vitest + RTL; контракты — через `scripts/extract_ts_fields.py` и `tests/contract/expected_fields.json`; e2e — HTTP-скрипт `scripts/e2e-teacher.sh` (дополняется) и Playwright-проверка, если доступен Chromium.

**Платформа**: браузеры Chrome / Firefox / Яндекс.Браузер, desktop-first 1920 px и шире; мобильная адаптация вне рамок (AGENTS §7).

**Тип проекта**: веб-приложение (фронт + бэкенд).

**Цели по производительности**: карта группы и журнал готовы к чтению за ≤ 2 с на демо-данных (SC-004); один SQL-проход по оценкам нужных обучающихся за период, без N+1.

**Ограничения**: локальный контур, CPU-only, без внешних API и CDN (конституция I); экраны `/arm/*` не меняются (FR-026, SC-010); русский язык интерфейса; только синтетические данные.

**Масштаб**: до ~100 обучающихся, до 12–25 в группе, 8 этапов на режим, сотни оценённых попыток.

## Фазы реализации (укрупнённо; задачи — в `tasks.md`)

1. **Основание данных**: таблица «правило → этап», тест полноты, схемы, миграция, настройки порогов.
2. **Сервис и API**: агрегация группы/обучающегося, разбор этапа, журнал, «Над чем поработать», права, аудит.
3. **Фронт, ядро (US1 + US2)**: лента этапов, вывод, разбор, переход в мастер назначения.
4. **Обучающийся и журнал (US3, US4, US7)**: карта обучающегося, журнал, блок в кабинете.
5. **Показ и печать (US5)**: режим показа и PDF.
6. **ИИ-пояснение (US6)**: метод шлюза, шаблонный фолбэк, вердикты, аудит.
7. **Доступность, проверка удобства, сдача**: тесты доступности, прогон на 2–3 преподавателях, обновление `docs/COMPLIANCE.md`, `docs/FINAL-GATE.md`, реестра `spec/README.md`.
