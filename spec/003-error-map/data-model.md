# Модель данных (Phase 1): Карта ошибок

Новых сущностей хранения две: вердикт преподавателя и раздел настроек. Остальное вычисляется из существующих данных и не сохраняется. JSON-поля — camelCase, идентификаторы режима `operator112 | dds` (конституция V).

## 1. Вычисляемые сущности (в ответах API, в БД не хранятся)

### Stage — этап схемы
| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Стабильный код этапа: `intake`, `address`, … (см. §3) |
| `order` | int | Порядковый номер в ленте |
| `title` | string | Название на экране, рабочий термин |
| `mode` | `operator112 \| dds` | Режим, которому принадлежит этап |
| `articleId` | string \| null | Статья справочника по теме (если есть и существует в справочнике) |

### StageLevel — уровень этапа
| Поле | Тип | Описание |
|---|---|---|
| `stageId` | string | Ссылка на этап |
| `attempts` | int | Учтённых попыток (общий знаменатель) |
| `attemptsWithError` | int | Попыток с ≥1 ошибкой на этапе |
| `share` | number 0..1 | `attemptsWithError / attempts`; для серой плитки — `null` |
| `level` | `rare \| sometimes \| often \| noData` | Слова: «редко», «иногда», «часто», «мало данных» |
| `comparison` | `better \| same \| worse \| null` | Только для карты обучающегося: «лучше / как у группы / хуже группы» |
| `affectedStudents` | int | Сколько обучающихся допустили ошибку на этапе |

Уровень определяется порогами: `rare` — доля < `sometimesFrom` (0,10); `sometimes` — от 0,10 до `oftenFrom` включительно (0,30); `often` — > 0,30. Если `attempts` < `minAttempts` — `noData`. Границы включительности зафиксировать в тесте на эталонном наборе (SC-005).

### TypicalError — типовая ошибка этапа
| Поле | Тип | Описание |
|---|---|---|
| `ruleId` | string | Правило оценщика (`a3`, `d1`, `op-f1`, …) |
| `plainText` | string | Формулировка простыми словами (из справочника в коде) |
| `severity` | `critical \| major \| minor` | Для сортировки внутри этапа |
| `studentCount` | int | Сколько обучающихся допустили |
| `students` | `{id, name}[]` | Кто допустил (после проверки прав) |
| `exampleAttemptId` | string \| null | Одна реальная попытка-пример |
| `exampleSessionId` | string \| null | Занятие попытки, чтобы построить ссылку на отчёт |

В разборе показывается не более трёх типовых ошибок, отсортированных по `studentCount` ↓, затем по тяжести.

### Headline — вывод
| Поле | Тип | Описание |
|---|---|---|
| `kind` | `problems \| clean \| noData` | |
| `stageIds` | string[] | ≤ 3 самых проблемных этапа; только `often`, а при их отсутствии — пусто |
| `text` | string | Готовая фраза, например «Главная проблема группы: …» / «Критичных проблем нет» |

Сортировка этапов в выводе: по `share` ↓, при равенстве — по `order`.

### ChainLink — причинная связь
| Поле | Тип | Описание |
|---|---|---|
| `from` / `to` | string | Этапы (`from` раньше `to` по порядку) |
| `caption` | string | Подпись словами, например «Неверный тип → не те службы» |

### FocusItem — «Над чем поработать»
`stageId`, `title`, `hint` (нейтральная формулировка, без оценок), `articleId | null`. Ровно до трёх штук, по доле ошибок обучающегося; без данных группы и других людей.

## 2. Сохраняемые сущности

### ErrorMapVerdict — вердикт по ИИ-пояснению (новая таблица `error_map_verdicts`)
| Колонка | Тип | Описание |
|---|---|---|
| `id` | string(32), PK | `emv-NNN` по общему правилу идентификаторов (`app/db/ids.py`) |
| `teacher_id` | string(16), index | Автор вердикта |
| `group_id` | string(64), index | Группа, для которой построена карта |
| `student_id` | string(16), NOT NULL, по умолчанию `''` | Пустая строка — вердикт по карте группы; иначе id обучающегося. NULL недопустим: в SQLite и PostgreSQL NULL в уникальном индексе считаются разными, и уникальность не сработала бы |
| `mode` | string(16) | `operator112 \| dds` (CHECK) |
| `stage_id` | string(32) | Этап |
| `period` | string(8) | `2w \| 1m \| all` |
| `source` | string(12) | `ai \| template` — чьё пояснение оценивалось |
| `text_hash` | string(64) | Хэш показанного текста — вердикт относится к конкретному тексту |
| `verdict` | string(8) | `agree \| disagree` (CHECK) |
| `created_at` | string(32) | ISO-время |

Уникальность (все колонки NOT NULL): одна актуальная запись на `(teacher_id, group_id, student_id, mode, stage_id, text_hash)`; повторный выбор обновляет вердикт (прежнее значение остаётся в аудите). Миграция — `0005_error_map_verdicts`, `--reset` сида после правки моделей (AGENTS §3).

Каждый вердикт и изменение порогов записывается в журнал аудита (`audit.record`): действия `error_map.verdict`, `error_map.settings`. Задание из карты ошибок пишет существующее `assignment.create` (отдельного действия нет, см. D10 в `research.md`).

### Настройки (без новой таблицы): `SystemSettings.settings["errorMap"]`
```json
{
  "sometimesFrom": 0.10,
  "oftenFrom": 0.30,
  "minAttemptsGroup": 5,
  "minAttemptsStudent": 3,
  "sameBandPoints": 10
}
```
Значения — черновик, меняются администратором; проверка: `0 < sometimesFrom < oftenFrom < 1`, `sameBandPoints` 0–50, минимумы ≥ 1. Отсутствующий раздел заменяется значениями по умолчанию.

## 3. Статические справочники (код бэкенда, `services/error_map_stages.py`)

Таблицы — **черновик, требуют сверки с экспертом по обучению (D1)**. Правила — реальные идентификаторы из `backend/ml/assess/rules.py`. Автотест полноты проверяет, что каждое правило оценщика встречается ровно в одной строке или явно в «Прочее».

### Режим `dds` (ДДС)
| № | `id` этапа | Название | Правила |
|---|---|---|---|
| 1 | `intake` | Приём вызова | `t1` |
| 2 | `address` | Адрес | `a1`, `a2`, `a3`, `a4` |
| 3 | `decision` | Тип происшествия | `v2`, `v2t`, `d4`, `tr1` |
| 4 | `card` | Карточка | `f1`, `g1`, `c1`, `c2` |
| 5 | `services` | Службы | `d1` |
| 6 | `route` | Маршрут | `d2`, `d3` |
| 7 | `statuses` | Статусы реагирования | `v1`, `v3`, `v4`, `v5`, `v6`, `v6b`, `v6c`, `v6l`, `v7`, `s1`, `s2`, `s3` |
| 8 | `closing` | Закрытие | `t2`, `t3` |
| — | `other` | Прочее | `x1`, `m1` и любые не отнесённые |

### Режим `operator112` (специалист-112)
| № | `id` этапа | Название | Правила |
|---|---|---|---|
| 1 | `intake` | Приём вызова | `op-t0`, `op-t1` |
| 2 | `applicant` | Заявитель | `op-a1`, `op-a2`, `op-a3`, `op-a4` |
| 3 | `place` | Место | `op-a5`, `a1`, `a2`, `a3` (адресные правила оценщика, решение D8) |
| 4 | `essence` | Суть происшествия | `op-d0`, `op-d1` |
| 5 | `type` | Тип по классификатору | `op-f0`, `op-f1` |
| 6 | `signs` | Признаки и флаги | `op-s1`, `op-s2`, `op-s3` |
| 7 | `services` | Оповещение служб | `op-f2` |
| 8 | `closing` | Завершение | `op-t2`, `op-t3` |
| — | `other` | Прочее | `g1`, `f1`, `c1` и прочие без `op-` соответствия |

Отличие от спеки: для `operator112` спека называла 6 рабочих этапов, план уточняет до 8 по фактическим правилам (добавлены «Заявитель», «Признаки и флаги», «Оповещение служб»). Если эксперт сохранит исходные 6, смена затрагивает только эту таблицу.

### Причинные связи (черновик)
`dds`: `decision → services` («Неверный тип → не те службы»), `decision → route`, `address → route`, `services → statuses`, `statuses → closing`.
`operator112`: `essence → type`, `type → signs`, `type → services`, `place → services`.

### Простые формулировки
Для каждого `ruleId` в коде — короткая фраза без жаргона (например, `a3` → «Адрес не совпадает с тем, что в билете»). Источник правила (`Rule.source`) остаётся в данных для проверки преподавателем, но на карте не выводится. Тест: у каждого правила есть `plainText` не длиннее 90 символов.

### Статьи справочника
Соответствие этап → `articleId` — необязательное; тест проверяет существование id в сиде справочника.

## 4. Связи между сущностями

- `Stage` ←1:N→ `StageLevel` (по одному на запрос: группа/обучающийся × период × режим).
- `Stage` ←1:N→ `TypicalError` через `ruleId`.
- `ErrorMapVerdict` ссылается на `(group, student или '', mode, stage, period, textHash)`; обращений по внешним ключам к таблицам нет, как и у соседних AI-таблиц.
- Источники для расчёта: `Attempt` (режим, студент), `Evaluation.errors` (правила), `User.group` (группа), `User.assigned_groups` / `Assignment.teacher_id` / `TrainingSession.teacher_id` (права).

## 5. Переходы состояний

Только у вердикта: «нет вердикта» → `agree` или `disagree`; повторный клик меняет значение. Остальные сущности вычисляются на лету.

## 6. Правила проверки (из требований)

| Требование | Проверка |
|---|---|
| FR-003 | Одна попытка считается на этапе один раз при нескольких ошибках |
| FR-005/006 | В выводе ≤ 3 этапов; серые этапы не попадают в вывод |
| FR-007 | Ошибки без соответствия — в `other` |
| FR-012 | Сравнение показывается только при достаточных данных |
| FR-017 | `verdict` ∈ {`agree`, `disagree`}; запись в аудит |
| FR-020 | В ответе для обучающегося нет полей группы и имён других людей |
| FR-028 | Доступ преподавателя только к своим группам |
