## Бесплатный режим, согласованный пользователем

Пользователь передал доступ Groq и выбрал бесплатный тест. `LIVE_CALL_REALTIME_TRANSPORT=cascade`: существующий PCM WebSocket → непрерывный локальный Vosk → потоковый Chat Completions Qwen3.8-27B в Groq → локальный Silero короткими фрагментами → PCM24 кГц. Ключ хранится только в игнорируемом backend/.env. Вход/выход не записываются в файлы. ИИ начинает разговор сам сгенерированной репликой по билету; заготовленной вводной записи нет. Речь непрерывно принимается во время генерации и озвучки. Детекция начала речи отменяет генерацию и очищает звук браузера; поздний результат TTS не звучит и не попадает в историю. Нужна серверная детекция конца реплики: это составной голосовой конвейер с задержкой распознавания и синтеза, а не нулевая задержка/native speech-to-speech.

Первый запуск использует опубликованные веса Qwen3.8-27B через Groq; затем API можно направить на локальное размещение тех же весов. Голосовые модели остаются локальными. Облачный GPU не требуется; квоты и реальная задержка проверяются при испытании. Прежний SGLang-Omni режим сохраняется как отдельный вариант `omni`.

Пользователь отклонил WAV-прототип: нужен непрерывный голосовой разговор в гарнитуре, с перебиванием. Выбран открытый Qwen/Qwen3-Omni-30B-A3B-Instruct (Apache-2.0, русский вход/выход) за SGLang-Omni `/v1/realtime`. Облачный GPU и локальный GPU используют один сервер и веса. Доступ к GPU пока не предоставлен; качество и задержка не проверены.

## Контракт и жизненный цикл

- POST `/api/v1/operator112/attempts/{id}/realtime`: авторизованный владелец активной отвеченной тренировочной попытки получает одноразовый билет на WS (30 секунд), без промпта, фактов и ключа модели. URL внешнего WS приложения задаётся серверным `LIVE_CALL_PUBLIC_WS_URL` (полный путь `/api/v1/operator112/realtime`). Отсутствующая конфигурация → 503 до запроса микрофона.
- WS принимает билет первым сообщением (не URL/логи); сверяет Origin с Origin POST, повторно проверяет сессию, владельца и состояние. Один разговор на попытку, один backend worker. Резервирование билетов ограничено, просроченные удаляются. Для нескольких worker нужен общий ticket/lease store.
- Микрофон непрерывно отправляет PCM16 16 кГц; никаких WAV, клиентской VAD и кнопок реплик. Сервер модели определяет завершение высказывания. `semantic_vad` используется только при объявленной поддержке; иначе `server_vad`.
- Backend сам устанавливает инструкции и факты билета; клиент может передавать только PCM, truncate и finish. PCM24 кГц ответа проигрывается по чанкам через Web Audio. При speech_started клиент останавливает буфер, отбрасывает поздний звук отменённого ответа и сообщает реально прослушанную длительность.
- Сервер закрывает разговор по лимиту времени, отзыву доступа/завершению попытки, отключению браузера и ошибке провайдера. Звук и ключи не сохраняются; завершённые транскрипты сохраняются в Attempt.calls, kind=realtimeCaller. Прерванный ответ не записывается как завершённый.
- Секрет модели только на backend. Прямой доступ к серверу модели закрыт сетью/SSH/VPN, либо защищён шлюзом. Браузер знает только WS нашего приложения. Нет автоматического отката на записи или WAV.

## Приёмка

Регрессии: одноразовый/истёкший билет, чужой Origin/пользователь, закрытая попытка, запрет session.update от браузера, корректный PCM, таймаут/cleanup; потоковое воспроизведение, перебивание до response.created, поздние чанки и освобождение микрофона. Реальная приёмка требует GPU endpoint: диалог на русском, адрес/контакты без подмены, короткие паузы внутри фразы, перебивание, 3 минуты, повтор после обрыва. Тестовый WS не доказывает качество модели.

Источники: [модель](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Instruct), [протокол SGLang-Omni](https://sgl-project.github.io/sglang-omni/basic_usage/qwen3_omni.html#realtime-speech-with-server-side-turn-detection).
