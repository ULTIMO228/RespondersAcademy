# Implementation Plan: АРМ специалиста-112 один в один (рабочее место обучающегося-112)

**Branch**: `SASHA` (отдельная ветка фичи не создавалась) | **Date**: 2026-10-20 | **Spec**: [spec.md](spec.md)
**Input**: `spec/009-arm-112-student/spec.md`; уточняет `spec/007-arm-one-to-one/spec.md` для роли «специалист-112»

## Summary

Экран `/arm/operator112` перестаёт быть отдельной формой и становится рабочим местом специалиста-112, как в настоящем АРМ. Ученик видит журнал с шапкой специалиста, поверх него приходит окно входящего вызова или SMS. После «Принять» открывается карточка ПОВ-112 в режиме заполнения: полоса телефонии, таймер, заявитель, полный адрес, «что случилось?» с вкладками и чипами, оранжевая панель служб с «Добавьте службы» и «сохранить». К этому добавляются связи карточек с оценкой привязки, история SMS, блокировка, напоминание, «Сообщить о проблеме» и локальная карта. Учебное остаётся только в полосе тренажёра. Контракт меняется только аддитивно, оценщик читает прежние поля, поэтому баллы 112 до и после совпадают (SC-004).

**Область (решение владельца 2026-10-20)**: делается только обучающийся-112. Экраны ДДС, вход и общая часть 007 сюда не входят. **Код ДДС не меняется**: профиль и АРМ ДДС делает другой участник, поэтому 112 строится в своих слайсах без правок `widgets/incident-card`, `widgets/incident-list`, `widgets/service-panel`, `pages/incident`, `pages/journal`, `pages/phone`. **Голосовой диалог** (007 FR-031…FR-034) делает отдельный участник позже. Здесь остаётся только точка подключения `useApplicantVoice`, а звук заявителя работает как сейчас — по записи билета (research R6).

## Technical Context

**Language/Version**: TypeScript strict / Next.js App Router (версию смотреть в `node_modules/next/package.json`; перед кодом читать `node_modules/next/dist/docs/`); Python 3.11 (FastAPI, SQLAlchemy 2 async, Alembic)
**Primary Dependencies**: существующие; новых нет
**Storage**: SQLite (dev/demo), PostgreSQL 12+ (целевая); миграция Alembic `0007_problem_reports`; вложения — `backend/var/uploads/problem-reports/`
**Testing**: vitest + RTL (рядом с кодом), pytest (unit / integration / contract `expected_fields.json`), Playwright `e2e/arm-112-visual.spec.ts` (1920×1080), ручной `quickstart.md`
**Target Platform**: локальный контур, офисный ПК без GPU, Chrome / Firefox / Яндекс.Браузер, desktop 1920px+
**Project Type**: web application (фронт + бэкенд в одном репозитории, FSD на фронте)
**Performance Goals**: окно вызова и смена вида — без заметной задержки (< 100 мс на клиенте); журнал — один запрос на открытие и обновление по событиям попытки
**Constraints**: аутентичность 1:1 (AGENTS §9, FR-001); учебное — только в полосе тренажёра; без внешних сетей (карта, шрифты — локальные); токены `--pf-*` в симулятор не импортируются (`simulatorBoundary.test.ts`); старые попытки читаются без миграции данных
**Scale/Scope**: 14 окон «входит»; ~4 новых фичи/виджета на фронте, 1 переписанный слайс страницы; 3 новых эндпоинта + 2 у преподавателя; 1 миграция; 1 новый компонент оценки (`links`)

## Расхождения без референса (FR-001: перечислить в плане)

| Место | Решение | Почему |
|---|---|---|
| Порог красного таймера | 60 с | в памятке и сверке нет; референсы: тёмный на 00:09, красный на 01:23 (R7) |
| «×» окна входящего вызова | вызов остаётся в очереди, ответ засчитывается с задержкой | референса поведения нет; допущение спеки (R5) |
| Закрытие карточки «×» до сохранения | подтверждение «Закрыть карточку без сохранения?» · «закрыть» / «отмена» в стиле окна ИНСТРУКЦИЯ_94 | референса нет (Edge Cases) |
| «создать новую карточку» вне вызова | пустая карточка без телефонии, не в оценке | FR-008 |
| «Краткая инструкция» | короткая памятка по сочетаниям клавиш и окнам из справочника 016 | содержимого на референсе нет |
| Окно карты | локальная схема-плитка, слои неактивны | конституция I (R10) |
| Голос | живой ИИ-заявитель (014-live-caller) в тренировке и экзамене; запись — только при выключенном флаге | решение владельца 2026-10-20 (R6) |

## Фазы реализации (для /speckit-tasks)

Порядок — по приоритетам историй (конституция IV). После каждой фазы: `npm run check`, `npm run test`, `uv run pytest -q`, `uv run ruff check .`, отдельный коммит.

0. **Подготовка**: зелёная база тестов (`baseline.txt`), `affected-tests.md` (тесты старой формы и софтфона), чек-лист `checklists/visual-112.md`.
1. **Основа (блокирует всё)**: аддитивный контракт (TS + Pydantic + `expected_fields.json`), новые типы событий, расширение билетов в моках с валидатором, `GET /operator112/journal`, состояние вида в `useOperator112`, `CARD_TIMER_RED_SEC`, `useApplicantVoice` поверх текущего проигрывателя.
2. **US1 журнал** (P1): `widgets/operator112-journal`, меню неактивно, тумблеры, колонки FR-006, только свои и фоновые карточки (FR-007).
3. **US2 входящее** (P1): окна вызова и SMS, очередь после «×», «Принять» → карточка, `document.title`.
4. **US3 карточка** (P1): `widgets/operator112-card`, полный адрес и окно карты, «что случилось?» с вкладками и чипами, «нет контакта» / «срыв звонка», таймер.
5. **US4 службы и сохранение** (P1): оранжевая панель, «Добавьте службы», подтверждение оповещения, результат. **MVP = фазы 1–5**: после неё старая форма и софтфон удаляются (R12), а SC-004 сверяется.
6. **US5 связи** (P2): `/matches`, окна совпадения и «Показ связей», события `link*`, компонент оценки `links`, билеты с `repeatOf`.
7. **US6 служебные окна** (P3): «История сообщений», блокировка, напоминание (перенос `useReminders`), «Сообщить о проблеме» (миграция 0007, эндпоинты, блок у преподавателя).
8. **Полировка**: клавиатура и `aria-label` (FR-032), снимки `e2e/arm-112-visual.spec.ts`, сверка по чек-листу, старые попытки (FR-033), обновление `spec/README.md`, `AGENTS.md` §3 (роуты и слайсы), `.ai/`.

## Риски

- **Объём фазы 4** (карточка) — самая крупная. Её дробим на задачи по блокам КАРТОЧКА_1 и закрываем по одному блоку со снимком.
- **SC-004**: эталонных прогонов 112 может не быть. Тогда записываем «не проверено», не выдумываем (как 018 T039).
- **Новые билеты** (SMS, повторный звонок) — синтетика: тексты и пары карточек согласует владелец до фазы 3/6.
- **Сброс БД** для новых полей билетов и миграции 0007 — только по просьбе владельца (`app.seed.load --reset`).
- **Стык с голосом**: второй участник подключается через `useApplicantVoice`. Если ему нужен другой интерфейс (поток событий распознавания), хук меняется в одном месте.
