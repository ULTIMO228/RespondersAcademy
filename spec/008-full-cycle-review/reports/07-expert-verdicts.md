## 2. Экспертные заключения по ключевым направлениям

### Заключение 1: Соответствие нормативной базе Системы-112 Москвы
- **Позитивные аспекты**:
  - Высокая аутентичность структуры полей опросного листа (УЧОЛ) и карточки информационного обмена (УКИО);
  - Корректная реализация дерева признаков классификатора ЕКП (118 групп);
  - Строгое соблюдение московского жизненного цикла статусов реагирования ДДС (`accepted`, `notAccepted`, `responseStarted`, `arrived`, `workInProgress`, `workDone`, `workRefused`).
- **Критические несоответствия**:
  - Рассинхронизация адресной подсказки с формой ввода (DEF-05);
  - Отсутствие отраслевого ограничения 100 символов для службы 03 (DEF-06);
  - Отсутствие глобальных хоткеев в окне оператора 112 (DEF-08).

### Заключение 2: Архитектурная целостность и сквозные сценарии
- Выявлен блокирующий архитектурный дефект валидатора сценариев (DEF-03): валидация адреса по жесткому списку из 14 фикстур делает невозможным прохождение сквозного сценария 112 → ДДС при живом вводе улицы из 4000 адресов Москвы.
- Выявлен разрыв между новой платформой заданий и эмулятором АРМ (DEF-04): создание сессий с `scenario_ids=[]` скрывает модули из интерфейса курсанта.

### Заключение 3: Информационная безопасность и RBAC
- В слое `backend/app/api/compat` допущена опасная ошибка: проверка `if viewer is not None and viewer.is_student` оставляет анонимных пользователей (`viewer is None`) с суперпользовательскими правами, позволяя подделывать оценки и читать данные пользователей.

## 3. Пошаговый план устранения дефектов (Remediation Roadmap)

### Фаза 1: Устранение критических уязвимостей безопасности (P0)
1. В `backend/app/api/compat/attempts.py`, `sessions.py`, `card_actions.py`, `users.py`:
   - Заменить `viewer: Viewer | None = Depends(get_viewer)` на строгую зависимость `viewer: Viewer = Depends(require_viewer)`;
   - В `evaluation_service.py:_read_teacher`: запретить вызов без сессии и удостовериться, что преподаватель может действовать только от собственного имени (`viewer.user_id == teacher_id` или `viewer.role == "admin"`).
2. В `backend/app/api/compat/users.py`:
   - Требовать сессию преподавателя или администратора (`require_role("teacher", "admin")`).

### Фаза 2: Восстановление работоспособности сквозных сценариев (P0)
1. В `backend/app/services/assignment_service.py:254`:
   - Заполнять `scenario_ids` сессии списком идентификаторов сценариев из `AssignmentScenarioVersion` / `card_ids`.
2. В `backend/ml/generate/validator.py`:
   - При валидации карточек, созданных студентом (`student_card`), сверять адрес не с ограниченным allowlist (14 адресов), а с полным справочником улиц Москвы (`address_match.exact`), предотвращая 409 Conflict.

### Фаза 3: Устранение 11 тестов бэкенда (P1)
1. В `ErrorMapExplanation` согласовать схему: добавить алиас `sourceKind` и свойство `source_kind` для совместимости с TS и тестами.

3. В `test_report_builder_ai.py`: скорректировать проверку префикса (`"Сводка по правилам"`).
4. В датасете: обновить хэши в `manifest.json`.

### Фаза 4: Доработка доменной аутентичности UI (P2)
1. В `Operator112Workspace.tsx`:

   - Добавить класс превышения норматива на контейнер `.work__bar`.
2. В `backend/app/services/operator112_service.py:51`:
   - Синхронизировать текст подсказки с реальными полями ввода адреса.
