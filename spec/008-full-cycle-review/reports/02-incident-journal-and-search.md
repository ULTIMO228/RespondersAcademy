## 1. Сверка структуры таблицы журнала

### 1.1 Нормативный перечень колонок
По руководству АО «Искра Технологии» (2024, стр. 18–22) и московской памятке (`ФРОНТ-АРМ-112-ЕДИНЫЙ-ДОКУМЕНТ.md:43`):
Таблица журнала содержит колонки:
1. `Шеврон раскрытия` (служебная)
2. `Связи` (число связанных карточек / цепочка)
3. `Важное / Напоминание / Закладка` (иконки индикации)
4. `ЧС` (признак ЧС)
5. `Опер.` (оператор 112)
6. `АРМ` (номер рабочего места)
7. `Номер` (номер карточки происшествия)
8. `Дата` (дата регистрации ДД.ММ.ГГГГ)
9. `Время` (время регистрации ЧЧ:ММ:СС)
10. `Тип происшествия` (наименование из классификатора)
11. `Постр.` (число пострадавших / признак наличия)
12. `Адрес` (формализованный / краткий адрес происшествия)
13. `Статус службы` (статус реагирования дежурной службы)
14. `Действие / Отработка` (кнопка перехода к отработке)

## 2. Анализ функционала поиска и фильтрации

### 2.1 Форма расширенного поиска (`AdvancedSearch.tsx`)
Форма содержит 17 параметров согласно памятке (стр. 35–40):
- Текстовые поля: `incidentType`, `address`, `raion`, `descriptiveAddress`, `region`, `description`, `applicant`, `operator`, `cardNumber`.
- Мультивыбор: `signs` (признаки из дерева), `arms` (номера АРМ), `okrugs` (округа), `services` (службы), `channels` (каналы), `sources` (источники), `cardStatuses` (статусы).
- Диапазон дат: `createdFrom`, `createdTo`.

### 2.2 Выявленные расхождения и дефекты
1. **Отсутствие серверных фильтров по флагам «ЧС» и «Пострадавшие»**:
   - В UI таблицы выведены колонки «ЧС» и «Постр.».
   - В `backend/app/services/cards_query.py:23-24` в списках `SCALAR_FILTER_KEYS` и `LIST_FILTER_KEYS` отсутствуют ключи `chs`, `emergency`, `hasCasualties`, `injured`.
   - Если диспетчеру ДДС необходимо отфильтровать только карточки с ЧС или только с пострадавшими, бэкенд `GET /cards` не предоставляет такого параметра фильтрации.
2. **Сортировка только по дате**:
   - В `IncidentTable.tsx:27` константа `SORT_COLUMN = "Дата"`.
   - Клики по другим заголовкам колонок («Номер», «Время», «АРМ», «Статус службы») не меняют поле сортировки и не передают параметр `sortBy` в API. В реальном АРМ-112 клик по заголовку любой колонки сортирует выборку по возрастанию/убыванию.
3. **Раскрытие описания под строкой**:
   - По памятке: клик по строке раскрывает блок «Описание: дата, АРМ, оператор, текст».
   - В реализации `IncidentRow.tsx` раскрытие работает корректно, однако предпросмотр аудиозаписей звонка из строки журнала не поддержан (доступен только при переходе в карточку).

## 3. Независимый вердикт эксперта
- **Статус**: 🟡 **Средний дефект (неполнота фильтрации API)**.
- Базовый функционал отображения ленты, постраничной пагинации (по 10 записей) и раскрытия строк выполнен качественно.
- Для соответствия стандарту АРМ-112 требуется расширить `cards_query.py` параметрами фильтрации `isEmergency` (ЧС) и `hasCasualties` (пострадавшие).
