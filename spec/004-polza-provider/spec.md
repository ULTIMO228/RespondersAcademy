# Фича 004 — Внешний провайдер моделей Polza.ai (опционально, по умолчанию выключен)

Статус: **реализовано T001–T006 (2026-10-19)**, поправка инварианта AGENTS.md §2 согласована владельцем; решения: внешней модели отдаются только генерация сценариев и пояснение карты ошибок, экрана администратора нет (есть API статуса). **T007 (проверка с реальным ключом) не выполнена.**

## 1. Зачем и что вне рамок

Дать ИИ-функциям (генерация сценариев, разбор спорных случаев, ответы заявителя, пояснение в карте ошибок) второй источник ответов — облачный OpenAI-совместимый API [Polza.ai](https://polza.ai/docs) (`https://polza.ai/api/v1`, модель задаётся строкой вида `openai/gpt-4o`, ключ в заголовке `Authorization: Bearer`). Локальные модели остаются основным и умолчательным путём.

Вне рамок: оценка попыток обучающихся внешней моделью (остаётся локальной), хранение ключей в БД в открытом виде, выбор других провайдеров (контур делается так, чтобы второй провайдер добавлялся конфигурацией), экран администратора для редактирования ключа (v1 — переменные окружения; экран — отдельная фича).

## 2. Инвариант и решение, которое нужно принять

AGENTS.md §2 запрещает внешние API в рантайме. Предлагаемая поправка (требует явного «да» владельца): **внешний провайдер допускается только как выключенная по умолчанию опция, включаемая администратором развёртывания переменными окружения; без `POLZA_API_KEY` поведение и сеть не меняются**. Учебные данные наружу не уходят без обезличивания: в запрос попадают только синтетические сценарии/ошибки (персональных данных в системе нет, §2), но владелец должен подтвердить, что отправка синтетических текстов третьему лицу допустима для хакатона/заказчика.

## 3. Требования

- **FR-1** Провайдер выбирается переменной `AI_PROVIDER` = `local` (умолчание) | `polza`. При `local` внешних запросов нет вообще.
- **FR-2** Настройки: `POLZA_API_KEY` (SecretStr, не логируется и не отдаётся в API), `POLZA_BASE_URL` (умолч. `https://polza.ai/api/v1`), `POLZA_MODEL`, `POLZA_TIMEOUT_SEC`. `polza` без ключа → понятная ошибка запуска/статуса, не молчаливое переключение.
- **FR-3** Единый клиент `OpenAiCompatClient` (расширение `ml/generate/llm.py`: сейчас `OllamaClient(openai=True)` ходит на `/v1/chat/completions` без авторизации): добавляются `Authorization`, путь `/chat/completions` относительно base URL, `response_format` JSON-схемы с проверкой ответа, ограничение `max_tokens`.
- **FR-4** Любая ошибка (сеть, 401/402/429/5xx, таймаут, невалидный JSON) → `None`, и работает существующий детерминированный/шаблонный фолбэк. Ошибки провайдера не приводят к 500 у пользователя.
- **FR-5** Ответы внешней модели помечаются в интерфейсе так же, как локальные (бейдж «ИИ»); источник в метаданных: `provider: polza:<модель>`. Итоговая оценка по-прежнему за преподавателем (Q&A в3).
- **FR-6** Журнал аудита: действие `ai.external_call` — функция, провайдер/модель, размер запроса, результат (ok/ошибка). Тела запросов и ответов и ключ в аудит не пишутся.
- **FR-7** Защита расходов: лимит запросов в минуту и суточный лимит (`POLZA_RPM`, `POLZA_DAILY_LIMIT`); превышение → фолбэк. Баланс/лимит ключа читается из Polza (`/other/key`) для статуса, но не блокирует работу.
- **FR-8** Статус провайдера для администратора: `GET /api/v1/admin/ai/provider` → `{provider, model, configured, reachable, lastError?}` без ключа; проверка достижимости — по запросу, не на каждый вызов.
- **FR-9** Тесты не ходят в сеть: клиент покрыт подменой `httpx` (MockTransport); сквозная проверка с настоящим ключом — ручная, отдельной командой.
- **FR-10** Документация: `backend/.env.example`, `backend/README.md`, `docs/offline-check.md` (раздел «внешний провайдер: опция»), поправка §2 в AGENTS.md после согласования.

## 4. Архитектура

```
AiGateway (app/ai_gateway.py)  ← подмена set_gateway() сохраняется
   └─ LocalAiGateway ── ml.generate.llm.configured_client()
                              ├─ AI_PROVIDER=local → OllamaClient (llama/ollama), как сейчас
                              └─ AI_PROVIDER=polza → OpenAiCompatClient(base_url, key, model)  ← новое
```

Точка выбора одна — `configured_client()`; вызывающий код (генерация сценариев `ai_scenario_service`, `explain_stage`, разбор споров) не меняется. Рейт-лимит и аудит живут в обёртке `ExternalCallGuard` вокруг клиента.

## 5. Роли и права

Ключ и провайдер задаёт администратор развёртывания (окружение). Статус — только роль `admin`. Преподаватель/обучающийся видят лишь бейдж «ИИ». Ключ никогда не попадает во фронт.

## 6. Критерии приёмки

1. С пустым `POLZA_API_KEY` и `AI_PROVIDER=local` — ни одного исходящего запроса (тест с запретом сети), все прежние тесты зелёные.
2. С подменённым транспортом: корректный ответ → результат с `provider: polza:…`; 401/429/таймаут/мусор → фолбэк и запись в аудит со статусом ошибки.
3. Ключ не встречается в логах, ответах API и аудите (тест-утечка).
4. Превышение лимита запросов → фолбэк без вызова сети.
5. Ручная проверка: с реальным ключом генерация сценария через Polza возвращает валидный сценарий (результат записывается в `quickstart.md`).
