# spec/ — реестр фич

Каждая фича — отдельная папка `NNN-короткое-имя/`. Номер сквозной, выдаётся по порядку
постановки фичи; новая фича получает следующий свободный номер. Состав пакета внутри папки —
по образцу `000-фронт/`: обзор, карта требований, роли, архитектура, спеки страниц,
модели данных, пользовательские потоки, дизайн-правила, решения Q&A, глоссарий,
правила кода, план реализации, задачи, мок-данные.

| Папка | Фича | Статус |
|---|---|---|
| [`000-фронт/`](000-фронт/README.md) | Тестовый фронтенд тренажёра оператора ДДС: эмулятор АРМ-112 на мок-данных, 3 роли (обучающийся / преподаватель / администратор), мок-API `/api/mock/*` | ✅ Завершена (волны 0–5, 283 задачи — `000-фронт/12-tasks.md`; доказательства сдачи — `../docs/FINAL-GATE.md`) |
| [`001-ai/`](001-ai/spec.md) | Локальный ИИ-контур двух режимов: подготовка модели, генерация и проверка сценариев, разбор спорных смысловых случаев, реестр ошибок | Реализованы фазы 1–6 (T001–T051), датасет v1 упакован; открыты T052–T060 |
| [`002-full-system-integration/`](002-full-system-integration/spec.md) | Сквозная интеграция фронтенда, бэкенда и ИИ: режим специалиста-112 в UI, платформа-обложка, безопасная авторизация (HttpOnly), задания, сквозная цепочка A → B, стенд одной командой (demo-up) | Волны W1–W3 завершены (T001–T058 закрыты), W4 подготовлена (стенд T060, документация T029/T030, сценарий T061 готовы) |

## Мок-данные

Рабочие моки приложения генерируются из спек-моков: `npm run mocks:sync` копирует
`spec/000-фронт/mocks/` в `mocks/` (и `icons/` в `public/icons/`); доменный валидатор —
`npm run mocks:validate`. Код приложения обращается только к `mocks/` через алиас
`@mocks/*`, к `spec/` — никогда.
