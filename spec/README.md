# spec/ — спецификации тестового фронтенда тренажёра оператора ДДС

Пакет указаний для разработки **тестовой системы с тестовым фронтом на мок-данных**: эмулятор АРМ-112 для подготовки операторов ДДС г. Москвы (хакатон «Лидеры цифровой трансформации», задача № 9).

Стек-ориентир: **Next.js (App Router) + TypeScript**. Роли: Обучающийся (диспетчер ДДС), Преподаватель, Администратор. Язык: русский.

## Как читать пакет

Порядок для нового участника:

1. `00-overview.md` — что строим, рамки, состав MVP.
2. `09-glossary.md` — термины (без них домен не понять).
3. `02-roles.md` — кто что может.
4. `06-user-flows.md` — сценарии занятий от начала до отчёта.
5. `03-architecture.md` — карта роутов и мок-слой.
6. `04-pages/*.md` — детальная спека каждого экрана (цель, блоки, данные, состояния, приёмка).
7. `05-data-models.md` — TS-контракты; `mocks/` — данные под них.
8. `07-design-guidelines.md` — **обязательно перед любой вёрсткой**: жёсткое правило аутентичности АРМ-112.
9. `10-code-rules.md` — **обязательно перед началом кодинга**: правила кода фронта (норматив ПРАВИЛА-КОДА-ФРОНТ) и адаптации FSD под Next.js.
10. `08-qa-decisions.md` — почему решения именно такие (ответы заказчика).
11. `01-requirements-map.md` — проверка: каждый пункт ТЗ → где закрыт.
12. `11-implementation-plan.md` — план реализации по фазам (после чтения спек, перед кодом).

## Жёсткие правила (кратко)

- **Дизайн**: дизайны из «карты проекта» — только пожелания. Истина — реальный ПОВ-112/АРМ-112 (скриншоты в `hack/Фронт/images/`, `hack/Фронт/Источники/скриншоты_из_docx/`, `research/arm-112/screenshots/`). Современный, аккуратный, но аутентичный по структуре и полям — см. `07-design-guidelines.md`.
- **Контур**: локальный, без внешних сетей и CDN; все данные — синтетические моки.
- **ИИ**: в тестовом фронте имитируется моками, в UI — бейдж «ИИ»; приоритет оценки — за преподавателем.
- **Нормативы**: реакция 30 сек, отработка 3 мин; полный жизненный цикл статусов реагирования обязателен.
