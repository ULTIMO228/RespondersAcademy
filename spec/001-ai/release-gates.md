# Правила допуска локальной ИИ-версии

Это обязательный шаблон **до первого доступа к закрытому holdout**, а не свидетельство готового релиза. `ModelRelease.status=accepted` запрещён, пока все поля манифеста не заполнены и условия ниже не пройдены. Изменение порога после открытия holdout требует нового закрытого набора и нового манифеста.

## Манифест до прогона

Ответственный преподаватель и инженер фиксируют: `gateVersion`, время утверждения, `approvedBy`, hash списка `sourceTicketId` для train/validation/holdout, hash очищенного датасета, версии эталона и рубрики, baseline/кандидата/судьи, prompt и chat template, рантайм, квантование, параметры, число повторов, оборудование и разрешённый CPU-бюджет. Holdout назначается целиком по `sourceTicketId` **до генерации**; генератор, подбор judge и промпта не получают его содержимое.

В holdout нужны оба режима и минимум по одному корректному, ошибочному и спорному текстовому случаю на режим. Минимум восемь независимых исходных билетов для финальной проверки; вариации одного билета считаются одной группой. Если состав недостижим, решение о выпуске откладывается, а не заменяется удобной выборкой. После открытия holdout его примеры не используются для обучения или выбора промпта.

## Метрики и знаменатели

Метрики считаются по **всем** заранее назначенным случаям и всем повторам; неудачные, невалидные и оборванные ответы остаются в знаменателе. Отдельно показываются оба режима, каждая задача (`scenario_generation`, `semantic_review`) и категории ошибок. Для сравнения с baseline используют те же случаи, рубрику и конфигурацию запуска.

| Проверка | Условие допуска |
|---|---|
| Валидный полный ответ | ≥95% всех ответов проходят схему, полноту и допустимые значения. |
| Цикл, timeout или обрыв | ≤1% всех ответов суммарно. |
| Выдуманный код ЕКП/адрес | 0 случаев среди всех ответов, где эти значения выдавались; в наборе обязаны быть проверяемые случаи с кодом и адресом. |
| Пропущенная критическая ошибка | 0 на всех размеченных критических случаях; если таких случаев нет, gate не пройден. |
| Качество по режиму | Macro-F1 по ручной метке и recall критических ошибок не ниже baseline **для каждого** режима; ложные обвинения не чаще baseline. Если показателя нет или данных недостаточно, gate не пройден. |
| Независимое подтверждение | Судья иной модельной семьи; при той же модели каждый пример с модельным вердиктом требует ручного решения. Критические и спорные случаи всегда требуют человека. |
| Воспроизводимость промпта | ≥3 повтора каждого фиксированного validation-случая; все ответы и разброс сохранены, без выбора лучшего повтора. |
| CPU-профиль | p50/p95 полной задержки, TTFT, пик RAM, доля timeout и размер на диске укладываются в **числовой бюджет**, утверждённый на целевом офисном ПК после validation-пилота и до открытия holdout. Пустой бюджет означает отказ от релиза. |
| Безопасность и происхождение | 100% источников прошли общий `SanitizedTicket` gate и человеческое утверждение; в запросах, логах, датасете и артефакте нет исходных ПДн. |

Отчёт `evalRunId` сохраняет числитель/знаменатель, доверительный контекст размера выборки, ссылки на каждый failed case и сравнение с прежним релизом. Нулевой критический пропуск на малой выборке не доказывает безопасность вне неё; ограничение явно указывается в отчёте. Ошибка любого обязательного условия даёт `rejected`; в занятии остаётся прежний принятый релиз либо резерв без LLM. Повторная попытка выпуска требует нового кандидата/манифеста.
