## Следующий шаг

1. Собрать первый реальный `SanitizedTicket` (пилотная партия билетов) и прогнать конвейер `sanitize → split → baseline_small_model → teacher_generate → deterministic_checks → independent_judge → human_adjudication → prepare_ai_dataset` не на фикстурах, а на нём — до этого числа/пороги настраивать не на чем.
2. Закрыть T052–T055 (US3, грамматика `dds`), затем сквозную проверку и нагрузочный тест T056–T057.
3. Закоммитить реализацию T001–T051 отдельно от работы по датасету, чтобы не смешивать «код готов» и «данные готовы» в одном диффе.

Для генерации сценария и подготовки датасета нужен **один** реестр `SanitizedTicket`: `piiCheck=passed`, решение человека и `sourceHash` до любого вызова модели. Решение преподавателя по оценке должно атомарно создавать `TeacherOverride`, `CalibrationSample` и запись аудита. Судья другой модельной семьи даёт независимую проверку; при совпадении модели каждый пример требует человека.
