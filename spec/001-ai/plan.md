# План реализации: локальный ИИ-контур тренажёра 112/ДДС

**Ветка**: `main` (новая не создавалась) | **Дата**: 2026-09-22 | **Спецификация**: [spec.md](spec.md)

**Вход**: решения пользователя по полному ИИ-контуру, двум режимам, предварительной оценке, локальной проверке текста и роли Qwen.

## Summary

Дополнить существующий Python backend и фронт: преподаватель готовит и утверждает варианты билетов; обучающийся получает объяснимую оценку; преподаватель сразу видит результат и каждую обнаруженную ошибку, затем может изменить итог. Существующий ML-оценщик и правила определяют факты и баллы. Локальная Qwen3.5-0.8B — кандидат для генерации фабулы и для второго эшелона спорной семантики/объяснения; её включение в занятие зависит от проверки качества и CPU-задержек. Грамматика, подсчёты, группировка ошибок и B→C работают без LLM.

## Technical Context

**Language/Version**: Python ≥3.11 (`backend/pyproject.toml`), TypeScript strict, Next.js/React из текущего `package.json` и установленного `node_modules`; точные версии сверяются перед кодом.

**Primary Dependencies**: FastAPI, SQLAlchemy, Pydantic, SymSpell, RapidFuzz, scikit-learn и опциональный `sentence-transformers` уже объявлены backend; локальный Ollama-путь уже есть. Для отдельного контура подготовки выбраны LangGraph (возобновляемый граф) и LangChain model adapters; они пока не установлены и добавляются после проверки совместимости с lockfile. Для выпуска модели кандидаты: Qwen3.5-0.8B, PEFT/QLoRA при подходящем оборудовании, llama.cpp с GGUF Q4 для CPU-инференса. Выбор ревизий после smoke-теста совместимости.

**Storage**: существующие SQLAlchemy-модели в SQLite для разработки и PostgreSQL для целевого контура; локальные checkpoints LangGraph и версионированные файлы выборки, инструкции, eval-прогонов и манифеста модели вне базы; только очищенная синтетика.

**Testing**: pytest unit/contract/integration в `backend/tests/`, Vitest/RTL и Playwright во фронте, фиксированный набор билетов для offline ML-eval, повторные prompt-eval и независимый LLM-judge с ручной сверкой, тест нагрузки на целевом CPU. Полный `npm run check` и `backend` тесты — на этапе реализации.

**Target Platform**: локальный изолированный веб-сервис на типовом офисном CPU без GPU; браузерные роли преподавателя и обучающегося. GPU/Mac команды допустимы только на этапе подготовки адаптера.

**Project Type**: существующее Next.js-приложение с совместимым mock API и отдельным Python backend; интерфейсы `src/shared/api/ai-gateway.ts`, `backend/app/ai_gateway.py`, `/api/mock/*`, `/api/v1/*`.

**Performance Goals**: сохранение попытки не ждёт LLM; в пробном классе 20 обучающихся потерь сдачи нет. Время появления предварительной оценки, p95, TTFT, throughput и RAM измеряются на целевом CPU; числовой SLA для генерации не утверждается без замера.

**Constraints**: offline runtime, синтетические данные, RBAC, четыре совместимые оси оценки, версия источника/эталона/модели, не более одной записи одной причины ошибки в попытке, преподаватель как арбитр. Коды классификатора и статусы не придумываются моделью.

**Scale/Scope**: 32 исходных билета × 3 ситуации, два режима, учебный класс до 20 человек; подбор следующих задач, RAG и свободный ИИ-абонент B→C вне фичи.

## Constitution Check

| Принцип | До исследования | После проектирования |
|---|---|---|
| I. Локальный CPU-контур | PASS: runtime только локальный; облако лишь для подготовки очищенной синтетики | PASS: очередь и резервный путь не требуют сети; размер модели и p95 — выпускной gate |
| II. Методическая достоверность | PASS: эталон из билета/ЕКП/памятки, правка преподавателя | PASS при обязательной записи каждого override в аудит и `CalibrationSample`; запись ошибки несёт ruleId, доказательство и версию эталона |
| III. Измеримый ML | PASS: основная оценка остаётся ML+правилами | PASS: отдельный отложенный набор, сравнение с базой, проверка JSON, ошибок и несогласий; LLM отключаема |
| IV. Простота и ядро | PASS при закрытии полного цикла первого режима | PASS при подтверждении второго режима и передачи **сохранённой** карточки A→B до реализации US5; RAG, рекомендатель и новый B→C не включены; скринкаст ≤5 минут — обязательный финальный gate |
| V. Единый контракт | PASS при четырёх полных JSON-схемах | PASS при сверке [четырёх схем](contracts/README.md) с действующими API и уведомлении команды об изменении; совместимый v1 не ломается |

**Условные gates**: полные схемы и цепочка A→B проверяются до подключения модели; US5 реализуется после подтверждения полного учебного цикла двух режимов. Условие выпуска Qwen — успешный пилот; без него feature path остаётся работоспособным на существующем оценщике и шаблонной генерации.

## Порядок реализации и точки контроля

1. **База и контракт (P1)**: проверить четыре полные JSON-схемы, старый `Evaluation`, выровнять пути билетов и RBAC. Gate: схема/ответы mock/v1 совместимы, команда уведомлена о новых схемах.
2. **Замкнутые режимы и связка (P1)**: подтвердить работающий учебный цикл первого режима; затем подключить второй и передать именно карточку, сохранённую обучающимся в A, в задание B. Для новой генерации общий gate очистки источника обязателен до вызова модели. Gate: A→B проходит без ручной конвертации, исходная попытка и версия карточки видны в происхождении.
3. **Оценка и реестр (P1)**: сохранять попытку до вычисления; выполнить ML/правила и локальную грамматику; записать компоненты и каждую ошибку с доказательством; показать преподавателю и предварительно обучающемуся. Gate: поздняя LLM не меняет факты и решение преподавателя; его правка попадает в аудит, отчёт и выборку перекалибровки.
4. **Пилот LLM после связки A→B (P1)**: подготовить LangGraph-конвейер с checkpoints, LangChain-адаптерами, очисткой и human gate; снять baseline, сгенерировать примеры сильной моделью, независимо оценить оба ответа и разобрать споры. До QLoRA сравнить системные промпты; затем открыть frozen holdout. Gate: версия включается только по [правилам выпуска](release-gates.md); иначе сохраняется fallback.
5. **Проверка текста (P2)**: применить уже существующий локальный `backend/ml/nlp/grammar.py`, дополнить покрытие полей/адреса и русских терминов в обоих режимах. Gate: неизвестные слова не исправляются автоматически; групповой отчёт уже строится из реестра на шаге 3.
6. **Сдача**: воспроизвести демо на синтетике и записать скринкаст длительностью не более пяти минут; без видео конституционный gate не закрыт.

`tasks.md` подготовлен. Первая правка путей сидов и черновики промптов/схем начаты; LangGraph, датасет, judge и релиз модели пока не реализованы. Статус каждой задачи отмечается в `tasks.md` после проверки.
