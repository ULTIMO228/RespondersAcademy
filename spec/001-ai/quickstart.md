# Проверка фичи 001 после реализации

Это сценарий приёмки для будущей реализации, а не отчёт о пройденных тестах. Основные данные и переходы — в [data-model.md](data-model.md), интерфейсы — в [contracts/ai-workflow-v1.md](contracts/ai-workflow-v1.md). Использовать только синтетические сиды.

## Предусловия

1. Python ≥3.11, `uv`, Node/npm и локальные зависимости установлены заранее. Целевой прогон выполняется с отключённым доступом во внешнюю сеть.
2. `backend/models/` содержит только принятые локальные версии, проверенные по manifest; отсутствие LLM допустимо для проверки резервного пути.
3. Билеты/учебные тексты, используемые для генерации и теста модели, прошли единый `SanitizedTicket` gate с человеческим утверждением. Отложенные билеты не входят в обучение и настройку промпта.
4. Перед началом сохранить снимок базы/использовать свежую тестовую базу: `uv run python -m app.seed.load --reset` удаляет её прежние данные и предназначен только для изолированной тестовой среды.

## Запуск существующего контура

Из корня репозитория:

```bash
cd backend
uv sync --group dev
uv run python -m app.seed.load
uv run pytest -q tests/unit/test_assess_operator112.py tests/unit/test_assess_dds.py tests/unit/test_nlp.py tests/unit/test_validator.py
uv run uvicorn app.main:app --port 8000
```

В отдельном терминале из корня репозитория:

```bash
BACKEND_URL=http://localhost:8000 npm run dev
```

Перед запуском полной backend-сборки выполнить регрессионную проверку путей сидов после переноса `spec/mocks/` в `spec/000-фронт/mocks/`. На этапе реализации выполнить `uv run pytest -q` и `uv run ruff check .`; для фронта — `npm run check && npm run test`. Команды здесь перечислены как gate, их успешное прохождение этим документом не заявляется.

## Сценарии приёмки

1. **Подготовка сценария и A→B**. Войти преподавателем, выбрать режим `operator112`, один утверждённый очищенный билет и запросить вариацию. Неутверждённый источник должен быть отклонён до генерации. Проверить `sourceTicketId`, код ЕКП, адрес и правило эталона. Принять одно поле, другое исправить, повторно проверить и утвердить версию. До утверждения обучающийся её не видит. Студент отправляет и сохраняет свою карточку; вход `dds` должен содержать именно её поля, `sourceAttemptId`, `sourceCardId`, `sourceCardVersion`, даже если она отличается от эталонного `cardSnapshot`.
2. **Сдача и предварительная оценка**. Обучающийся сдаёт корректную карточку, затем карточку с неверным адресом, пропущенным фактом и просрочкой. Сохранение каждой попытки возвращается без ожидания LLM. У преподавателя появляется новая попытка с тремя отдельными основаниями; студент видит только свой предварительный результат. Неверный адрес не компенсируется семантической близостью.
3. **Спорный смысл**. На фиксированном парафразе основной оценщик попадает в калиброванную спорную зону. Проверить, что LLM получает только очищенный текст и разрешённые факты, возвращает допустимые `referenceFactIds` и `explanation` по единой схеме. Если ответ `uncertain` или нарушает схему, преподаватель получает `review_required`; общий балл не подставляется нулём. После решения преподавателя появляется `final`; `TeacherOverride`, `CalibrationSample` и аудит сохраняются атомарно. Поздний ответ модели не меняет итог.
4. **Сбой/нагрузка**. Отключить локальную модель, одновременно сдать карточки 20 учебных аккаунтов. Проверить 0 потерянных попыток, доступность проверенных компонентов, ограниченную очередь и возможность завершить занятие. Отдельно измерить p50/p95, TTFT, RAM и timeout на целевом CPU; не подменять эти измерения скоростью личного GPU.
5. **Грамматика и ошибки**. Ввести опечатку, допустимое сокращение, неизвестную улицу и пустой текст; запустить проверку после правки преподавателя. Замечания ссылаются на текущее поле/фрагмент; текст не исправляется автоматически. Реестр содержит уникальные ошибки, а групповой счёт равен числу исходных записей.
6. **Роли и отчёт**. Студент запрашивает чужую попытку/реестр и получает отказ. Преподаватель меняет балл с причиной; у студента и в отчёте виден окончательный балл, первоначальный остаётся в аудите. PDF/CSV и экран показывают одинаковые групповые числа. Звонок B→C сохраняет утверждённую реплику и транскрипт без свободного ответа модели.
7. **Выпуск модели**. До открытия holdout заполнить [манифест](release-gates.md), включая числовой CPU-бюджет, состав групп, знаменатели и hash набора. Запустить baseline и кандидат на одном holdout по исходным билетам; проверить валидность ответов, ошибки по обоим режимам, незавершённые ответы и CPU-профиль. Принять лишь кандидата, прошедшего заранее записанные пороги. Отклонённый manifest не активируется; предыдущая версия продолжает работать.
8. **Датасет и независимый судья**. Остановить LangGraph после очистки для ручного разрешения, возобновить тем же `thread_id` и убедиться, что вызов модели не повторился. Сильная модель предлагает исправление только для train/validation; judge иной модельной семьи отдельно оценивает исходный и исправленный ответы, не видя решения генератора. Если модель судьи совпадает с генератором, каждый такой пример требует человека. При критическом расхождении пример ждёт человека и не попадает в выборку автоматически.
9. **Промпт и рассуждение**. Для одной версии системной инструкции повторить каждый фиксированный случай не менее трёх раз и сверить все ответы, манифест параметров, расхождения и метрики обоих режимов. Проверить thinking/non-thinking, лимит токенов, timeout, остановку цикла и отсутствие raw chain-of-thought в датасете/логах.

## Что зафиксировать в протоколе

- ID сценария, попытки, версии эталона и оценщика; для LLM — manifest релиза или явное `disabled`.
- Матрицу ожидаемых и обнаруженных ошибок по `ruleId`; отдельные примеры корректного, ошибочного и спорного смысла для каждого режима.
- Фактические команды, exit code, метрики CPU и размер артефакта на диске.
- Скриншоты состояний `preliminary`, `review_required`, `final` и исправления преподавателя, без персональных данных; финальный демонстрационный скринкаст ≤5 минут с полным циклом двух режимов.

Фича считается принятой при выполнении `SC-001..SC-015` из [spec.md](spec.md). При невыполнении модель остаётся выключенной, а нарушение ядра исправляется до демонстрации.
