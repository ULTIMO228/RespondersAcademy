# Учебные билеты (96 задач)

Источник: [source/bilety_zadachi_112.pdf](../source/bilety_zadachi_112.pdf) — «Билеты — задачи по С 112. АГС_ГСИ», 32 страницы, **скан без текстового слоя** (нужен OCR или ручная перепечатка).

## Структура

32 билета, в каждом — таблица из 3 ситуаций с заголовком «Отработайте вызовы от заявителя»:

| № | Ситуация | Адрес |
|---|---|---|
| 1 | фабула + ФИО заявителя + телефон | адрес в свободной форме, иногда с уточнением в скобках курсивом |

Всего 32 × 3 = **96 задач** — это и есть «96 билетов» из Q&A. Эталонных ответов (тип, службы, действия) в файле **нет** — их нужно построить по классификатору и памятке, а преподаватель-эксперт валидирует.

Данные обезличены (типовые ФИО Иванов/Петров/Сидоров/Соколов, телефоны вида 916-896-3254), показывать можно без ограничений.

## Наблюдения

- Билеты написаны для **оператора 112** (приём звонка), но для режима ДДС их легко превратить в готовые карточки: фабула → «Описание со слов заявителя», адрес → адресный блок, ФИО/телефон → заявитель.
- **Разброс сложности заложен намеренно:** ложные/непрофильные вызовы (поругался с продавцом), адреса вне Москвы (Волжский, Королёв, Балашиха — карточку должны перенаправить в 112 региона), неполные адреса («№ дома неизвестен, там библиотека № 193»), ловушки на признаки («03 не требуется», «дом газифицирован», «пострадавшие не блокированы»), многослужбовые (ДТП + разлив топлива + пострадавшие → 101, 102, 103, ЦОДД, Мосгортранс).
- Задачи повторяются между билетами (1.3 = 16.2) — при построении датасета дедуплицировать.
- Много **лексики для словаря STT и грамматической проверки**: названия улиц, номера машин, «ВАЗ 2115», «Донормил», «МЖД», «МКАД 74 км».
- Формат «Ситуация | Адрес» — это шаблон для генерации новых вариаций LLM-ом.

## План работы с билетами

1. Перепечатать/OCR все 32 страницы в `data/tickets/tickets.json` (поля: `ticket`, `n`, `situation`, `caller_name`, `caller_phone`, `address`, `address_note`).
2. Для каждой задачи вручную + по классификатору проставить эталон: `group`, `final_type`, `main_service`, `notify_services[]`, `expected_status` для целевой ДДС, `required_comment_elements[]`, `traps[]`, `difficulty`.
3. Дать преподавателю-эксперту (или команде) провалидировать — это и есть «утверждение эталона» из сценария A ТЗ.
4. Использовать как: базовые сценарии (уровень 1–2), few-shot примеры для генерации вариаций (уровень 3+), тестовая выборка для классификатора и оценщика.
