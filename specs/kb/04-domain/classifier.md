# Классификатор происшествий (ЕКП), версия v046_24

Источник: [source/klassifikator_proisshestviy_v046_24.xlsx](../source/klassifikator_proisshestviy_v046_24.xlsx) («корректировка МВД + Департамент»). Плоская выгрузка в TSV: [`data/classifier/klassifikator_v046_24.tsv`](../../data/classifier/klassifikator_v046_24.tsv).

Это та самая таблица, по которой ПОВ-112 автоматически формирует список оповещения. Для нас — **источник эталонов**: «какие службы должны получить карточку» и «какой тип должен быть у карточки».

## Структура

Один лист, 1310 строк × 104 колонки. Три строки заголовков (0–2), данные с 3-й.

**Иерархия:** 23 группы верхнего уровня (строки с пустыми п1–п3), внутри — 1283 конечных типа происшествий.

| Кол. | Заголовок | Что это |
|---|---|---|
| 0–3 | Г, п1, п2, п3 | Уровни иерархии (группа, признак 1, 2, 3) |
| 4 | Номер | Код типа, напр. `1010101` = группа 1, п1=1, п2=1, п3=1 |
| 5 | Группа происшествий (учёт в статистике) | Название группы / типа |
| 6 | 112 — Признак.1 (тип происшествия) | Первый признак опросной карты («на улице», «в доме»…) |
| 7 | 112 — Признак.2 | Второй признак («мусор», «трава», «квартира»…) |
| 8 | 112 — Признак.3 | Третий («открытое пламя», «дым»…) |
| 9 | Дополнительные признаки | Не влияют на тип |
| 10 | **Итоговый тип происшествия** | Уникален для каждой из 1283 строк, напр. «пожар: мусор», «задымление: трава» |
| 11 | ТИП происшествия ЕКП 35 | Укрупнённый тип (637 уникальных) |
| 12 | **Главная служба** | Код: `MCHS` (614), `Police` (305), `AMBULANCE` (68), `MOSGAZ` (38), `MOSLIFT` (24), `AUTOROADS` (21), `MOSVODOCANAL` (20), `METRO`, `OEK`, `MOSGORTRANS`, `MOESK`, `MOEK`, `MZD`, `MGTS`, `MOSVODOSTOK`, `MOSCOLLECTOR`, `GORMOST`, `GKH`… (102 строки без главной службы) |
| 13–98 | по одной на службу/условие | **Реакция службы** на этот тип |

**Значения в ячейках реакции:**
- `карточка-112` — служба получает карточку в исходном виде (на АРМ-112). Самое частое значение (~14 800).
- Название типа в терминах службы, напр. `пожар`, `травма`, `взрыв`, `отравление`, `нарушение правопорядка`, `аварии в городском хозяйстве` — служба интегрирована, карточка транслируется в её систему с этим типом (~4 000).
- `нет реагирования` — служба в курсе, но не реагирует (741).
- Пусто — служба не оповещается.

## Как использовать в проекте

1. **Эталон списка оповещения** для сценария: по итоговому типу (кол. 10) взять все непустые колонки реакций, кроме `нет реагирования` → набор служб, которые должны получить карточку. Главная служба — кол. 12.
2. **Справочник типов** для карточки: группа → признак 1 → признак 2 → признак 3 — это ровно те кнопки, что видны на скриншоте опросной карты в памятке (стр. 15).
3. **Обучение классификатора** «текст описания → группа / итоговый тип»: 23 группы — реалистичная целевая переменная; 1283 типа — слишком мелко для синтетики, использовать как второй уровень только для частых.
4. **Эталон для оценки «правильно ли диспетчер определил, что карточка профильная»**: если служба ученика в списке оповещения с реакцией `карточка-112` — карточку надо принять; если `нет реагирования` или пусто — корректно «Не принята».
5. **Фильтр ленты ученика по профилю** (требование ТЗ): ученик службы X видит только типы, где у X есть реакция.

## Замечания по качеству данных

- Есть опечатки в заголовках («Депортамент», «самойбийство») — при парсинге не полагаться на точные строки заголовков, использовать индексы колонок.
- Несколько строк с составной главной службой (`METRO, MZD`, `MOESK, OEK`) и одна с пробелом вместо кода.
- Значение `карточка -112` (с пробелом) встречается 756 раз — нормализовать вместе с `карточка-112`.
- Перенос строк внутри ячеек заголовков (МОЭСК, ЦУКБ.БПЛА).
