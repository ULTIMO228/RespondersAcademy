# Карточка происшествия и статусы реагирования

Источник: «Работа на АРМ-112. Памятка для ДДС» (ГБУ «Система 112», 2025) — [source/rabota_s_arm112_dds.pdf](../source/rabota_s_arm112_dds.pdf). В PDF на стр. 12–20, 23–25 — реальные скриншоты интерфейса ПОВ-112, по ним делать эмулятор.

## Как работает система-112 Москвы

- Заявитель звонит один раз на «112», оператор Службы 112 опрашивает, классифицирует, регистрирует карточку в ПОВ-112 (информационная система системы-112) и направляет всем службам из **списка оповещения**.
- Список оповещения формируется **автоматически** по итоговому типу происшествия через ЕКП (Единый классификатор событий, происшествий и ЧС) — см. [classifier.md](classifier.md). Оператор может добавить службу вручную, удалить — нет.
- Карточки также приходят из внешних информационных систем (ВИС): Служба 101 (КИС УСС МЧС), 102 (СОДЧ МВД), 103, 104, ЦОДД, Мосводоканал, ЭРА-ГЛОНАСС, 112 МО и Калужской обл. Карточки от ВИС содержат меньше данных: нет номера АРМ оператора, не всегда есть опросная карта, нет формализованных признаков, пострадавшие — только в описании.
- Службы получают карточку на АРМ-112 (удалённый терминал системы-112) или в свою систему через интеграцию, и обязаны регистрировать в системе-112 ход реагирования через **статусы реагирования** и комментарии.
- За соблюдением регламентов следит **Отдел контроля реагирования** — при нарушении звонит диспетчеру. Это ровно та функция, которую в тренажёре выполняет авто-оценка.

**Три требования законодательства** (488-ФЗ, ПП РФ 1931, ПП Москвы 1420-ПП):
1. Все службы МГСЧС подключены к системе-112.
2. Службы обязаны обрабатывать информацию и регистрировать реагирование.
3. **Диспетчер должен подтвердить получение карточки через 30 секунд** после направления в службу.

## Структура карточки (поля для эмулятора)

**Шапка:**
- Номер карточки в системе-112, дата/время сохранения, кто зарегистрировал (оператор, номер АРМ; у ВИС — «оп. 9999»).
- Таймер с момента создания (мм:сс).
- Телефоны: **АОН** (автоматически), **предоставленный** (заявителем), **на место** (если заявитель не на месте происшествия).
- Признаки-кнопки: «Пострадавшие», «Нет на месте / Отказ от скорой», «Нет доступа / Заблокированные», «нет контакта», «срыв звонка».

**Заявитель:** фамилия и имя, статус.

**Адресный блок:** страна, субъект, населённый пункт, объект, округ, район, улица, дом/владение, корпус, стр./соор., квартира/офис, подъезд, этаж, код; **описательный адрес** (свободный текст); значок карты. Зарегистрированный адрес может не совпадать с местом происшествия.

**Описание со слов заявителя** — свободный текст до 1999 символов. В описании могут быть детали, которые нельзя выразить признаками, но критичны для реагирования.

**Опросная карта и формализованные признаки** (правая часть): тип происшествия (напр. «Происшествие 101») → признак 1 (Где: улица / транспорт / дом / здание / опасный объект) → признак 2 (Признак пожара: дым / открытое пламя / запах гари / сработала сигнализация) → признак 3 (Дом: квартира / балкон / подъезд / подвал / лифт / мусоропровод …). Каждая комбинация → итоговый тип → список оповещения.

**Список оповещения** (нижняя оранжевая полоса): блоки служб (Служба 102, Служба 101, ОМВД, ЦОДД, Мос.Без., Упр. района…), в каждом — последний статус реагирования и время. По «карандашу» в блоке своей службы диспетчер ДДС проставляет статус.

## Статусы реагирования (жизненный цикл для ДДС)

| Статус | Кто/когда | Требования |
|---|---|---|
| Добавлена | система | автоматически при сохранении карточки с оповещением службы |
| Получена службой | система | при поступлении на сервер интегрированной службы или **при открытии карточки диспетчером на АРМ-112** |
| **Принята** | диспетчер | в течение **30 с** после направления карточки. Реагирование будет. |
| **Не принята** | диспетчер | в течение 30 с. Реагирование не будет (не наша зона/объект/тип, уже реагируем по другой карточке). **Комментарий обязателен**: причина + кому передана информация. Можно потом сменить на «Принята». |
| Начало реагирования | диспетчер | выезд сил и средств |
| Прибытие | диспетчер | прибытие на место |
| Проведение работ | диспетчер | начало аварийно-восстановительных работ |
| **Работы завершены** | диспетчер | завершение работ. Перед сохранением все результаты — в комментарий: **статус закрывает карточку для редактирования** |
| Отказ от выполнения работ | диспетчер | реагирование начато, но работы не проводились. Комментарий обязателен. Закрывает карточку. |

Статусы выбираются **только последовательно**: сначала доступны только «Принята» / «Не принята»; после «Принята» — «Начало реагирования», «Прибытие», «Проведение работ», «Завершение работ», «Отказ от выполнения работ»; после «Не принята» — только «Принята».

Исключения: Служба 103 не ставит «Не принята» и «Отказ» (вместо них «Работы завершены: Завершение работ без бригады»); Служба 104 не всегда пишет комментарии.

Отсутствие первичного статуса в 30 с переводит карточку в статус **«Не оповещено»** — это нарушение.

## Правила проставления статусов (= критерии оценки)

1. **Соответствие фактическому статусу** — если работы не будут проводиться, нельзя ставить «Принята», и наоборот.
2. **Соответствие компетенции службы** — статус отражает работу именно этой службы; нельзя отказываться только потому, что реагирует другая служба.
3. **Своевременность** — первичные статусы в регламентное время; статусы хода работ — по факту получения информации.
4. **Полнота информации** — для «Не принята» и «Отказ» комментарий обязателен; уточнённый адрес, принадлежность объекта, факт передачи в другую службу — тоже в комментарии.

## Статусы карточки (в целом)

| Статус | Значение |
|---|---|
| Зарегистрирована | сохранена в ПОВ-112 |
| Отработана | Служба 112 завершила оповещение |
| Проверена | проверена главным специалистом-112 |
| **Не оповещено** | какая-то служба не поставила «Принята»/«Не принята» вовремя (красная индикация) |
| **Отказ** | служба поставила «Не принята» или «Отказ», карточка проверена |
| **Не завершено** | прошло > 48 ч, у какой-то службы нет «Работы завершены» |
| Завершена | все службы поставили «Работы завершены» |

## Типовые нарушения (из практики отдела контроля) — база для типологии ошибок

1. **Отсутствует статус реагирования** (не уложились в 30 с).
2. **Статус не соответствует заявке.** Примеры: «Принята: не обслуживаем территорию» вместо «Не принята: …»; «Принята» во всех дублях при незнании, кто обслуживает лифты; «Работы завершены: нет договора» вместо «Отказ от выполнения работ».
3. **Отказ от профильного происшествия.** Посторонние в подвале, вскрытый чердак, повреждение автомобиля при очистке крыши — «Не принята» без оснований.
4. **Нет комментария** к «Не принята» / «Отказ». Информация передана в УК «ПИК», провод «Ростелекома», реагирование по другой карточке (нужно «Не принята: дубль» или «реагирование по КП №…») — всё это должно быть в комментарии.
5. **Неполный комментарий.** «Не обслуживаем» без указания, кому передано; «люк огорожен, принадлежность устанавливается» — не написали.
6. **Нет статусов хода работ** («Начало реагирования», «Прибытие», «Проведение работ») и комментариев к ним при длительном реагировании с потоком повторных звонков.
7. **Нет оперативной связи** с местом установки АРМ-112.

## «Что делать, если…» (правила для эталонных действий)

- Ошибочно «Не принята», а реагировать будем → поставить «Принята».
- Ошибочно «Принята», а реагировать не будем → «Отказ от выполнения работ» с комментарием (причина, кому передано).
- Ошибочно «Работы завершены» или «Отказ» → сообщить в отдел контроля по телефону.
- Ситуация изменилась, нужны другие службы → позвонить на «112», представиться (ФИО, должность, служба), назвать адрес и повод, сообщить номер карточки и изменение ситуации.
- Уточнить информацию по текущей карточке → позвонить в отдел контроля.
