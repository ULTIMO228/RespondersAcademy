# Модель процесса: два режима обучаемого (специалист-112 и диспетчер ДДС)

Зафиксировано 18.09.2026 по итогам разбора памятки «Работа на АРМ-112» (стр. 12–33, скриншоты ПОВ-112), полного ТЗ и Q&A. **Исправляет** вывод из [03-qa-session-summary.md](03-qa-session-summary.md) «оператор 112 исключён»: исключён только *живой голосовой диалог с заявителем как обязательное требование*, а сама роль оператора 112 — в объёме.

## Суть

В системе-112 Москвы карточка проходит через двух разных людей из двух разных организаций:

```
Заявитель ──звонок──▶ [A] Специалист-112 ──«сохранить»──▶ ПОВ-112 ──по ЕКП──▶ [B] Диспетчер ДДС
                        ГБУ «Система 112»                список оповещения      Гормост, ЖКХ, Мосгаз…
```

Это разные профессии, но тренажёр готовит человека, которого по результатам могут направить на практику **в любое из двух мест**. Поэтому:

- **одна учётная запись обучаемого, один интерфейс, два режима задания** (`operator112` / `dds`);
- **выход режима A — вход режима B**: карточка, заполненная обучаемым-оператором по звонку, может упасть в очередь обучаемому-диспетчеру. В ТЗ это «сформированные обучающимися карточки событий» (сценарий «Действия с карточками»: сгенерированные / сформированные обучающимися / смешанные);
- заявитель в режиме A — ИИ: **текстом** (обязательно) или **голосом** «якобы с телефонии» (если получится).

## Режим A — специалист-112 (памятка стр. 12–16)

Обучаемый принимает вызов и заполняет карточку **с нуля**. 96 билетов («Отработайте вызовы от заявителя») написаны ровно под этот режим: фабула + ФИО + телефон + адрес = то, что заявитель говорит в трубку.

Экран карточки (стр. 15):

| Блок | Содержимое |
|---|---|
| Шапка | АОН (автоматически), предоставленный телефон, телефон на место; «Происшествие N», «Сохр. дата, Опер. N, АРМ N»; таймер мм:сс с момента создания; кнопки «записи звонков», «список SMS» |
| Признаки-кнопки | Пострадавшие · Нет на месте/Отказ от скорой · Нет доступа/Заблокированные · нет контакта · срыв звонка; флаги **ЧС** / **ЧП** |
| Заявитель | Фамилия и имя + статус (очевидец / пострадавший…) |
| Адрес | Страна → Субъект → Населённый пункт → Объект → Округ → Район → Улица → Дом/Вл. → Корпус → Стр./соор. → Квартира/офис → Подъезд → Этаж → Код; описательный адрес; значок карты; «очистить адрес» |
| Описание со слов заявителя | свободный текст, счётчик 0/1999 |
| Опросная карта (справа) | «добавить тип происшествия» → «Происшествие 101» → **Где** (Улица / Транспорт / Дом / Здание-объект / Опасный объект) → **Признак пожара** (Дым / Открытое пламя / Запах гари / Сработала сигнализация) → **Доступ** (Нет доступа) → **Дом (пламя)** (квартира / балкон / газовая колонка / газовая плита / лифт / мусоропровод / подъезд / счётчик / частный дом / проводка / электрощит / лестничная клетка / подвал / дача / сарай / прочие). Выбранные — синим. Комбинация = итоговый тип ЕКП |
| Список оповещения (оранжевая полоса внизу) | формируется **автоматически** по итоговому типу; «+» — добавить службу вручную; удалить нельзя |
| Кнопки | сохранить · связать · таймер · тревога · сообщение · закрыть |

После сохранения (стр. 16): карточка «Зарегистрирована», блок «Класс.: …», нижний блок **журнал звонков** (Опер. / АРМ / Дата и время / Служба / Куда звонили / Телефон / ФИО / Суть сообщения — напр. «коммутация, принято») для служб, оповещаемых по телефону; кнопка **«отработана»** → статус карточки «Отработана» → главный специалист проверяет → «Проверена».

**Оценка в A** (эталон = билет + ЕКП): правильность итогового типа и признаков (→ список оповещения), адрес по справочнику улиц (опечатки, Дубнинская/Дубининская), полнота описания (не потерял «дом газифицирован», «03 не требуется»), выставленные признаки (пострадавшие), время до сохранения, грамматика ручного ввода. Открытый вопрос: учитывать ли ручные добавления служб в список оповещения (см. STATUS в specs).

## Режим B — диспетчер ДДС (памятка стр. 21–33)

Карточка (из режима A, из билета, сгенерированная, «от ВИС» — урезанная: нет АРМ оператора, нет опросной карты, нет признаков, пострадавшие только в описании) падает в очередь на главном экране (стр. 12: грид, таймер, красный индикатор контроля, автообновление). Диспетчер карточку **не редактирует** — работает в блоке своей службы в списке оповещения:

1. Открыть за **30 с** (открытие = авто-статус «Получена службой»; иначе карточка → «Не оповещено», красная).
2. «Карандаш» в блоке своей службы → только «Принята» / «Не принята». Рядом поля **«Номер наряда»**, **«Направлены рабочие»** (стр. 24).
3. «Не принята» / «Отказ от выполнения работ» — комментарий обязателен: причина + кому передано («дубль», «реагирование по КП №…», «передано в УК ПИК»).
4. Далее последовательно: Начало реагирования → Прибытие → Проведение работ → Работы завершены (закрывает карточку). После «Не принята» доступна только «Принята».
5. Параллельно — доклад руководителю/бригаде по софтфону (точка C, ИИ: «Слушаю» → «Понял, принято»); при изменении ситуации — звонок на 112 (ещё один ИИ-собеседник, опционально).
6. Пока работает — падают новые карточки (многозадачность обязательна).

**Оценка в B** = функция отдела контроля реагирования (стр. 26–31), 7 типов нарушений: (1) нет статуса реагирования за 30 с; (2) статус не соответствует заявке («Принята: не обслуживаем» вместо «Не принята»); (3) отказ от профильного происшествия; (4) нет комментария к «Не принята»/«Отказ»; (5) неполный комментарий (не указано, кому передано); (6) нет статусов хода работ при длительном реагировании; (7) нет оперативной связи. Плюс тайминги (30 с / 3 мин на «чтение, заполнение, решение, голосовое подтверждение»), многозадачность, чек-лист доклада.

Статусы карточки в целом: Зарегистрирована → Отработана → Проверена; Не оповещено / Отказ / Не завершено (>48 ч) — красные; Завершена.

## Что общее для двух режимов

- Один компонент карточки: в A редактируемый, в B — просмотр + блок статусов своей службы.
- Один справочник ЕКП (`data/classifier/`), один справочник улиц, один банк сценариев (билет → в A это «звонок», в B — готовая карточка с эталонной классификацией).
- Один оценщик с двумя наборами правил, один отчёт, одна адаптивная сложность — результаты в обоих режимах определяют, «куда направить на практику».
- Преподаватель при назначении выбирает режим (или цепочку: сначала A, потом та же карточка в B).
