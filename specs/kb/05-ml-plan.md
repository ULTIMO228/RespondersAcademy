# ML-часть: план

Зона ответственности ML-специалиста. Граница с ИИ-инженером — в конце документа.

## Принцип

Кейс «LLM-шный», но измеримая часть — классическая ML: модели, которые *классифицируют, сравнивают, считают* и чью точность можно показать числом. Именно это жюри спросит как «проверка расчётов» и «достоверность». Обучать большие модели с нуля не будем — нет данных и смысла; будем обучать маленькие модели и калибровать на размеченных примерах.

**Всё офлайн, на CPU** (типовой офисный ПК). Модели скачиваются один раз с HuggingFace, дальше интернет не нужен.

## Модули

### 1. Движок оценки карточки (ядро)

**Вход:** действия ученика с карточкой (статусы с таймстампами, введённые поля, комментарии) + эталон сценария + нормативы.
**Выход:** оценка по рубрике + список ошибок с привязкой к правилу из памятки.

| Что проверяем | Как | Источник правила |
|---|---|---|
| Первичный статус за 30 с | таймстамп открытия / статуса vs. норматив | памятка, 488-ФЗ |
| Правильность первичного решения («Принята» / «Не принята») | сравнение с эталоном из классификатора (служба в списке оповещения?) | classifier.md, п. 4 |
| Последовательность статусов | Принята → Начало → Прибытие → Работы → Завершены; пропуски, нарушение порядка | памятка, «Правила проставления» |
| Полная отработка за 3 мин | таймстамп «Работы завершены» vs. норматив | Q&A |
| Комментарий к «Не принята» / «Отказ» | наличие; смысловое наличие обязательных элементов (причина, кому передано) — эмбеддинги + извлечение сущностей | памятка, нарушения 4–5 |
| Поля карточки (адрес, тип, служба, пострадавшие) | точное / нечёткое / по справочнику | тикеты + классификатор |
| Свободный текст (описание, комментарии) | эмбеддинги → косинус → порог | Q&A: «смысловое, не побуквенное» |
| Грамматика / опечатки | LanguageTool офлайн; отдельно — опечатки в адресах | Q&A: Дубнинская/Дубининская |
| Многозадачность | время реакции на каждую карточку в очереди, «залипание» на одной | Q&A |

Веса — настраиваемые преподавателем (требование ТЗ), по умолчанию — из калибровки (модуль 7).

### 2. Проверка адресов

Нормализация введённого адреса («ул. Ленина 5» ≡ «Ленина, д.5»), нечёткое сопоставление со справочником улиц Москвы (офлайн-выгрузка OSM/ФИАС), детекция похожих названий (Дубнинская / Дубининская) с предупреждением. Это отдельный модуль с прямым заказом от экспертов и готовый пример для питча.

### 3. Оценка голосового доклада руководителю службы

Ученик по софтфону проговаривает вводную → Vosk даёт транскрипт → проверяем чек-лист: назвал ли адрес, тип происшествия, число пострадавших, номер карточки. Сопоставление реплик с пунктами — эмбеддинги + парафразы. Небольшой модуль, тот же механизм, что и в п. 1.

### 4. Классификатор типа происшествия

Текст описания → группа ЕКП (23 класса), опционально → итоговый тип для частых. Данные: 96 билетов (тестовая выборка) + синтетика от LLM по группам (несколько сотен). Модель: замороженный эмбеддер + логрег/SVM, либо дообученный `rubert-tiny2`. Применения: проверка «правильно ли ученик определил тип/профильность», авторазметка сгенерированных сценариев, фильтр брака генерации, подсказка типа в карточке на низкой сложности.

### 5. Контроль качества генерации

Сгенерированный сценарий → классификатор подтверждает категорию → эмбеддинги ловят дубликаты (косинус > 0.9) → в предпросмотр преподавателю попадают только прошедшие фильтр, с пометками. Это «снижение нагрузки на преподавателя» из ТЗ в измеримом виде.

### 6. Адаптивная сложность

Прямой ответ на критерий «прогнозирование» (подтверждено на Q&A: «как рейтинг в шахматах»). Рейтинг ученика + сложность сценария (по признакам: число ловушек, служб в списке, полнота адреса, поток карточек) → подбор следующего. Начать с Эло-подобного обновления, при наличии данных — регрессия. Плюс интервальное повторение категорий, где ошибался.

### 7. Калибровка и валидация оценщика

Собрать 50–100 отработанных карточек (сгенерированные + вручную испорченные), командой разметить «правильно / ошибка / какая», посчитать согласие авто-оценки с ручной: точность по полям, корреляция итогового балла, каппа Коэна. Итоговый балл — регрессия по признакам (близости, время, ошибки) на ручной разметке. **Учёт правок преподавателя** (Q&A: «система учитывает корректировки при пересчёте оценок») = дообучение этой регрессии на его метках. Это слайд «достоверность».

### 8. Аналитика

pandas + графики: радар компетенций ученика (скорость, статусы, поля, комментарии, грамотность), динамика по занятиям, тепловая карта группы «тип происшествия × тип ошибки», топ ошибок группы, кластеризация свободных замечаний (эмбеддинги → кластеры → «типичные ошибки»), детекция аномалий (слишком быстро и идеально). Это не ML-фича, а то, что делает результат ML видимым преподавателю; жюри отдельно оценивает наглядность диаграмм.

### 9. Данные

- Классификатор → структурированный справочник (JSON): группа → признаки → итоговый тип → главная служба → список оповещения.
- Билеты → `tickets.json` с эталонами (см. [04-domain/tickets.md](04-domain/tickets.md)).
- Памятка → типология ошибок (7 категорий нарушений) и правила эталонных действий.
- Словарь доменной лексики для Vosk (улицы, службы, аббревиатуры).

## Модели

| Задача | Модель | Размер | Примечание |
|---|---|---|---|
| Эмбеддинги (оценка, дедуп, чек-листы) | `intfloat/multilingual-e5-small` или `deepvk/USER-base` | 470–500 МБ | сравнить на своих примерах, выбрать по метрике |
| Эмбеддинги в реальном времени / классификатор | `cointegrated/rubert-tiny2` | 120 МБ | очень быстрый на CPU |
| Запасной вариант, чисто русский | `ai-forever/sbert_large_nlu_ru` | 1.7 ГБ | медленнее |
| Грамматика | LanguageTool (офлайн, Java) | — | или лёгкий spell-checker |
| Нечёткое сравнение | `rapidfuzz` | — | адреса, названия |
| Классификатор | scikit-learn поверх эмбеддингов / дообученный rubert-tiny2 | — | обучение на CPU за минуты |

Стек: Python, sentence-transformers, scikit-learn, rapidfuzz, LanguageTool, pandas, matplotlib/plotly.

## Как «обучаем свою модель» (честно)

1. Классификатор поверх эмбеддингов — на синтетике + билетах, с train/test и confusion matrix.
2. Дообучение `rubert-tiny2` на классификацию группы — минуты на CPU.
3. Опционально: дообучение эмбеддера на парах «реплика — пункт чек-листа» (sentence-transformers), если базовое качество на коротких фразах слабое.
4. Калибровочная регрессия итогового балла на ручной разметке команды и правках преподавателя.

Все — маленькие, но настоящие модели с метриками. Большую LLM никто на хакатоне не обучает.
