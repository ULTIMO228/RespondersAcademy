# Research: технические решения (Phase 0)

Формат: **Decision** — **Rationale** — **Alternatives considered**. Все решения соответствуют принципу I конституции (офлайн, CPU).

## R1. Эмбеддинг-модели для семантической оценки

- **Decision**: `cointegrated/rubert-tiny2` (≈120 МБ) — основной эмбеддер для реального времени (комментарии, действия, чек-лист доклада, классификатор группы ЕКП). `intfloat/multilingual-e5-small` (≈470 МБ) — второй эмбеддер для дедупликации сценариев и калибровочных экспериментов; выбор между ними для каждой задачи фиксируется по метрике на `data/labeled/`.
- **Rationale**: rubert-tiny2 даёт < 20 мс на фразу на CPU, достаточен для коротких реплик; e5-small заметно лучше на длинных фабулах. Оба грузятся с HuggingFace один раз и работают офлайн через sentence-transformers.
- **Alternatives**: `ai-forever/sbert_large_nlu_ru` (1,7 ГБ, медленнее в 10×) — оставлен как запасной; OpenAI/облачные эмбеддинги — запрещены конституцией.

## R2. Проверка грамматики и опечаток без Java

- **Decision**: `symspellpy` с русским частотным словарём + доменный словарь (улицы, службы, аббревиатуры) — основной офлайн-спеллчекер. LanguageTool (`language_tool_python`, требует Java) — опциональный плагин, включается флагом, если на машине есть JRE.
- **Rationale**: Q&A: опечатки критичны; типовой офисный ПК может не иметь Java; symspellpy — чистый Python, миллисекунды на строку. Грамматика (согласование) второстепенна относительно опечаток в адресах.
- **Alternatives**: Яндекс.Спеллер — онлайн, запрещён; `pymorphy3` + правила — трудоёмко; только LanguageTool — риск отсутствия Java у экспертов.

## R3. Проверка адресов и похожих улиц

- **Decision**: офлайн-справочник улиц Москвы `data/streets/moscow_streets.json` (выгрузка OpenStreetMap через Overpass на этапе разработки; ~4 000 записей: название, тип, округ/район). Нормализация («ул. Ленина 5» → `{street: "ленина", type: "ул", house: "5"}`), сопоставление `rapidfuzz` (`token_set_ratio`), детекция «похожая улица» при ratio ≥ 85 и неточном совпадении.
- **Rationale**: пример заказчика Дубнинская/Дубининская — обе есть в справочнике, ratio ≈ 90; отдельный тип ошибки, отличный от грамматики. ФИАС избыточен и тяжёл.
- **Alternatives**: онлайн-геокодеры — запрещены; ФИАС/ГАР — гигабайты, лицензионные вопросы; без справочника — не ловит пример заказчика.

## R4. Классификатор категории ЕКП

- **Decision**: эмбеддинги rubert-tiny2 + логистическая регрессия (scikit-learn) на 23 группы; обучающие данные — 96 задач билетов (тест) + синтетика от `dds_ai.generate` по группам (≥ 15 примеров на группу); при нехватке — дообучение rubert-tiny2 (минуты на CPU). Confusion matrix и accuracy в `ml/scripts/eval_classifier.py`.
- **Rationale**: SC-003 (≥ 80 %); нужен для фильтра генерации и проверки типа в оценке; 1283 итоговых типа — слишком мелко, используем как второй уровень только для частых.
- **Alternatives**: zero-shot через LLM — медленно и невоспроизводимо; TF-IDF + SVM — запасной бейзлайн, оставлен в скрипте для сравнения.

## R5. Локальная LLM для генерации сценариев

- **Decision**: Ollama + `qwen2.5:7b-instruct` (q4_K_M, ≈4,7 ГБ) как основная; `qwen2.5:3b` (≈2 ГБ) как лёгкий профиль для слабых ПК. Промпты few-shot из билетов; выход — строго JSON по `scenario.schema.json`, валидация + до 2 повторов. Генерация — фоновая задача с прогрессом.
- **Rationale**: качественный русский, приемлемо на CPU (7B: ~3–6 ток/с на 4 ядрах → 5 сценариев ≈ 2–3 мин, допустимо для преподавателя, не для обучаемого). Ollama проще в офлайн-поставке, чем llama.cpp вручную.
- **Alternatives**: облачные API — только на этапе разработки для синтетики (разрешено конституцией), не в прототипе; `saiga`/`vikhr` — рассмотреть, если качество JSON хуже.

## R6. STT / TTS для софтфона

- **Decision**: STT — Vosk `vosk-model-small-ru-0.22` (≈45 МБ) с доменной грамматикой/словарём (улицы, службы, числа); TTS — Silero v4 ru (torch CPU, ≈50 МБ, несколько голосов: `aidar`, `baya`, `kseniya`, `eugene`) — обеспечивает вариативность муж/жен по службе.
- **Rationale**: обе модели офлайн, лёгкие, задержка «Слушаю» < 1 с. Ответчик — конечный автомат (приветствие → слушаем до паузы 2 с / кнопки → подтверждение), без LLM в реальном времени.
- **Alternatives**: Whisper (faster-whisper small) — точнее, но 2–5 с на фразу на CPU; оставлен как опция для офлайн-переоценки записей. Coqui TTS — тяжелее.

## R7. Транспорт аудио софтфона

- **Decision**: браузер `getUserMedia` → `AudioWorklet` → PCM16 16 кГц чанки по 100 мс → WebSocket `/ws/softphone/{attempt_id}` → бэкенд (Vosk streaming) → ответные WAV-чанки TTS в тот же WS → воспроизведение через WebAudio. Запись доклада сохраняется в `var/recordings/{attempt_id}.wav`.
- **Rationale**: ТЗ допускает софтфон/WebRTC без реальных SIP; WS-аудио не требует TURN/STUN и SIP-сервера, работает в изолированной сети. Задержка в локалке < 100 мс.
- **Alternatives**: WebRTC + aiortc — сложнее (ICE, SDP), выигрыш не нужен в локальной сети; SIP (Asterisk/FreeSWITCH) — описывается в `docs/architecture.md` как путь внедрения.

## R8. Архитектура оценщика

- **Decision**: `dds_ml.assess.engine.assess(attempt, scenario, config) -> AssessmentResult`. Компоненты: `timing`, `statuses`, `comments`, `fields`, `grammar`, `address`, `multitask`, `report_checklist`. Каждая возвращает `score ∈ [0,1]`, список `errors[{type, rule, message, step, fixed}]`, `warnings`. Итог = Σ weight·score × 100; веса — из конфигурации занятия, значения по умолчанию из `calibration`. Реестр правил `rules.py`: `Rule(id, type, source, text)`; `source` обязателен.
- **Rationale**: принципы II и III; FR-023/024/030; детерминированные компоненты работают без моделей.
- **Alternatives**: единый LLM-судья — невоспроизводим, нет метрик; чисто правила без семантики — не выполняет «смысловое сравнение» из Q&A.

## R9. Калибровка и валидация

- **Decision**: `data/labeled/attempts/*.json` — 50–100 попыток (синтетика + вручную испорченные), размеченные командой по типам ошибок и экспертному баллу. `ml/scripts/eval_assessor.py` считает точность по типам ошибок, каппу Коэна, корреляцию Пирсона/Спирмена итогового балла. `calibrate.py` подбирает веса регрессией (ridge) на разметке + правках преподавателя (`AssessmentOverride`).
- **Rationale**: SC-002, критерий жюри «достоверность», Q&A «система учитывает правки преподавателя».
- **Alternatives**: экспертная разметка заказчика — недоступна в сроки; фиксированные веса без калибровки — нет слайда «достоверность».

## R10. Адаптивная сложность

- **Decision**: Эло-подобное обновление: рейтинг обучаемого `R_s`, сложность сценария `D` (взвешенная сумма: число ловушек, число служб в списке, полнота адреса, темп потока, источник ВИС). Ожидаемый результат `E = 1/(1+10^((D−R_s)/400))`, фактический `S = score/100 × norm_ok`; `R_s += K(S−E)`. Подбор следующего: сценарий с `D ≈ R_s + δ`, с повышенной вероятностью категории из слабых (интервальное повторение).
- **Rationale**: Q&A «как рейтинг в шахматах»; прозрачно, объяснимо, без обучающих данных. Регрессия — если появятся данные.
- **Alternatives**: бандиты/IRT — избыточно для двух недель.

## R11. Отчёты и экспорт

- **Decision**: CSV — pandas; PDF — `reportlab` (чистый Python, кириллица через встроенный DejaVu); диаграммы для PDF — matplotlib PNG; для веба — Recharts.
- **Rationale**: без headless-браузера и wkhtmltopdf; офлайн; DOCX/PDF из ТЗ — отчёт и сертификат.
- **Alternatives**: WeasyPrint — зависимости GTK на Windows; печать из браузера — не автоматизируется для экспорта.

## R12. Аутентификация и RBAC

- **Decision**: логин/пароль (argon2), сессионный JWT в HttpOnly-cookie, зависимости FastAPI `require_role(...)`; матрица доступа роль × ресурс в `docs/architecture.md` и в контрактном тесте (SC-010).
- **Rationale**: Q&A — логина/пароля достаточно; TLS в контуре описывается, включается в nginx при внедрении.
- **Alternatives**: OAuth/2FA — не требуется.

## R13. Развёртывание офлайн

- **Decision**: Linux — `docker-compose` (postgres, backend, frontend/nginx, ollama) + образы, экспортированные `docker save` в дистрибутив; Windows без Docker — локальный запуск: PostgreSQL установлен отдельно, `uv sync`, `npm run build`, Ollama Windows. `deploy/prepare-models.*` скачивает всё в `models/` один раз (на машине с интернетом), затем папка копируется.
- **Rationale**: ТЗ: Windows 10/11 и Ubuntu; эксперты будут разворачивать локально; видео — страховка.
- **Alternatives**: только Docker — риск на Windows у экспертов; PyInstaller — торможение сборки torch.

## R14. Мониторинг в реальном времени

- **Decision**: WebSocket-каналы: `/ws/student/{user_id}` (очередь, новые карточки), `/ws/teacher/{session_id}` (агрегированное состояние всех обучаемых, push при событии + heartbeat 2 с), `/ws/board/{session_id}` (табло). Источник состояния — таблица `attempt` + in-memory кэш `session_engine`.
- **Rationale**: FR-002/018/022; локальная сеть, ≤ 20 клиентов — нагрузки нет.
- **Alternatives**: polling 2 с — допустимый фолбэк, реализован в клиенте при разрыве WS.

- Веса компонентов по умолчанию до калибровки: время 0,25; первичное решение 0,2; статусы 0,15; комментарии 0,15; поля 0,1; грамотность 0,1; многозадачность 0,05; доклад — добавляется с весом 0,1 при наличии, остальные нормируются.
