# Responders Academy — учебный эмулятор АРМ-112 для операторов ДДС

Тестовый фронтенд тренажёра диспетчера ДДС г. Москвы (хакатон «Лидеры цифровой трансформации», задача № 9):
эмуляция АРМ-112 (ПОВ-112) в изолированном локальном контуре на синтетических мок-данных.
Роли: обучающийся (диспетчер ДДС), преподаватель, администратор.

> **Учебная система. Не является рабочей системой-112.** Все данные синтетические и обезличенные
> (`spec/08-qa-decisions.md` в10): 96 учебных ситуаций из 32 билетов, 36 сценариев, классификатор ЕКП
> на 1283 записи, 24 учебные учётные записи.

Стек: Next.js (App Router) + React + TypeScript strict, архитектура Feature-Sliced Design в `src/`,
данные — собственный мок-слой `/api/mock/*` поверх JSON. Внешних сервисов, CDN и сетевых вызовов нет.

## Что реализовано

| Контур | Экраны | Кратко |
|---|---|---|
| Вход | `/login` | логин + пароль + № АРМ + шаг 2FA (заглушка, любые 6 цифр), политика входа из настроек системы, блокировка учётной записи, гварды ролей и `/forbidden` |
| Обучающийся | `/arm`, `/arm/card/[cardId]`, `/arm/phone`, `/arm/progress`, `/arm/help` | журнал карточек с расширенным поиском, поступление карточки в режиме занятия (сигнал + таймер 30 сек), полный цикл статусов реагирования с блокирующими валидациями, опросная карта по классификатору, ручной ввод с автосохранением и буферизацией при обрыве сети, софтфон B→C с ИИ-абонентом, прогресс и мок-оценка с бейджем «ИИ» |
| Преподаватель | `/teacher`, `/teacher/monitor/[studentId]`, `/teacher/scenarios`, `/teacher/scenarios/[id]`, `/teacher/session`, `/teacher/reports`, `/teacher/reports/[sessionId]` | конструктор и валидация сценариев (шаблоны + мок-генерация ИИ), учебные материалы, привязка профильных категорий, мастер занятия, управление ходом (пауза / возобновление / внеочередная выдача / завершение), read-only мониторинг экрана курсанта, журнал и карточка отчёта, правка оценки (приоритет преподавателя), обратная связь, экспорт CSV/PDF |
| Администратор | `/admin/users`, `/admin/system` | пользователи (создание, смена роли, блокировка, сброс пароля, фильтры), журнал аудита с фильтрами и пагинацией, состояние и управление сервисами, настройки с проверкой нормативов ТЗ, мониторинг нагрузки, системные журналы, статистика использования, пакетное обновление (заглушка) |
| Служебное | `/dev`, `/dev/ui` | карта всех экранов для показа и полка UI-примитивов |

Данные — через мок-API `/api/mock/*` (60 эндпоинтов, 49 Route Handlers) поверх JSON из `mocks/`;
контракты и коды ответов — [`docs/mock-api.md`](docs/mock-api.md). Мутации живут в in-memory store процесса:
перезапуск сервера возвращает исходные данные.

## Требования

| Компонент | Версия | Зачем |
|---|---|---|
| Node.js | ≥ 20.9 (движок `next`) | сборка и сервер |
| npm | ≥ 10 | установка по lockfile |
| Python 3 | ≥ 3.9 | `npm run mocks:validate` (валидатор моков; запускается в `prebuild`) |
| `bash` + `curl` | системные | сквозные скрипты `scripts/e2e-*.sh` |

Интернет нужен **только** для `npm ci`. После установки зависимостей приложение работает полностью офлайн:
внешних CDN, шрифтов и API нет (см. [`docs/LIBRARIES.md`](docs/LIBRARIES.md) и `docs/offline-check.md`).

## Установка и запуск

```bash
npm ci                 # установка строго по package-lock.json
npm run mocks:sync     # spec/mocks → mocks/, icons → public/icons (выполняется и автоматически в predev/prebuild)
npm run dev            # режим разработки: http://localhost:3000
```

Production-сборка (её же используют сквозные проверки и демо):

```bash
npm run build          # prebuild: mocks:sync + mocks:validate
npm start              # http://localhost:3000; другой порт — npm start -- -p 3130
```

### Сквозные проверки (e2e по HTTP)

Три curl-скрипта проходят пользовательские сценарии ТЗ §10 целиком — через реальные Route Handlers,
с авторизацией по cookie и проверкой изоляции данных между ролями:

```bash
npm run build
npx next start -p 3130 &     # мок-стор в памяти: перед КАЖДЫМ прогоном сервер поднимается заново
scripts/e2e-student.sh       # АРМ обучающегося: вход → журнал → занятие → цикл статусов → софтфон → оценка → 403 на чужое
scripts/e2e-teacher.sh       # преподаватель: сценарии и валидация → мастер занятия → мониторинг → отчёт → правка оценки
scripts/e2e-admin.sh         # администратор: пользователи → аудит → сервисы → настройки → мониторинг → изоляция ролей
```

Скрипты печатают `PASS/FAIL` по шагам, код возврата 0 — все шаги прошли. Базовый адрес переопределяется
переменной `BASE_URL`. **Важно:** мок-стор накапливает состояние в памяти процесса, поэтому повторный прогон
на том же сервере даст ложные расхождения — перезапустите сервер.

Браузерный e2e-раннер (`@playwright/test`) подключается в фазе 5.1 волны 5; на момент подготовки сдачи
основным сквозным контуром остаются HTTP-скрипты выше — см. «Честные ограничения».

Офлайн-приёмка (чистая машина, отключённая сеть, 0 внешних запросов) — `docs/offline-check.md`.
Шпаргалка 5-минутного демо-пути — `docs/demo-script.md`.

## Честные ограничения

Что это **не** и чего в решении нет — намеренно, по договорённостям Q&A (`spec/08-qa-decisions.md`)
и границам тестового фронта (`spec/00-overview.md`). Построчная сверка — [`docs/COMPLIANCE.md`](docs/COMPLIANCE.md).

**Мок-контур вместо бэкенда.**

- Бэкенда и БД нет: данные — JSON из `mocks/`, мутации — in-memory store процесса Next.js, перезапуск сервера
  сбрасывает состояние. Контракты (`src/shared/api/types/*`, `spec/05-data-models.md`) рассчитаны на замену
  мок-слоя реальным сервисом **без смены интерфейсов** — меняется только data-access (`spec/03-architecture.md`).
- PostgreSQL, SQL-миграции, XML-конфигурации, репликация, кластеризация и нагрузочные характеристики ТЗ §7/§9
  (отклик ≤ 2 с, ≥ 100 оп/с, ≥ 20 сессий, VoIP ≤ 150 мс) — декларации уровня бэкенда; во фронте показаны
  как мок-индикация в разделе «Система».
- TLS и защита каналов передачи — свойство контура развёртывания, в тестовом фронте не реализуются
  (`spec/01-requirements-map.md` §5).

**ИИ имитируется.**

- Все «ИИ-функции» (генерация сценариев, разбор грамматики, оценка попытки, реплики абонента, рекомендации)
  выдаёт мок-шлюз `src/shared/api/ai-gateway.ts` — адаптер с фиксированным контрактом `AiResponse`,
  рассчитанный на подмену реальным сервисом (пометка «ИИ-модуль: заменить на реальный сервис»,
  `spec/03-architecture.md`). Везде, где ответ пришёл «от ИИ», в интерфейсе стоит бейдж «ИИ» (в1, в5).
- Моделей, GPU и STT/TTS в прототипе нет: по в1 всё должно работать на CPU, поэтому тяжёлых клиентских
  вычислений в спеках и коде не закладывалось.

**Софтфон — UI-эмуляция.**

- Реального SIP/WebRTC-стека нет (в2): набор внутреннего номера, статус линии, транскрипт разговора и журнал
  вызовов эмулируются мок-слоем. Контур — только B→C (диспетчер ДДС → руководство службы); точка A
  (заявитель → 112) исключена заказчиком (в8).
- Аудиозаписей вызовов в моках нет — только текстовые транскрипты; загрузка аудио-заглушек в материалах
  сценария доступна, воспроизведения нет (в8, ТЗ §12 MP3/WAV).

**Этап 2 (в прототип не входит).**

- Мобильная адаптация: интерфейс десктопный, планшеты — десктопная версия. Адаптив опционален по ТЗ §6;
  конфликт §6 ↔ §8/§15 разобран в `spec/01-requirements-map.md`.
- Экспорт XLSX (есть CSV и PDF-печать), расширенная аналитика сверх `byStage` / `byErrorType` / `dynamics`,
  сертификаты (реализована PDF-заглушка через canvas, без шаблона заказчика и юридической силы).
- Звуковое сопровождение ограничено сигналом поступления карточки; речевого синтеза нет.

**Проверки и тесты.**

- Сквозной контур — HTTP-скрипты `scripts/e2e-*.sh` (реальные Route Handlers, cookie-сессия, проверка 403):
  они покрывают сценарии ТЗ §10, но не проверяют браузерный рендер. Браузерный e2e (Playwright) —
  инфраструктура фазы 5.1 волны 5; актуальный статус — в `docs/FINAL-GATE.md`.
- Скринкаст демо-пути (`docs/demo.mp4`, ТЗ §14/§18) **не записан** — требует захвата экрана и микрофона.
  Готов покадровый сценарий записи с репликами и таймингами:
  [`docs/demo-recording-plan.md`](docs/demo-recording-plan.md).
- Сопроводительная документация .docx/.pdf и презентация pptx/pdf — внешние треки сдачи, статус в
  [`docs/DELIVERY.md`](docs/DELIVERY.md).

**Данные.**

- Моки полностью синтетические и обезличенные (в10); выгрузок из боевой системы-112 нет и не предполагается.
- Классификатор ЕКП (1283 записи) получен конвертацией предоставленного xlsx; шрифт — системный,
  внешние шрифты не подключаются по требованию локального контура (в11).
