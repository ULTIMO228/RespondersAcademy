# Бесплатный голосовой тест

Состав: непрерывный PCM16 микрофона → локальные Silero VAD и Vosk → потоковый Qwen3.8-27B в Groq → короткие фрагменты Silero → PCM16 24 кГц в браузер. Нужны существующие extras `stt`/`tts`, локальные модели и бесплатная квота Groq. Подготовка VAD: `python -m ml.scripts.prepare_models --only vad`; модель MIT фиксируется commit и SHA-256. Отдельная GPU-аренда не требуется. Веса Qwen доступны под Apache-2.0; сервер LLM впоследствии можно заменить локальным совместимым endpoint.

Backend `.env` (не коммитить):

```dotenv
LIVE_CALLS_ENABLED=true
LIVE_CALL_REALTIME_TRANSPORT=cascade
LIVE_CALL_LLM_TRANSPORT=api
LIVE_CALL_LLM_URL=https://api.groq.com/openai/v1
LIVE_CALL_LLM_MODEL=qwen/qwen3.8-27b
LIVE_CALL_LLM_API_KEY=<ключ>
LIVE_CALL_PUBLIC_WS_URL=ws://127.0.0.1:8000/api/v1/operator112/realtime
LIVE_CALL_MAX_SEC=180
```

Сохранить существующие `JWT_SECRET` и настройки БД. У frontend: `BACKEND_URL=http://127.0.0.1:8000`, `NEXT_PUBLIC_LIVE_CALLS_ENABLED=true`. Запуск из backend: `python -m scripts.run_voice_demo` (один worker, прогревает Vosk/Silero до первого вызова); из корня: `npx next dev -p 3000`. Для другого домена/HTTPS нужен соответствующий `wss`-адрес нашего backend.

Обучающийся входит в тренировку и нажимает «Ответить на вызов». ИИ сам начинает разговор: генерирует короткое обращение по билету. Заготовленной первой записи нет. Заявителю можно задавать вопросы и перебивать его; микрофон работает во время распознавания, генерации и воспроизведения. После обновления страницы надо нажать «Подключить голос». Микрофон освобождается при закрытии, ошибке, завершении попытки или разговора.

Это составной разговорный конвейер. Конец реплики определяется на сервере: сейчас Vosk endpoint или 400 мс отсутствия речи по Silero VAD. Нулевая задержка не заявляется; длинная пауза внутри мысли может разбить вопрос. Неразборчивая речь может не распознаться; шум/эхо могут вызвать ложное перебивание — испытывать в гарнитуре. Отмена немедленно прекращает вывод и запрос LLM; уже начавшееся вычисление Silero может закончиться в фоне, но звук отменённого ответа не отправляется. В истории не сохраняются прерванные ответы целиком. Звук микрофона и ответы в этом режиме не пишутся в файлы; транскрипт — в `Attempt.calls`, `kind=realtimeCaller`.

Проверка 19.10.2026 с реальным Groq: модель доступна, первый текст короткого тестового запроса — 0,96 с. Синтетический голосовой вопрос «Служба сто двенадцать. Назовите адрес происшествия» распознан; ответ по c-010: «Москва, улица Грина. Номер дома не знаю, но там библиотека номер 193». Начало звука после конца вопроса — **1,16 с**, 28 PCM-чанков (266400 байт). Это один синтетический замер, он не заменяет проверку живого микрофона и не гарантирует такую задержку на каждом вызове.

Сквозная проверка через Next → авторизованный backend → реальный WebSocket: техническая попытка `att-011`, два распознанных вопроса, один отменённый ответ, один завершённый, 34 аудио-чанка, **0 поздних чанков после отмены**. Техническое задание `asg-008` завершено. При первом испытании найден пустой ответ Qwen на соседние user-сообщения после отмены; API теперь объединяет их без изменения сохранённой истории, добавлена регрессионная проверка. 30 затронутых backend-тестов, 42 frontend-теста, TypeScript и Ruff проходят. Общий backend-прогон до последней правки: 461 passed, 3 известных прежних failed (доступ к старым записям/контрольная сумма датасета), 1 skipped.

Скрипт без БД и микрофона: `python -m scripts.smoke_realtime_cascade`; он делает настоящий API-запрос по синтетическому билету и пишет только итоговый JSON в игнорируемый `var/`. При превышении квоты ошибка показана в софтфоне; автоматического перехода на платный тариф или записанное аудио нет.

Источники: [Groq streaming](https://console.groq.com/docs/text-chat), [бесплатные лимиты](https://console.groq.com/docs/rate-limits), [веса Qwen](https://huggingface.co/Qwen/Qwen3.8-27B), [Vosk](https://alphacephei.com/vosk/), [Silero](https://github.com/snakers4/silero-models).

После изменений 25 целевых backend-тестов и Ruff проходят.
