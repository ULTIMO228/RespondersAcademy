# Сверка соответствия ТЗ (финальная)

Задача `T5.3-05`, критерий завершения проекта `spec/000-фронт/11-implementation-plan.md` §8 п. 3.
Построчный проход матрицы трассировки [`spec/000-фронт/01-requirements-map.md`](../spec/000-фронт/01-requirements-map.md):
**требование ТЗ → статус в прототипе → где посмотреть**.

Документ описывает **тестовый фронтенд** (учебный эмулятор АРМ-112 на мок-слое). Всё, что относится
к бэкенду, инфраструктуре и контуру развёртывания, помечено как декларация — это честная граница проекта,
а не пропуск.

## Легенда статусов

| Статус | Значение |
|---|---|
| **Реализовано** | работает в приложении, проверяемо на экране и/или сквозным скриптом |
| **Реализовано (мок)** | работает в интерфейсе полностью, но источник данных/эффект — мок-слой, а не боевой сервис |
| **Декларация** | свойство бэкенда или контура развёртывания; во фронте не реализуется — показывается индикация или описано в спеке |
| **Этап 2** | осознанно вне прототипа (ТЗ §6 «опциональные» или отдельное решение), обоснование в матрице |
| **Внешний трек** | артефакт сдачи вне репозитория фронта |

Сокращения в колонке «Где смотреть»: `student` / `teacher` / `admin` — `scripts/e2e-student.sh`,
`scripts/e2e-teacher.sh`, `scripts/e2e-admin.sh`; «демо N» — шаг демо-пути `spec/000-фронт/06-user-flows.md`.

## Сводка по честности

Требования, которые **не** закрыты прототипом, — перечислены явно и без маскировки формулировками:

1. **Скринкаст `docs/demo.mp4` (ТЗ §14/§18)** — не записан, нужен захват экрана и микрофона;
   готов покадровый план ([`demo-recording-plan.md`](demo-recording-plan.md)).
2. **Мобильная адаптация (ТЗ §6/§8/§15)** — этап 2.
3. **Экспорт XLSX (ТЗ §6/§12)** — этап 2; CSV и PDF есть.
4. **Полноценные PDF-сертификаты (ТЗ §12)** — этап 2; в прототипе заглушка через canvas.
5. **Аудиозаписи вызовов MP3/WAV (ТЗ §12)** — нет; только текстовые транскрипты (согласовано в8).
6. **Расширенная аналитика сверх `byStage` / `byErrorType` / `dynamics` (ТЗ §6)** — этап 2.
7. **TLS, нагрузочные характеристики, PostgreSQL, SIP, кластеризация, репликация (ТЗ §7/§9/§12)** —
   свойства бэкенда и контура развёртывания, во фронте не реализуются (декларации).
8. **XML-форматы (ТЗ §12)** — не используются, конфигурации на JSON.
9. **Сопроводительная документация .docx/.pdf и презентация pptx/pdf (ТЗ §13/§14/§18)** —
   внешние треки, статус в [`DELIVERY.md`](DELIVERY.md).
10. **PostgreSQL 12+: миграция не исполнялась (2026-09-29, фича 002, T002).** `alembic upgrade head` создаёт 44 таблицы
    и защитные триггеры неизменяемости на SQLite (тесты `backend/tests/integration/test_alembic.py`); ветка PostgreSQL
    проверена только выпуском SQL без сервера (`alembic upgrade head --sql`, тот же файл). Причина: в среде разработки нет
    PostgreSQL, Docker-демон не запущен, локальных образов нет. Команда для проверки на PG 12+:
    `cd backend && uv sync --extra pg --group dev && DATABASE_URL=postgresql+asyncpg://arm112:arm112@localhost:5432/arm112 uv run alembic upgrade head && DATABASE_URL=… uv run alembic check`,
    затем `UPDATE`/`DELETE` утверждённой строки `ai_scenario_versions` должны падать с «approved scenario version is immutable».

11. **Двухфакторная аутентификация не реализована (2026-09-29, фича 002, решение владельца A14).** ТЗ §5 и Q&A в14
    предполагали второй фактор; в прототипе его нет: бэкенд отвергает `twoFactorCode`, `GET /auth/policy` отдаёт
    `twoFactorRequired: false`, экран входа второй шаг не показывает (ранее была заглушка «любые 6 цифр» —
    она удалена вместе с клиентским хранением сессии). Вместо неё: серверная сессия в `HttpOnly`-cookie, блокировка после
    неудачных попыток, отзыв сессий при смене пароля и блокировке. Принудительная смена временного пароля и уведомления
    также вне объёма. Расхождение со спецификацией фичи `000` (`04-pages/00-auth.md`) сохраняется намеренно.

Всё остальное из матрицы `spec/000-фронт/01-requirements-map.md` закрыто в прототипе со ссылкой на экран,
эндпоинт или шаг сквозного скрипта. Спорных пунктов «реализовано наполовину, но записано как готово»
в таблицах выше нет: частичные состояния помечены как «Частично» с указанием, чего именно не хватает.
