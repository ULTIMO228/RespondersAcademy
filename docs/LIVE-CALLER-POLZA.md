# Живой ИИ-заявитель через Polza.ai

Основной путь для финала (решение команды 19.10.2026). Обучающийся отвечает на вызов в софтфоне
режима «Специалист-112» и разговаривает с ИИ-заявителем в гарнитуре: заявитель говорит первым,
волнуется, вздыхает, сбивается, его можно перебить. Транскрипт сохраняется в попытке
(`Attempt.calls`, `kind=realtimeCaller`) без меток эмоций.

## Условие организаторов

Ответ модератора кейса 17–19.10.2026: внешний API допустим, если ту же модель потом можно
развернуть локально, «как было заявлено в ТЗ», и **без хардкода**. Поэтому:

- все модели — с открытыми весами (семейство Qwen); закрытые модели не используются;
- адрес (`POLZA_BASE_URL`), ключ и имена моделей задаются только в `backend/.env`.
  Переезд на собственный сервер — смена `POLZA_BASE_URL` на локальный OpenAI-совместимый
  сервер и имён моделей, без изменения кода.

Сервер ИИ-модуля по ТЗ — CPU от 6 ядер, 32 ГБ RAM, без GPU. Работает ли каждая модель на нём
с приемлемой задержкой, **не замерялось**: это нужно проверить отдельно.

## Как устроен разговор

```
микрофон (PCM 16 кГц) ─► Silero VAD (локально) ─► реплика оператора WAV ─► Polza /audio/transcriptions
                                                                              │
браузер ◄─ PCM 24 кГц ◄─ Polza /audio/speech ◄─ фразы ◄─ Polza /chat/completions (поток)
           (+ вставки звуков)     (инструкция эмоции)        (персона + факты билета)
```

- **VAD** (`ml/speech/vad.py`, Silero VAD, MIT, локально) определяет начало речи
  (перебивание заявителя) и конец реплики — пауза `LIVE_CALL_END_SILENCE_MS` (700 мс).
  Щелчки короче 200 мс речи в STT не отправляются.
- **LLM** получает факты билета и персону (`app/services/caller_persona.py`): короткие
  фразы, повторы, междометия, многоточия; метка настроения в начале реплики
  (`[спокойно]`, `[тревожно]`, `[паника]`, `[плачет]`) и до двух звуковых меток
  (`[вздох]`, `[всхлип]`, `[кашель]`, `[тяжело дышит]`, `[пауза]`). Успокаивается, если оператор
  уверен, и нервничает, если его долго не понимают. Факты защищены прежними правилами промпта.
- **Факты билета** подаются модели обычным текстом от лица заявителя (`facts_text`): без ключей карточки, сокращения «ул.», «№», «корп.» раскрыты словами; реплики оператора помечены как распознанная речь с ошибками; ответ — сначала по сути вопроса, не больше одного междометия (20.10.2026, на живой модели не сравнивалось).
- **Перебивание**: если заявитель встревожен (`тревожно`, `паника`, `плачет`), реплика по смыслу готовится уже после
`LIVE_CALL_BARGE_PREPARE_SEC` (1,5 с) речи оператора — распознавание и модель занимают секунды — и звучит поверх его речи
(`response.interrupting`), когда оператор говорит дольше `LIVE_CALL_BARGE_IN_SEC` (4 с; считается только речь, без пауз).
Договорил раньше — реплика не звучит и не остаётся в памяти модели. Спокойный заявитель дослушивает. Причины, по которым
перебивания не было, пишутся в лог («Перебивания не будет…», «не понадобилось», «не успело»). На живом звонке не проверено.
- **Метки оператор не видит**: `TagFilter` вырезает их из потока текста и транскрипта.
- **TTS** получает текст без меток и `instructions` с эмоцией по текущему настроению.
  Звуковая метка становится вставкой из библиотеки (`LIVE_CALL_SOUNDS_DIR/{sigh,sob,cough,breath}/*.wav`),
  а без библиотеки — произносимым междометием («Ох…», «Кхе-кхе…») или паузой.

Код: `app/services/realtime_polza.py` (наследник каскада `realtime_cascade.py`),
`app/services/caller_persona.py`; тесты — `tests/unit/test_realtime_polza.py`,
`tests/unit/test_caller_persona.py`.

## Модели (проверено на реальном API Polza 19–20.10.2026)

| Звено | Выбрано | Почему | Под условие организаторов |
|---|---|---|---|
| Распознавание | `ai-sage/gigaam-v3` | русский, 8 с речи → 2,6 с, без ошибок; `qwen/qwen3-asr-1.7b` — 33,8 с и ошибки («Гренна») | ✅ открытые веса, мала для CPU |
| Заявитель | `qwen/qwen3-30b-a3b-instruct-2507` (решение команды 20.10: семейство Qwen) | без размышления, медиана первого слова 2,2 с; на старом промпте говорил хуже GLM (см. ниже), после правок промпта 20.10 не сравнивался | ✅ открытые веса, MoE 3B активных, ~20 ГБ в 4-бит; скорость на CPU не замерялась |
| Голос | `openai/gpt-4o-mini-tts`, голос `coral` | понимает эмоцию из `instructions`; ~3 с на фразу | ❌ **в каталоге Polza нет ни одной открытой TTS** — все 12 закрытые |

Прежний выбор — `z-ai/glm-5.3-flash` + `LIVE_CALL_POLZA_REASONING_MAX_TOKENS=64`: лучшая речь (медиана 1,4 с), но веса
~328 ГБ — на сервер из ТЗ (CPU, 32 ГБ) не помещается. Qwen3-30B-A3B на старом промпте: многоточие после каждого слова,
цифры вместо слов, «рядом библиотека» вместо «в доме» — проверить заново.

Особенности API Polza, учтённые в коде:
- `/audio/speech` требует `voice` и отвечает JSON `{"audio": base64 WAV, ...}`, WAV с размером `0xFFFFFFFF` (поток);
- у GLM-5.3 размышление обязательно (по умолчанию `max`); `reasoning_effort=low` после перебивания уходил в
  сотни токенов (ответа не было, `finish=length`), `reasoning.max_tokens=64` — 14–78 токенов; вместе — пустой ответ;
- `reasoning_effort=none`, `enable_thinking=false` и аналоги у Qwen3.6-35B-A3B не выключают размышление.

## Быстрый старт: поговорить с заявителем

1. В `backend/.env` — ключ и модели (раздел «Настройка» ниже), затем из `backend/`:
   `uv sync --extra tts` и `uv run python -m ml.scripts.prepare_models --only vad`.
2. Проверка готовности (сеть не нужна, ключ не печатается):
   `uv run python -m scripts.live_caller_check`.
3. **Сначала в терминале** — быстро услышать, как он говорит, без браузера:
   `uv run python -m scripts.talk_caller` (печатаете реплики оператора, заявитель отвечает
   текстом и голосом; `--tags` — видеть метки эмоций, `--card c-050` — билет из БД,
   `--no-audio` — только текст). Звук — `var/talk-caller/NN.wav`, транскрипт — `dialogue.json`.
4. **Живой звонок в гарнитуре**: из корня `./scripts/demo-up.sh --live` — сид, бэкенд в один worker,
   сборка фронта с живым софтфоном; дальше по подсказкам в конце вывода (ivanov / student112 →
   тренировка «Режим 112» → билет → «Ответить на вызов»). Открывать именно `http://localhost:3130`.

Разговорная модель — `LIVE_CALL_POLZA_CHAT_MODEL=qwen/qwen3-30b-a3b-instruct-2507` (без `LIVE_CALL_POLZA_REASONING_*`).
Прежний `z-ai/glm-5.3-flash` (MIT; 320B/18B активных) на сервер из ТЗ без GPU не помещается,
см. риски в `spec/005-live-caller/README.md`.

## Настройка

`backend/.env` (ключ не коммитить):

```dotenv
POLZA_API_KEY=...
POLZA_BASE_URL=https://polza.ai/api/v1
LIVE_CALLS_ENABLED=true
LIVE_CALL_REALTIME_TRANSPORT=polza
LIVE_CALL_POLZA_CHAT_MODEL=<ID из каталога>
LIVE_CALL_POLZA_STT_MODEL=<ID из каталога>
LIVE_CALL_POLZA_TTS_MODEL=<ID из каталога>
LIVE_CALL_POLZA_TTS_VOICE=<голос, если модель требует>
LIVE_CALL_PUBLIC_WS_URL=ws://127.0.0.1:8000/api/v1/operator112/realtime
```

Локально нужен только Silero VAD: `uv sync --extra tts` (torch) и
`uv run python -m ml.scripts.prepare_models --only vad`. Фронтенду — `BACKEND_URL` и
`NEXT_PUBLIC_LIVE_CALLS_ENABLED=true`. Бэкенд — в один worker.

Если провайдер отвечает «неожиданный формат звука», поставьте `LIVE_CALL_POLZA_TTS_FORMAT=pcm`
(или обратно `wav`); если TTS не принимает `instructions` — `LIVE_CALL_POLZA_TTS_INSTRUCTIONS=false`.

## Проверка

1. `uv run python -m scripts.smoke_polza_caller --models` — ID моделей каталога.
2. `uv run python -m scripts.smoke_polza_caller` — одна реплика заявителя: текст с метками
   и без, задержки LLM/TTS/STT, звук `var/polza-smoke/caller.wav`. Запросы платные.
3. Ручной звонок в гарнитуре: заявитель начинает сам; вопрос «Назовите адрес» → точный адрес
   из билета; перебивание останавливает голос; в транскрипте нет меток.

## Голос: локальный Silero v5.6 (решение команды 20.10.2026)

Голоса Polza звучат с акцентом и тратят ~3 с на фразу; SpeechKit команда отклонила. Основной голос —
**Silero v5.6** локально на CPU: `LIVE_CALL_TTS_ENGINE=silero`, `LIVE_CALL_SILERO_MODEL=v5_6_ru.pt`,
`LIVE_CALL_SILERO_SPEAKER=xenia` (голоса: aidar, baya, kseniya, eugene, xenia). Модель (147 МБ) —
`uv run python -m ml.scripts.prepare_models --only tts-live` → `models/silero-live/`.
- Скорость на 4 ядрах: короткая фраза 0,14–0,18 с; холодный старт — загрузка 12 с + первая озвучка 5 с,
  поэтому бэкенд прогревает голос в фоне при старте, а звонок ждёт прогрева до «ready».
- Эмоций как таковых нет: настроение → темп и высота (SSML prosody); интонация вопроса/восклицания — автоматически.
- Лицензия Silero — CC BY-NC: для хакатона подходит, для коммерческого внедрения нужна лицензия Silero.
- Реальный звонок: приветствие через ~2,5 с после соединения; от конца реплики оператора до голоса ~5 с
  (распознавание Polza ~2,4 с, ответ GLM ~1,5 с, голос 0,1–1 с). Дальше ускорять — локальным распознаванием.

### Ускорение хода (20.10.2026, не замерено на живом звонке)

- **Раннее распознавание**: реплика уходит в STT уже после `LIVE_CALL_EARLY_COMMIT_MS` (250 мс) тишины, а не после
  всей паузы конца реплики (700 мс). Отвечать заявитель начинает, только когда пауза дошла до 700 мс; если оператор
  продолжил фразу — ранний результат выбрасывается и распознаётся вся фраза (лишний платный запрос). Ожидаемый выигрыш — ~0,45 с.
- **Короткая первая фраза**: первая фраза ответа уходит в Silero по запятой (не раньше 20-го символа), остальные — по
  предложениям. Адрес, номера и телефоны по запятой не режутся. Выигрыш — время дописывания первого предложения и его озвучки.
- **Замер в логе** (`app.services.realtime_polza`, уровень INFO, без текста реплик): «распознавание готово через N мс
  после конца речи», «первое слово через N мс», «первый звук через N мс». По ним видно, какое звено тормозит.
- Дальше: локальное распознавание GigaAM-v3 на CPU (−~2 с, нужен доступ к huggingface.co), меньше
  `LIVE_CALL_POLZA_REASONING_MAX_TOKENS` (32 вместо 64 — проверить, не теряется ли точность).

## Реальный звонок (20.10.2026, облачная среда, Polza)

WebSocket как из браузера → бэкенд → Silero VAD → GigaAM → GLM → gpt-4o-mini-tts; «оператор» — синтезированные вопросы 16 кГц.
- Приветствие: первый звук через ~4–5 с после соединения.
- После реплики оператора: VAD 0,7 с + распознавание ~2 с → сразу отклик «Да-да…»; ответ звучит ещё через ~3–7 с
  (первое слово модели 1,4–5,5 с в зависимости от загрузки провайдера + озвучка ~3 с). Узкое место — TTS через агрегатор.
- Перебивание работает; перебитая реплика остаётся в памяти модели (иначе заявитель здоровался заново).
- Сбой потока до первого слова повторяется один раз; оборванный на середине ответ не рвёт звонок; причина — в логе сервера.
- Пример разговора (101 с) собирается `scripts/talk_caller.py`-конвейером; транскрипт заявителя без меток.

Открыто: перебитые реплики заявителя не сохраняются в транскрипт попытки (логика ветки AMIR) — для разбора
преподавателем их стоит сохранять с пометкой «прервано»; решение за командой.

## Состояние на 19.10.2026

- Сквозной звонок проверен на подменённом провайдере (локальный OpenAI-совместимый фейк):
  бэкенд + WebSocket как из браузера + настоящий Silero VAD на записи речи 16 кГц →
  приветствие заявителя, одна реплика оператора распознана, ответ озвучен, транскрипт
  (заявитель / оператор / заявитель) сохранён в попытке без меток.

- Юнит-тесты на подменённом HTTP прошли (STT, TTS, эмоции, метки, VAD-нарезка, ошибки провайдера).
- **Реальные запросы к Polza не выполнялись**: из среды разработки polza.ai недоступен, ключа нет.
  Задержка, качество голоса и эмоций, корректность ID моделей — не проверены.
- Библиотека неречевых звуков не собрана: без неё вздохи звучат междометиями.
