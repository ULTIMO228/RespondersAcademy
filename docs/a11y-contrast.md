# Замер контраста по дизайн-токенам (T5.2-01)

Дата замера: 2026-09-20. Источник значений — `src/shared/ui/styles/vars.css` и файлы
`tokens-journal.css` / `tokens-card.css` / `tokens-softphone.css` / `tokens-teacher.css` /
`tokens-admin.css` (единственное место с hex в проекте, `spec/000-фронт/10-code-rules.md` §5).

## Как считалось

Формула WCAG 2.1: относительная яркость `L = 0.2126·R + 0.7152·G + 0.0722·B` (каналы
линеаризованы: `c ≤ 0.03928 → c/12.92`, иначе `((c+0.055)/1.055)^2.4`), контраст
`(L_св + 0.05) / (L_тёмн + 0.05)`. Полупрозрачные токены (`rgba(…)`) сведены на свой фон
альфа-композицией. Значения `var(--…)` раскрыты рекурсивно с учётом темы
(`[data-theme="light"]` / `[data-theme="dark"]`).

Пороги: обычный текст — 4.5:1 (AA) / 7:1 (AAA); крупный текст (≥ 18px) — 3:1 (AA) / 4.5:1 (AAA);
не-текстовые элементы (маркеры, иконки, фокус-кольцо) — 3:1 (WCAG 1.4.11).

Замер сделан скриптом по токенам, а не по скриншотам: важна именно пара токенов, а не
антиалиасинг конкретного рендера.

## Главное

**Палитра НЕ менялась и меняться не будет.** Это осознанное отступление, а не недосмотр:
`spec/000-фронт/07-design-guidelines.md`, ЖЁСТКОЕ ПРАВИЛО №1 (HARD ULTRA) — тренажёр обязан быть
неотличим от боевого ПОВ-112/АРМ-112, эксперты сверяют экраны с рабочей системой; перекраска
«ради контраста» прямо запрещена («НЕ ДЕЛАЕМ: … смену палитры, в том числе перекраску “для
контраста”»). Статусная семантика (красный / жёлтый / оранжевый / зелёный / серый) и цветокод
служб (01 / 02 / 03 / 04 / ЖКХ / АТ / ЕДДС / 112) — канон АРМ ЕДДС, их значения не трогаем.

Итог замера: **80 пар, 48 проходят свой порог AA, 32 (40 %) — ниже**. Минимум 1.35:1, максимум 18.88:1.

Доступность закрывается НЕ цветом, а мерами, не меняющими вид:

| Мера | Где сделано |
|---|---|
| Двухцветное фокус-кольцо (белое + синее, токен `--focus-ring`) | `src/app/styles/global.css`, T5.2-02 |
| Клавиатурный порядок и горячие клавиши | T5.2-02 |
| `prefers-reduced-motion` — мигание новой карточки → статичный маркер | `src/entities/incident/ui/IncidentRow.module.css`, T5.2-03 |
| Текстовые дубли состояний (статус словом рядом с цветом, `aria-label`, `title`) | T5.2-05, T5.2-08 |
| RU-даты и 24-часовое время | `src/shared/lib/format/dateTime.ts`, T5.2-04 |

Единственная правка, сделанная по итогам замера, — **фокус-кольцо**: одиночное синее кольцо на
графитовых поверхностях давало 1.35–2.78:1, поэтому глобальный `:focus-visible` переведён на уже
существовавший токен `--focus-ring` (белое кольцо + синее). Новых цветов не добавлено, статика
экранов не изменилась: кольцо видно только при навигации с клавиатуры.

## Пары ниже порога: почему не правим

Сгруппировано по причине. Во всех случаях решение — «оставить цвет, усилить не-цветовые признаки».

### 1. Канон статусной палитры и цветокода служб (не подлежит изменению)

`Реагирование` (зелёный, 3.46:1), `Закрыта` (серый, 2.65:1), кружки служб `04` (жёлтый, 1.65:1),
`ЕДДС` (оранжевый, 2.45:1), `ЖКХ` (3.46:1), ячейка «важное» (оранжевая, 3.24:1).
Это цвета боевой системы (`spec/000-фронт/07-design-guidelines.md`, «Цветовая семантика»,
`research/arm-112/screenshots/arm-edds/page-41/42.png`). Компенсация: статус **всегда**
продублирован словом («Реагирование», «Закрыта»), кружок службы — подписью службы рядом,
иконочные кнопки — `aria-label` (T5.2-08). Цвет нигде не является единственным носителем смысла
(WCAG 1.4.1 выполняется).

### 2. Акценты ПОВ-112: синий `#157dbd` и оранжевый `#ec653b`

Синий на белом — 4.47:1 (не дотягивает до 4.5:1 на 0.03), оранжевый на белом — 3.24:1.
Это фирменные акценты интерфейса (выбранные элементы, «просмотр», история службы / «создать
карточку», «сохранить», ЧП). Затрагивает: активную вкладку, попап истории службы, кнопку
«Сохранить», бейдж «ИИ» (3.79:1), бейдж роли «Администратор», heatmap-максимум, название службы
в контактах. Компенсация: все эти элементы — крупные заливки с белым текстом ≥ 13px, у всех есть
текстовая подпись; кнопки имеют состояния `:hover`/`:focus-visible`/`:disabled`, различимые без цвета.

### 3. Приглушённый текст `--color-ink-soft` (#8a9095): 2.81–3.23:1

Третичные подписи карточки (мелкий кегль под полями). Это плотность оригинала, а не
декоративный «серый на сером». Компенсация: третичным цветом набраны только дубли информации,
которая есть рядом обычным `--color-ink`/`--color-ink-muted` (5.46–6.28:1, AA ✅).

### 4. Тёмный экран «Поиск происшествий» (`--color-graphite-500`, #838f97)

Заголовки колонок и текст пустого состояния — `--color-light-muted` на фоне экрана: 2.26:1;
ссылка «Повторить» в пустом состоянии — 1.35:1. Фон экрана снят пипеткой с референса
(`images/p12_Image66.png`, `ДДС_image2–5`). Компенсация: сами строки ленты лежат на
`--color-graphite-900` и дают 10.50:1 (AAA) — читается именно содержимое; шапка колонок
дублируется порядком колонок, фиксированным спекой; ссылка «Повторить» получила видимое
двухцветное фокус-кольцо (T5.2-02) и доступна с клавиатуры.

### 5. Экран входа (голубое небо `#84b8d7`)

Белый текст на небе — 2.14:1, приглушённый белый — 1.93:1, кнопка «Вход» — 3.95:1.
Экран воспроизводится 1:1 по `Источники/скриншоты_из_docx/ДДС_image1.png`. Компенсация:
поля ввода и кнопка — крупный кегль (18px, 16px), подписи полей продублированы `aria-label`,
фокус-кольцо белое (`AuthForm.module.css`), ошибки входа выводятся текстом, а не цветом.

### 6. Прочее

- «Плитка не подключён» (2.79:1) — серый «выключенного» элемента ПОВ-112; рядом всегда есть
  текст «не подключён».
- Неактивная кнопка (3.92:1) — `:disabled` дополнительно снимает курсор и `pointer-events`,
  состояние читается не только цветом.
- Таймер сверх норматива (3.48:1 на панели) — крупный моноширинный кегль (22px), порог для
  крупного текста 3:1 пройден; дублируется красной рамкой строки и маркером нарушения.

## Что проверить глазами (координатору)

Замер — по токенам; в браузере остаётся сверить:

1. `/arm` и `/arm/card/c-095` против референсов `images/p12_Image66.png`, `images/p23_Image108.png` —
   расхождений по цвету быть не должно (палитра не менялась).
2. Фокус-кольцо на тёмной ленте и на панели служб — белая подложка должна быть видна,
   плотность таблицы не должна «поехать».
3. Режим высокой контрастности Windows: `outline` остаётся, `box-shadow` не рисуется — кольцо
   не должно пропасть полностью.

## Воспроизведение замера

Скрипт разовый, в репозиторий не кладётся (`spec/000-фронт/12-tasks.md` T5.2-01: файл задачи — только

(чего по HARD-правилу не предполагается) замер повторяется по тем же парам.

## Платформа-обложка (фича 002, T056, 2026-09-29)

Платформа (`/login`, `/student/*`, `/reference`, `/account/*`) использует собственные токены `--pf-*`
(`src/shared/ui/styles/tokens-platform.css`) и **проходит WCAG 2.2 AA**; выше описан симулятор `/arm/*` — его палитра
по правилу №1 не менялась.

- **Замер по токенам** — автотест `src/shared/ui/styles/tokens-platform.test.ts`: 27 пар «текст/фон» ≥ 4,5:1 и 11
  нетекстовых пар (граница поля, кольцо фокуса, линии графиков) ≥ 3:1; таблица значений — `docs/platform-design.md`.
- **Найдено и исправлено при проектировании**: оранжевый АРМ `#ec653b` с белым текстом даёт 3,24:1 → кнопка действия
  `#c8461d` (4,83:1); синий `#157dbd` — 4,47:1 → ссылки `#0f6aa3` (5,82:1); синий фокус на графите оболочки — 2,78:1 → в оболочке
  кольцо белое. Оригинальные оранжевый и синий остаются только у графики (порог 3:1), не у текста.
- **Замер в браузере** (скрипт обходит отрисованные тексты 1280×800, считает контраст вычисленных цветов; по страницам платформы
  обучающегося — 0 текстов ниже порога, 36+22+23+26+27+31+30 текстовых узлов). Тот же прогон на страницах преподавателя и
  администратора показал контраст ниже AA — это прежние экраны на палитре АРМ (оранжевая кнопка 3,24:1, синяя 4,47:1, серый
  текст 2,79:1 и т. п.); они переоформляются в волне W3 (T051, T054) и в этот замер платформы не входят.
