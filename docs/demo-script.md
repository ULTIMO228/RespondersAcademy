# Шпаргалка докладчика: демо-путь защиты (≤ 5 минут)

Источник сценария — `spec/06-user-flows.md` «Демо-путь для защиты» (ТЗ §14, Q&A в12).
Автоматический аналог того же пути — `e2e/demo-path.spec.ts` (`npm run e2e`).

## Подготовка (до выхода к экрану)

1. `npm ci` → `npm run build` → `npm start` (или `npx next start -p 3140`). Мок-стор живёт в памяти
   процесса: **сервер поднимается заново перед показом**, иначе карточка c-095 уже отработана прошлым
   прогоном и статусы не повторятся.
2. Два окна браузера рядом: слева — преподаватель, справа — курсант (разные профили/окна, чтобы сессии
   не перетирали друг друга). Оба окна — 1920×1080, масштаб 100 %.
3. Демо-учётки (подсказки видны на `/login`, блок «Тестовые учётные записи»):
   - преподаватель — `morozova` / `teacher112` / АРМ **21**;
   - курсант демо-пути — `tarasova` / `student112` / АРМ **14** (Тарасова Юлия Олеговна, группа ДДС-02);
   - администратор (в демо-путь не входит) — `admin` / `admin112` / АРМ **24**.
   Код 2FA — **любые 6 цифр** (например, `123456`).
4. На `/teacher` завершить занятие, оставшееся от предыдущего показа («Завершить занятие» → «Завершить»),
   чтобы дашборд показывал именно новое занятие. Проверка: на экране «Занятие не идёт».
5. Открыть запасной скринкаст в соседней вкладке (см. «Запасной ход»).

## Фактические тайминги репетиций

Оба прогона — «робот-репетиция» `npm run e2e` (Playwright, тот же путь в браузере), секундомер — таймеры
Playwright. Живого прогона со звуком/скринкастом не делалось (см. «Что не проверено»).

| Весь прогон `npm run e2e` (16 тестов, включая smoke) | 3 мин 12 с | 3 мин 13 с | — |

Шаг 4 занимает ровно три минуты потому, что вторая карточка модуля выдаётся через норматив полной
отработки (180 сек) после старта занятия курсанта. В живом показе это время не простаивает: оно целиком
уходит на шаги 3б–3г и на мониторинг — вторая карточка появляется примерно на 4:10, внутри бюджета
3:30–4:30. Поэтому ключевое правило темпа: **курсант должен нажать «Билет 32» не позже 1:10**.

## Запасной ход при сбое

1. **Не поднялся сервер / белый экран.** Перейти на заранее открытую вкладку со скринкастом демо-пути и
   комментировать по этой же таблице. Параллельно перезапустить `npm start` — мок-стор поднимется чистым.
2. **Карточка не пришла курсанту.** Причина почти всегда одна: занятие стартовало без нужных категорий
   или выбран курсант не той службы. Преподаватель на `/teacher` → «Выдать карточку курсанту» →
   «Выдать сейчас». Если не помогло — скринкаст.
3. **Статус не сохраняется.** Проверить, что карточка не закрыта («Работы завершены» закрывает её для
   редактирования). Открыть вторую карточку занятия и показать цикл на ней.
4. **Звонок «висит».** Нажать «Завершить», повторить набор 301. Реплики ИИ-абонента детерминированы, при
   повторе те же.
5. **Отчёт пустой** («нет данных по попыткам»). Значит попытка не закрыта: вернуться к карточке курсанта и
   довести статус до «Работы завершены», затем «Сформировать отчёт» заново.
6. **Сеть пропала.** Ничего не делать: контур локальный, внешних запросов нет (см. `docs/offline-check.md`).

## Что не проверено

- Живой прогон с секундомером в руках человека и запись скринкаста со звуком (ТЗ §14, Q&A в12) — не
  выполнялись: нужен человек и звукозапись. Тайминги выше получены автоматическим прогоном того же пути.
- PDF выгружается системной печатью браузера («Сохранить как PDF»), поэтому в автоматическом прогоне
  проверяется вызов печати и непустая печатная страница, а не файл из диалога сохранения.
