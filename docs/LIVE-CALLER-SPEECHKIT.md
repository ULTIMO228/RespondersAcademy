# Живой заявитель: SpeechKit + Groq

Согласовано пользователем 19.10.2026. Облачные вызовы разрешены для демонстрации.
Факты билета синтетические. SpeechKit — коммерческий облачный API; локальная поставка
Hybrid требует отдельного договора и не считается установленной/проверенной.

## Подключение

1. В [консоли Яндекса](https://console.yandex.cloud/) выберите облако и каталог.
   Нужен активный платёжный аккаунт либо действующий пробный грант.
2. Identity and Access Management → Сервисные аккаунты → Создать.
   Имя `lct-voice`, роли на каталог `ai.speechkit-stt.user` и `ai.speechkit-tts.user`.
3. Откройте сервисный аккаунт → Создать новый ключ → Создать API-ключ.
   Области: `yc.ai.speechkitStt.execute`, `yc.ai.speechkitTts.execute`.
   Сохраните секретную часть, а не идентификатор ключа.
4. В **игнорируемый** `backend/.env` добавьте:

```dotenv
SPEECHKIT_API_KEY=секретная_часть_ключа
SPEECHKIT_FOLDER_ID=идентификатор_каталога
SPEECHKIT_TTS_MODEL=livetts
SPEECHKIT_VOICE=denis
SPEECHKIT_ROLE=casual
```

5. В `backend/` установите extra, сохранив используемые локальные extras:

```powershell
uv sync --extra speechkit --extra tts --extra stt
.venv/Scripts/python.exe -m scripts.smoke_speechkit
```

Скрипт делает небольшие **платные** запросы: синтез вопроса, самостоятельно
сгенерированное приветствие, распознавание вопроса и ответ с адресом. Используются
реальные SpeechKit и LIVE_CALL_LLM_*, без микрофона и без аудиофайлов. Результат
успешного теста — `backend/var/speechkit-smoke.json`; это проверка облачных сервисов,
а не доказательство качества живого разговора с человеком. Без ключа скрипт
завершается с пояснением, не обращаясь в облако.

6. После успешного теста добавьте `LIVE_CALL_REALTIME_TRANSPORT=speechkit` и
перезапустите backend (`python -m scripts.run_voice_demo`). Остальные LIVE_CALL_*
и NEXT_PUBLIC_LIVE_CALLS_ENABLED остаются из текущего рабочего конвейера.
Один backend worker, существующая БД, без повторного сидинга.

Для `general` задайте все три параметра явно: `SPEECHKIT_TTS_MODEL=general`,
`SPEECHKIT_VOICE=alexander`, `SPEECHKIT_ROLE=neutral`. Голоса general и LiveTTS
несовместимы. Нет автоматической подмены голоса/модели/поставщика при ошибке.

## Работа

Микрофон → наш авторизованный WS (PCM16, 16 кГц) → STT v3 RecognizeStreaming →
потоковый Groq/Qwen → TTS v3 StreamSynthesis → PCM16 24 кГц → Web Audio браузера.
Одна STT-сессия на звонок, одна TTS-сессия на ответ; текст поступает в синтез до
завершения генерации LLM. Локальный Silero VAD только обнаруживает начало речи
для перебивания; конец высказывания приходит от SpeechKit (EOU).
Несколько final до EOU объединяются; поздняя нормализация не вызывает повторного ответа.
Отмена закрывает TTS RPC; микрофон продолжает работать. Ключи только на backend.

UI/билеты/права и сохранение расшифровок используют существующий realtime-контракт.
Статус configured подтверждает наличие конфигурации/зависимостей, но не оплату или
валидность ключа. Ошибки ключа, квот и связи выводятся без сырого ответа провайдера.
Без настройки Яндекса текущий режим `cascade` продолжает работать до явного переключения.
Default лимит звонка 180 секунд; STT RPC ограничен 295 секундами даже при большем
LIVE_CALL_MAX_SEC (следующее соединение требует повторного подключения).

## Проверки и ограничения

### Поправки после ручной пробы

Пользователь отметил недостаток интонации и слабые ответы. Проверены прежние записи:
`backend/data/demo_audio/c-{010,049,050}-elevenlabs.mp3` — ElevenLabs, но модель,
voice_id и настройки генерации в репозитории отсутствуют. Живой ElevenLabs не
подключён: обычный API не подтверждает локальную доступность эмоциональных моделей.
В публичной private deployment документации перечислены TTS v2/v2.5; доступность
v3/v4 с эмоциональными audio tags для изолированной установки не установлена.
Записи остаются ориентиром, в потоковый разговор не подмешиваются.

Обновлены инструкции заявителю: понимать составные вопросы и просьбы оператора,
исправлять неверные сведения, различать неизвестное и отсутствие пострадавших,
говорить живым языком без чтения карточки и служебных ремарок. Модель остаётся Qwen.
`scripts/eval_live_caller.py` сравнил Qwen3.8-27B и gpt-oss-120b на 8 вопросах по c-010:
у gpt-oss был ошибочно принят номер библиотеки 193 за номер дома. Это маленькая
ручная проба, а не общий рейтинг моделей; данные — `var/live-caller-dialogue-eval.json`.

TTS получает предложения целиком вместо разрезания каждых 100 символов, точки в
адресных сокращениях и дробных числах не считаются концом предложения на границе
токенов. Force synthesis отправляется только в конце ответа. Проверены 39 целевых
тестов и Ruff. Реальный повторный smoke с новой передачей текста: 38 аудиочанков,
peak 24280, первое аудио через 1,35 секунды, вопрос и ответ с адресом подтверждены.
Последний результат перезаписывает `var/speechkit-smoke.json`.
Это сохраняет интонационный контекст; улучшение выразительности на слух и
крик/плач, сравнимые с ElevenLabs, пока не подтверждены.

Реальная проверка 19.10.2026 выполнена с предоставленным пользователем ключом:
`livetts`, голос `denis`, амплуа `casual`; приветствие сгенерировано без входного
аудио оператора, вопрос «Назовите адрес происшествия» распознан, ответ содержит
синтетический адрес. 47 аудиочанков, непустой PCM (peak 25124), первый звук через
0,93 секунды после session.update в этом единственном прогоне. Аудио в файлы не
сохранялось; результат — `backend/var/speechkit-smoke.json`. Это не замер p95 и не
подтверждение качества с реальной гарнитурой.

Дополнительно проверен реальный авторизованный WS через frontend (задание asg-009):
входящий синтетический вопрос прерывает первый ответ (1 cancelled), распознаётся
«Повторите адрес происшествия», затем приходит новый ответ. 43 аудиочанка, 0 поздних
чанков отменённого ответа. Результат — `backend/var/speechkit-relay-smoke.json`.

Целевые проверки SpeechKit/cascade/relay/контрактов: 37 passed. Полный backend до
двух дополнительных проверок сохранения безопасных сообщений об ошибках:
474 passed, 3 failed, 1 skipped. Сбои прежние: две проверки доступа к аудиозаписям
`test_ready_applicant_audio_is_playable_from_recordings` и хеш датасета
`test_release_invariants`. Ruff прошёл.

`tests/unit/test_realtime_speechkit.py` использует настоящие protobuf SDK и локальный
gRPC-сервер: непрерывный вход, EOU, живой выход до конца текста, auth/quota/network,
закрытие RPC при перебивании. Внешние запросы тесты не выполняют; с отсутствующим
extra модуль тестов пропускается. Облачная проверка отдельно требует ключа.
Качество русского голоса/распознавания и задержка должны оцениваться на живых диалогах.
