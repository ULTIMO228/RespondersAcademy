# ФИЧИ — РОЛИ И СЦЕНАРИИ (матрица функций)

Матрица «Обучающийся 1 | Обучающийся 2 | Препод | Админ» с листа 2 рукописных
заметок. Две колонки обучающихся — это **две подроли обучаемого** (уточнение
автора заметок): **Оператор 112** и **Диспетчер ДДС**. Роли приведены к ролевой
модели заказчика (Q&A в.14: `admin` / `teacher` / `student`; схема `users` —
[МОКИ-ДАННЫЕ](../../Фронт/МОКИ-ДАННЫЕ.md) п. 1.1). Контекст подролей (точки A/B/C) —
в [00-ОБЩАЯ-КОНЦЕПЦИЯ](00-ОБЩАЯ-КОНЦЕПЦИЯ.md), раздел 2.

---

## 1. Обучаемый — подроль «Оператор 112» (колонка «Обучающийся 1»)

| № | Функция | Содержание |
|---|---------|-----------|
| 1.1 | Аудио (записи разговоров) | Работа с записями разговоров: TTS на CPU недоступен, поэтому голосовой контур строится на готовых записях (способ работы с ними — открытый вопрос 3 в [03-ОТКРЫТЫЕ-ВОПРОСЫ](03-ОТКРЫТЫЕ-ВОПРОСЫ.md)). Прочтение заметки «Аудио-генерация (запись)» уточнено автором. |
| 1.2 | Заполнение карточки | Приём вызова и заполнение карточки по образцу АРМ-112: блок «Адрес», данные заявителя (ФИО, статус), «Описание со слов заявителя» (лимит 1999 символов), «Добавить тип происшествия» + опросная карта-теги, определение набора вызываемых служб (автоподбор по классификатору с возможностью ручной правки). Структура полей — единый документ п. 1.4, п. 3.4–3.9. |
| 1.3 | Подготовка к экзамену («пред экзамена») | Прочтение заметки «Этап 2 … реп. экзам» уточнено автором как «пред экзамена»: тренировочный прогон перед экзаменом по выбранным преподавателем билетам с фиксацией метрик, без экзаменационных ограничений. |

## 2. Обучаемый — подроль «Диспетчер ДДС» (колонка «Обучающийся 2»)

| № | Функция | Содержание |
|---|---------|-----------|
| 2.1 | Детекция каскадных ошибок («эффект домино») | Прочтение заметки уточнено автором: **эффект домино** — ошибки накладываются друг на друга; система должна понимать, когда ошибки есть. Детальное описание — [01-ФИЧИ-ПЛАТФОРМЫ](01-ФИЧИ-ПЛАТФОРМЫ.md), фича 9. |
| 2.2 | Репетиция экзамена | Экзаменационный режим подроли ДДС: получение карточки от «оператора 112», валидация данных, прохождение полного жизненного цикла, звонки службам (B→C); подсказки отключены, фиксируются метрики и итоговый отчёт (Q&A в.16). |
| 2.3 | Полный жизненный цикл карточки | Получение заполненной карточки → первичный статус (Принята/Не принята, с номером наряда и комментарием) → Начало реагирования → Прибытие → Проведение работ → Работы завершены / Отказ от выполнения работ. Обязательный полный цикл — Q&A в.6; статусная модель — МОКИ-ДАННЫЕ п. 2.1–2.2; голосовой контур B→C — Q&A в.8. |

*(Пункты 2.2 и 2.3 сгруппированы: «Репетиция экзамена» в заметках обозначает режим, «полный цикл» — его содержание по Q&A в.6.)*

## 3. Преподаватель (teacher)

| № | Функция | Содержание |
|---|---------|-----------|
| 3.1 | Просмотр аналитики | Результаты курсантов: отчёты, динамика, отклонения от нормативов; утверждение оценок (Q&A в.14). |
| 3.2 | Выбор билетов | Сборка занятий и экзаменов из 96 готовых билетов; задание очереди карточек сценария (МОКИ-ДАННЫЕ п. 1.4, п. 4). |
| 3.3 | Создание билетов (в т.ч. с ИИ) | Авторинг новых сценариев; генеративный ИИ — на продвинутом уровне, под контролем преподавателя (Q&A в.3). Связка с «Контролем генерации сценариев» ([01-ФИЧИ-ПЛАТФОРМЫ](01-ФИЧИ-ПЛАТФОРМЫ.md), фича 8). |
| 3.4 | Просмотр сложных ситуаций | Мониторинг класса в реальном времени: экраны курсантов в локальной сети, вмешательство при необходимости; контроль карточек-усложнений ([др.регион], [03 не тр.], суицидальные СМС, угроза взрыва — МОКИ-ДАННЫЕ п. 4). «Удалённый контроль» — Q&A в.16. |
| 3.5 | Заметки на карточке | Методические комментарии преподавателя на карточке курсанта; арбитраж расхождений с оценкой ИИ, материал для дообучения (Q&A в.3, в.7). |

## 4. Администратор (admin)

| № | Функция | Содержание |
|---|---------|-----------|
| 4.1 | Создание аккаунтов и ролей | Управление пользователями: 3 фиксированные роли, учебный класс (номера АРМ 1..N), логин/пароль + 2FA (Q&A в.14). |
| 4.2 | Мониторинг и отчётность | Общесистемный мониторинг занятий и сводные отчёты по классу. |
| 4.3 | Безопасность | Локальный изолированный контур по требованиям ИБ (Q&A в.7, в.11); раздел «Аудит» по образцу реального АРМ (единый документ, п. 3.16). |
| 4.4 | Выбор ИИ-моделей (масштабирование) | Прочтение заметки «Выбор моделей (все от ИИ)» уточнено автором: закладываем **возможность масштабирования** — выбор и добавление моделей (STT/LLM) под рост нагрузки; базовый контур работает на CPU (Q&A в.1). |
