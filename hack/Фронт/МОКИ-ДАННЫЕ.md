# МОКИ-ДАННЫЕ (JSON) — спецификация и датасеты для симулятора АРМ-112

Назначение: дать команде фронта всё для генерации JSON-моков коллекций
`users`, `reference`, `cards`, `scenarios`, `sessions`, `reports`.
Источники: классификатор `Классификатор_происшествий_v_046_24_корректировка_МВД_+_Департамент.xlsx`
(актуальная версия, см. п. 2.6), `Билеты- задачи по C 112 . АГС_ГСИ.pdf` (32 билета × 3 вызова = 96 ситуаций),
единый документ АРМ-112 (разделы 2–3), Q&A заказчика (раздел 6 единого документа).

Все ФИО, телефоны и адреса в билетах уже обезличены — можно свободно показывать
в прототипе и презентациях (подтверждено заказчиком, Q&A вопрос 10).

## 1. Структура коллекций и схемы

### 1.1 `users` — пользователи (роли по Q&A вопрос 14)

```ts
type Role = 'admin' | 'teacher' | 'student';

interface User {
  id: string;              // "u-001"
  login: string;           // латиница, без пробелов
  fullName: string;        // ФИО
  role: Role;
  armNumber: number;       // номер рабочего места (на экране карточки "Опер., АРМ 4")
  isActive: boolean;
}
```

Сид: 1 admin, 2–3 teacher, 10–20 student (номера АРМ 1..N соответствуют учебному классу).

### 1.2 `reference` — справочники (см. п. 2)

```ts
interface Reference {
  ddsStatuses: DdsStatus[];        // статусы жизненного цикла карточки у ДДС
  serviceStatuses: ServiceStatus[];// статусы служб (таймлайн)
  callerStatuses: string[];        // статус заявителя
  channels: string[];              // канал связи
  services: Service[];             // службы (из колонок классификатора)
  incidentGroups: IncidentGroup[]; // 119 групп, иерархия Г/п1/п2/п3
  classifierRows: ClassifierRow[]; // строки матрицы признаки→службы (см. 2.6)
}
```

### 1.3 `cards` — учебные карточки вызовов (96 штук, из билетов, см. п. 3)

```ts
interface IncidentCard {
  id: string;              // "c-001"…"c-096" (порядок = билет.номер)
  ticketNo: number;        // 1..32 — номер билета
  situationNo: 1 | 2 | 3;  // номер ситуации в билете
  group: string;           // группа происшествия (из классификатора, см. п. 2.5)
  summary: string;         // текст ситуации (фабула)
  address: string;         // адрес (как в билете; часть — с уточнением "при уточнении…")
  addressRefined?: string; // уточнённый адрес (если в билете есть)
  caller: { name: string; phone: string; status?: CallerStatus };
  victims?: { count: number; note?: string };
  noAmbulance?: boolean;   // пометка «03 не требуется»
  crossRegion?: boolean;   // вызов из другого региона (уточнить/переадресовать)
  expectedServices: string[]; // ЭТАЛОН: службы по классификатору (заполняется из матрицы 2.6)
  expectedTags: string[];  // ЭТАЛОН: теги опросной карты (112-Признак.1/2/3)
}
```

### 1.4 `scenarios` — сценарии занятий

```ts
interface Scenario {
  id: string;              // "s-001"
  title: string;           // напр. "Пожар-квартира. Базовый"
  level: 'beginner' | 'advanced';  // шаблон / генеративная вариация (Q&A вопрос 3)
  cardIds: string[];       // очередь карточек (1–3+, с многозадачностью — Q&A вопрос 6)
  timeNorms: { primaryReactionSec: 30; fullProcessingSec: 180 }; // нормативы заказчика
  hints: boolean;          // подсказки для новичков (Q&A вопрос 4)
  callTarget?: string;     // внутренний 3–4-значный номер службы для голосового контура B→C
}
```

### 1.5 `sessions` — учебные сессии

```ts
interface Session {
  id: string;
  studentId: string;       // users.id, роль student
  teacherId: string;
  scenarioId: string;
  startedAt: string;       // ISO datetime
  cardEvents: CardEvent[]; // хронология действий
}
interface CardEvent {
  cardId: string;
  openedAt: string;        // момент открытия карточки
  primaryReactionMs: number; // факт норматива 30 сек
  statuses: { ddsStatus: DdsStatus; at: string; comment?: string; dutyNumber?: string }[];
  servicesCalled: string[];  // каким службам звонил диспетчер (контур B→C)
  completedAt: string;
  fullProcessingMs: number;  // факт норматива 3 мин
}
```

### 1.6 `reports` — отчёты (состав задан заказчиком, Q&A вопрос 16)

```ts
interface Report {
  sessionId: string;
  student: { fullName: string; armNumber: number };
  timeMetrics: { stage: string; normMs: number; factMs: number; deviationMs: number }[];
  grammarErrors: { cardId: string; field: string; fragment: string; type: 'spelling' | 'syntax' }[];
  errors: { cardId: string; type: string; severity: 'critical' | 'major' | 'minor' }[];
  score: number;           // интегральный балл (веса определяет команда, Q&A вопрос 5)
  charts: { byStage: unknown; byErrorType: unknown; dynamics: unknown };
}
```

## 2. `reference` — содержимое справочников

### 2.1 Статусы ДДС (жизненный цикл карточки у диспетчера)

Из скриншотов ДДС (единый документ, п. 2.1) и Q&A вопроса 6 — **полный цикл обязателен**:

```
Принята | Не принята → Начало реагирования → Прибытие → Проведение работ → Работы завершены
                                                    ↘ Отказ от выполнения работ
```

Форма статуса: поля `Статус` (выбор из списка), `Номер наряда`, `Комментарий`
(пример из билета ДДС: «Принята», наряд 23, «Отправил сантехник для перекрытия воды»).
Первичный статус формируется выбором из двух: **Принято / Не принято**, остальное — вручную.

### 2.2 Статусы служб (таймлайн виджета службы)

```
Добавлена → Получена службой → Принята → Работы завершены
                              ↘ Не принята (причина: «вне компетенции», «заявка отклонена»)
```

Отказ службы фиксируется с комментарием. Нет статуса «Завершение работ» 48 часов → карточка «Не завершено».

### 2.3 Статусы заявителя (карточка 112)

```
очевидец | пострадавший | родственник | знакомый | ребенок | участник
```

### 2.4 Каналы связи (карточка 112)

```
ЕССМ | ЕДЦ | Линия ДСП | МГТС-112 | Мегафон | МТС | Мобильное приложение | МЧС | телефония (АОН)
```

### 2.5 Группы происшествий — 119 штук (классификатор v.046_24)

Блоки (детально — в едином документе, раздел 4.4): пожары и задымления (6), ДТП (4),
взрывы и угрозы (3), обрушения (2), природные явления (3), экология (3), аварии на объектах (5),
опасные вещества (5), транспортные объекты (6), газ (4), городское хозяйство (~16),
правопорядка (~30), дорожные помехи, человек в опасности (~14), соцпомощь, животные,
скорая помощь, прочие (благодарности, жалобы, справки, тренировки, помощь службам, БПЛА)
+ **новая группа v.046_24: «Прочие происшествия (от 102)»**.

### 2.6 Матрица классификатора v.046_24 — что меняется для моков

Версия `v.046_24` (1310 строк × 104 колонки) **заменяет v.046_11** — брать её. Отличия:

- **МВД**: три варианта отображения — без признаков / «Правонарушение» / «Пострадавшие»;
- **СМП**: три варианта — без признака / «Пострадавшие» / «Пострадавшие не на месте»;
- добавлены колонки служб: **МОСГАЗ, ЦЭМП (5 колонок), ФСБ, Мособлгаз, Департамент РБиПК (ГКУ МОСБЕЗ: АРМ-112 + МКП/аналитика), Аппарат МЭРА, Москоллектор, РЖД, Департамент образования, Комитет ветерарии, Мосжилинспекция, ДГП (интеграция + АРМ-112), ЦУКБ МО (в т.ч. БПЛА), Организатор перевозок, Мосэкомониторинг, МО РХБЗ, Ситиэнерго, Департамент гражданского строительства** и др. (итого 104 колонки);
- структура строки: `Г/п1/п2/п3 → 112-Признак.1/2/3 (+доп.) → итоговый тип → ТИП ЕКП 35 → главная служба → отображение в каждой службе → сценарий реагирования`.

В мок `classifierRows` переносить строки целиком (по всем 104 колонкам) — генератор эталонов
`expectedServices`/`expectedTags` для карточек строится по ней.

## 4. `scenarios` — как собирать сценарии из карточек

Сценарий = очередь из 1–3 карточек (билет = готовый сценарий) + параметры. Правила сборки:

1. **Уровень beginner** — карточки-«шаблоны»: тип происшествия прямо следует из фабулы
   (пожар авто → 101; ножевое → 102+103; ДТП с пострадавшими → 103+102; газ → 104);
   подсказки включены; эталон берётся из `classifierRows` по тегам.
2. **Уровень advanced** — те же группы, но с осложнениями из датасета:
   `[др.регион]` (нужен перевод вызова / уточнение адреса), адрес «при уточнении»,
   `[03 не тр.]` (ложный вызов СМП — ловушка на автоподбор служб), массовость (1.2/21.1),
   текущее утопление (8.3), суицидальная СМС (22.3), угроза взрыва (29.3).
3. **Многозадачность** (Q&A в.6): в очереди 2–3 карточки; новая падает, пока текущая не закрыта.
4. **Голосовой контур B→C** (Q&A в.8): после обработки — звонок на внутренний номер главной службы;
   ИИ-абонент подтверждает приём. Номера служб — 3–4-значные учебные (напр. 101, 102, 103, 104).

Примеры эталонов автоподбора служб (для сверки генератора, полные — по матрице 2.6):

| Ситуация | Теги (112-Признак.1/2/3) | Службы |
|----------|--------------------------|--------|
| Пожар квартиры, открытое пламя, люди на балконе (5.1) | Дом / Открытое пламя / Квартира + Угроза людям | 101 (главная), 103, 102 (эвакуация) |
| ДТП, 3 пострадавших, утечка топлива (32.2) | ДТП / есть пострадавшие / утечка топлива | 103 (главная), 102, 101 (пожарный риск) |
| Запах газа в квартире (31.3) | Газ / в помещении / свист трубы | 104 (главная), МОСГАЗ |
| Драка 10–15 чел., 5 пострадавших (1.2) | Правонарушение / драка / массовая | 102 (главная), 103 |
| Задымление мусоропровода, пламени нет (2.1) | Дом / Дым / Мусоропровод | 101 (задымление — сценарий «Задымление»), без СМП |
| Ребёнок упал с велосипеда, др. регион (1.3) | Ребёнок / травма | перевод вызова в ЦУС Волгоградской обл.; СМП региона |

## 5. `sessions` / `reports` — правила учебного прогона

- **Нормативы времени (заказчик):** первичная реакция ≤ 30 сек; полная отработка ≤ 3 мин.
- **Таймер в карточке:** «минута набора» — красная подсветка шапки при превышении (единый документ, п. 1.2).
- **Фиксируемые события сессии:** открытие карточки, каждый статус ДДС (с нарядом и комментарием),
  звонки службам (контур B→C), закрытие карточки; отклонения от нормативов.
- **Оценка (веса — наша методика, Q&A в.5):** скорость, корректность заполнения реквизитов,
  грамматика ручного ввода (смысловая точность, не посимвольное совпадение), верность классификации
  (итоговый тип + главная служба по `classifierRows`).
- **Отчёт (Q&A в.16):** ФИО + номер АРМ; временные метки по этапам с отклонениями; список
  грамматических/синтаксических ошибок; интегральный балл; графики/диаграммы.
- **Адаптивная сложность (Q&A в.10):** успешные прогоны → advanced-карточки; ошибки/задержки →
  повторные beginner-карточки.
- **Удалённый контроль (Q&A в.16):** teacher в реальном времени видит экраны студентов локальной сети
  (экран мониторинга класса — отдельный виджет для `pages`).
